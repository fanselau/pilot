    New type in `src/core/types.ts` (if not already added by 10-01):

    ```typescript
    export interface VerifyResult {
      strategy: ProjectType;
      passed: boolean;
      totalChecks: number;
      passedChecks: number;
      failedChecks: number;
      issues: string[];
      testsRan: boolean;
      testsPassed: boolean | null;  // null if no tests found
    }
    ```

    New `src/core/verify-strategies.ts` with two exported functions:

    1. `runFileContentVerification(projectDir: string, phase: number): Promise<VerifyResult>`

       Checks (each one is a "check" in the count):
       a. **Phase directory exists** — `.planning/phases/${padded}-*` exists
       b. **Plan files exist** — at least 1 PLAN.md in phase dir
       c. **Summary files exist** — at least 1 non-superseded SUMMARY.md (reuse countSummaryFiles)
       d. **No stub files** — SUMMARY files have >10 lines (not empty stubs)
       e. **ROADMAP consistency** — phase referenced in ROADMAP.md
       f. **Test suite** — if package.json has `scripts.test`, run `npm test` or `npx vitest run` (whichever is configured). Pass/fail based on exit code.

       Returns VerifyResult with counts and issue descriptions.

    2. `runCliVerification(projectDir: string, phase: number): Promise<VerifyResult>`

       Checks:
       a. **Build succeeds** — if `scripts.build` exists, run `npm run build`. Check exit code 0.
       b. **Binary exists** — if `bin` field in package.json, check the binary file exists after build
       c. **Binary executable** — check file permissions (stat mode & 0o111)
       d. **Help flag works** — run the binary with `--help`, check exit code 0
       e. **Test suite** — if `scripts.test` exists, run `npm test`. Pass/fail on exit code.
       f. **Lint passes** — if `scripts.lint` exists, run `npm run lint`. Pass/fail on exit code.

       Returns VerifyResult with counts and issue descriptions.

    Both functions:
    - Use execa for subprocess execution with `reject: false` and reasonable timeouts (60s per command)
    - Never throw — capture all failures as issues in the result
    - Include `strategy` field ('file-content' or 'cli') in result

    Test cases for `runFileContentVerification`:
    - Project with valid phase dir, plans, summaries → passed=true, all checks pass
    - Project with phase dir but no summaries → passed=false, issues include "no summary files"
    - Project with stub summary (<10 lines) → passed=false, issues include "stub"
    - Project with no phase dir → passed=false, issues include "phase directory not found"
    - Project with test suite that passes → testsRan=true, testsPassed=true
    - Project with no test script → testsRan=false, testsPassed=null

    Test cases for `runCliVerification`:
    - Project with passing build + working binary → passed=true
    - Project with failing build → passed=false, issues include "build failed"
    - Project with binary that returns non-zero on --help → passed=false
    - Project with no bin field → binary checks skipped (not failures)
    - Project with test script → testsRan=true, testsPassed based on exit code

    NOTE: Tests should mock execa calls. Use vi.mock to mock execa for build/test commands. Use real filesystem for file existence checks (temp dirs).
  </behavior>
