    Add a new exported function to `src/core/verify-routing.ts`:

    `detectVerifyNotApplicable(logContent: string): boolean`

    This function checks if log content indicates that browser-based verification is not applicable. It looks for patterns that indicate the AI agent recognized there's nothing to browser-test.

    Patterns to match (case-insensitive):
    - "not applicable" 
    - "no web ui"
    - "no web interface"
    - "no browser"
    - "nothing to browser-test"
    - "no frontend"
    - "no http server"
    - "no server to test"
    - "markdown-only"
    - "no routes found"
    - "cannot start dev server"
    - "no dev server"

    Implementation:
    ```typescript
    const NOT_APPLICABLE_PATTERNS = [
      /not\s+applicable/i,
      /no\s+web\s+(ui|interface)/i,
      /no\s+browser/i,
      /nothing\s+to\s+browser[- ]test/i,
      /no\s+frontend/i,
      /no\s+http\s+server/i,
      /no\s+server\s+to\s+test/i,
      /markdown[- ]only/i,
      /no\s+routes?\s+found/i,
      /cannot\s+start\s+dev\s+server/i,
      /no\s+dev\s+server/i,
    ];

    function detectVerifyNotApplicable(logContent: string): boolean {
      return NOT_APPLICABLE_PATTERNS.some(pattern => pattern.test(logContent));
    }
    ```

    Update `runPhaseCycle` in `src/core/lifecycle.ts` to track verify attempts per phase and auto-skip after 3 failures.

    1. Add import: `detectVerifyNotApplicable` from `./verify-routing.js`
    2. Add import: `readFile` from `node:fs/promises` (if not already imported — it IS already imported)

    3. Add a verify attempt counter at the top of `runPhaseCycle` (inside the function, before the while loop):
       ```typescript
       let verifyAttempts = 0;
       const MAX_VERIFY_ATTEMPTS = 3;
       ```

    4. In the `case 'needs-verify':` block, AFTER a verify attempt completes (whether via smart routing or gsd-verify-auto), increment verifyAttempts and check for auto-skip:

       After any verify failure (exitCode !== 0 for gsd-verify-auto, or !result.passed for file/cli):
       ```typescript
       verifyAttempts++;

       // Check if we should auto-skip verify
       if (verifyAttempts >= MAX_VERIFY_ATTEMPTS) {
         // For browser UAT failures, check log content for "not applicable" pattern
         const logFile = path.join(config.logDir, `gsd-${title}.log`);
         let logContent = '';
         try {
           logContent = await readFile(logFile, 'utf8');
         } catch { /* no log file */ }

         const notApplicable = detectVerifyNotApplicable(logContent);
         
         if (notApplicable || verifyAttempts >= MAX_VERIFY_ATTEMPTS) {
           process.stderr.write(
             `[lifecycle] Phase ${phase}: verify failed ${verifyAttempts}x` +
             (notApplicable ? ' (not applicable detected)' : '') +
             `. Auto-skipping verify, marking as verified-manually.\n`
           );
           await writePhaseState(projectDir, phase, 'verified');
           // Write a UAT file indicating manual skip
           const phaseDir = await findPhaseDir(projectDir, phase);
           if (phaseDir !== null) {
             const padded = String(phase).padStart(2, '0');
             const uatPath = path.join(phaseDir, `${padded}-UAT.md`);
             const uatContent = [
               '# Verification Results (auto-skipped)',
               '',
               'result: pass',
               'failed: 0',
               '',
               `Verification auto-skipped after ${verifyAttempts} attempts.`,
               notApplicable ? 'Reason: Browser verification not applicable for this project type.' : 'Reason: Max verify attempts reached.',
               `Strategy used: verified-manually`,
             ].join('\n');
             try {
               await writeFile(uatPath, uatContent, 'utf8');
             } catch { /* best effort */ }
           }
           break; // Exit the needs-verify case — loop will see 'done' via 'verified' state
         }
       }
       ```

    5. **IMPORTANT placement:** The verifyAttempts counter must be checked in BOTH paths:
       - After gsd-verify-auto spawn returns non-zero (web projects)
       - After runFileContentVerification/runCliVerification returns !passed (non-web projects)
       - The counter increments on ANY verify failure regardless of strategy

    6. Also cap the `needs-gaps` path: if we enter needs-gaps from verify failure, that counts toward the total. The MAX_VERIFY_ATTEMPTS is across all strategies and gap closure re-verify cycles for the same phase.

    **Note on log file reading for gsd-verify-auto:** The log file path follows the convention `gsd-${title}.log` where title is built by `truncateTitle(project, 'verify-auto', String(phase))`. Import `getConfig` if not already imported (it is), and construct the log path. If the log file doesn't exist yet (first attempt hasn't completed), skip the content check.
