  <name>Task 1: Rewrite spawnAndWait poll loop with getSessionState routing</name>
  <files>src/core/runner.ts</files>
  <action>
  Replace the current `isSessionDone()`-based poll loop in `spawnAndWait()` with state-based routing.

  1. **Import** `getSessionState` from `opencode-db.ts` and `HungSessionError` from `../util/errors.ts` at the top of runner.ts (add to existing imports).

  2. **Replace the poll loop body** inside `spawnAndWait()`. Currently the loop does:
     ```
     isSessionDone(sessionId) → return
     ```

     Replace with:
     ```typescript
     const stateResult = getSessionState(sessionId, pidAlive);
     
     switch (stateResult.state) {
       case 'done':
         return;

       case 'hung-on-prompt':
         // Immediate kill — session is waiting for user input that will never come
         await this.killHungSession(procPid, title, `hung-on-prompt (tool: ${stateResult.pendingToolName})`);
         this.log(`Session hung on interactive prompt: ${title} (tool: ${stateResult.pendingToolName}, content: ${stateResult.pendingToolContent ?? 'unknown'})`);
         throw new HungSessionError({
           hungReason: 'interactive-prompt',
           lastToolCall: stateResult.pendingToolName,
           sessionTitle: title,
         });

       case 'hung-on-tool':
         // Long-running tool (bash build, test suite) — continue polling
         // Wall timeout (from the while-loop condition) serves as safety net
         break;

       case 'crashed':
         // PID dead, no clean step-finish
         throw new Error(`Process died without clean completion for: ${title}`);

       case 'working':
         // Session is actively processing — continue polling
         break;
     }
     ```

  3. **Compute `pidAlive` boolean** for the `getSessionState` call. Before the switch, add:
     ```typescript
     let pidAlive = true;
     if (procPid !== undefined) {
       try { process.kill(procPid, 0); } catch { pidAlive = false; }
     }
     ```

  4. **Remove the old PID-death handling block** that currently does the 2s + 3s WAL flush wait and falls back to `getAssistantMessageCount`. This is replaced by the `crashed` state from `getSessionState`.

     However, keep a brief WAL wait: when `pidAlive === false` and state is still `working`, do one 2s sleep and re-check `getSessionState` before falling through to the next iteration. This handles the race where the process exits but WAL hasn't flushed yet:
     ```typescript
     if (!pidAlive && stateResult.state === 'working') {
       await this.sleep(2000);
       const recheck = getSessionState(sessionId, false);
       if (recheck.state === 'done') return;
       if (recheck.state === 'crashed') {
         // PID confirmed dead, still no step-finish — check message count as fallback
         const msgCount = getAssistantMessageCount(sessionId);
         if (msgCount > 0) return; // Had activity, treat as done
         throw new Error(`Process died without clean completion for: ${title}`);
       }
       // Otherwise continue polling (state might still be pending tool, etc.)
     }
     ```

  5. **Keep `isSessionDone` import but mark as deprecated** (or remove if no other callers exist in runner.ts). Check if `isSessionDone` is used elsewhere in runner.ts — if only in `spawnAndWait`, remove the import. If used elsewhere, keep it.

  6. **Log the state on each poll cycle** for debug observability:
     ```typescript
     this.log(`Poll: ${title} — state=${stateResult.state}${stateResult.pendingToolName ? ` tool=${stateResult.pendingToolName}` : ''}`);
     ```
     Use the existing `this.log()` method (structured logging).
