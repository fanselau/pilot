  The function signature: `export function getSessionState(sessionId: string, pidAlive: boolean = true): SessionStateResult`

  Detection algorithm (order matters — check most specific first):

  1. **Check for step-finish with terminal reason**: Query the latest `step-finish` part for the session. If `reason === 'stop'` or `reason === 'length'`, return `{ state: 'done' }`.

  2. **Check for pending tool calls**: Query parts with `type='tool'` and `state.status='running'` (no result yet) for the session, ordered by `time_created DESC`. If found:
     - Extract tool name from `json_extract(data, '$.tool')`
     - If tool name is `'question'` (OpenCode's equivalent of AskUserQuestion): return `{ state: 'hung-on-prompt', pendingToolName: 'question', pendingToolContent: <extract from state.input, truncate to 200 chars> }`
     - Else: return `{ state: 'hung-on-tool', pendingToolName: toolName }`

  3. **Check for crash (PID dead, no terminal step-finish, no pending tools)**: If `pidAlive === false` and we reach this point (no done state, no pending tools), return `{ state: 'crashed' }`.

  4. **Default — working**: Return `{ state: 'working' }`.

  SQL queries to use (following existing patterns in opencode-db.ts):

  For step-finish check:
  ```sql
  SELECT json_extract(data, '$.reason') as reason
  FROM part
  WHERE session_id = ?
    AND json_extract(data, '$.type') = 'step-finish'
  ORDER BY time_created DESC LIMIT 1
  ```

  For pending tool calls:
  ```sql
  SELECT json_extract(data, '$.tool') as tool,
         json_extract(data, '$.state.input') as tool_input,
         json_extract(data, '$.state.status') as tool_status
  FROM part
  WHERE session_id = ?
    AND json_extract(data, '$.type') = 'tool'
    AND json_extract(data, '$.state.status') = 'running'
  ORDER BY time_created DESC LIMIT 1
  ```

  For nonexistent sessions: if no parts at all are found for the session_id, return `{ state: 'done' }` (safe default — session hasn't started or doesn't exist).

  Wrap in try/catch using the existing `handleDbError(err)` pattern. On error, return `{ state: 'working' }` (safe fallback — don't kill on query failure).
