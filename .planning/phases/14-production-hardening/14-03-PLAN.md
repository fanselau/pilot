Upgrade runner-log.ts to support structured logging levels and size-based rotation:

1. **Log levels:** Add log level support:
   ```typescript
   type LogLevel = 'DEBUG' | 'INFO' | 'WARN' | 'ERROR';
   const LEVEL_ORDER: Record<LogLevel, number> = { DEBUG: 0, INFO: 1, WARN: 2, ERROR: 3 };
   ```

2. **Update RunnerLogger interface:**
   ```typescript
   export interface RunnerLogger {
     debug(message: string): void;
     info(message: string): void;
     warn(message: string): void;
     error(message: string): void;
     log(message: string): void;   // backward compat — same as info()
     getPath(): string;
     close(): void;
   }
   ```

3. **Update createRunnerLogger:** Accept `level` parameter (default 'INFO' from config):
   ```typescript
   function createRunnerLogger(logsDir?: string, level?: LogLevel): RunnerLogger
   ```
   
   Each level method checks `LEVEL_ORDER[method_level] >= LEVEL_ORDER[configured_level]` before writing.
   
   Format: `[YYYY-MM-DDTHH:MM:SS] [LEVEL] message` — ISO-8601 timestamp with level tag.
   This replaces the old `[HH:MM:SS] message` format.

4. **Size-based rotation:** Add a check in the write path:
   ```typescript
   // Check file size before writing
   try {
     const st = statSync(logPath);
     if (st.size > MAX_LOG_SIZE) {
       rotateBySize(logPath);
     }
   } catch { /* file may not exist yet */ }
   ```
   
   `MAX_LOG_SIZE = 10 * 1024 * 1024` (10MB)
   
   `rotateBySize(logPath)`:
   - If `.log.3` exists, delete it
   - Rename `.log.2` → `.log.3`
   - Rename `.log.1` → `.log.2`  
   - Rename current → `.log.1`
   - (Next write creates fresh file)
   
   Use `renameSync`, `unlinkSync`, `statSync` from `node:fs`.

5. **Keep date-based rotation:** The existing `rotateRunnerLogs` function stays for cross-day cleanup. Size rotation handles within-day growth (the 10MB cap per the requirements).

6. **Backward compat:** The `log()` method maps to `info()` so existing callers don't break.
