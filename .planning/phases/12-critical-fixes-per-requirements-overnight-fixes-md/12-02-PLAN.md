<task type="auto">
  <name>Task 2: Fix progress overflow in progress.ts and projects.ts</name>
  <files>src/core/progress.ts, src/core/projects.ts</files>
  <action>
**Root cause:** Two bugs cause progress > 100%:

1. In `projects.ts` line 99: `summaryCount >= planCount` counts gap closure summaries (e.g., `09-03-SUMMARY.md`, `09-04-SUMMARY.md`) alongside original plan summaries, so a phase with 2 original plans + 2 gap closure plans has 4 summaries >= 2 plans = "done." But the real issue is `donePhases` can count phase directories that don't map to roadmap phases (decimal phases like `03.1-hotfix`, or extra dirs), exceeding `totalPhases`.

2. In `progress.ts` line 134: Same `summaryCount >= planCount` issue, plus `doneCount` can exceed `totalPhases` when phase directories exist on disk but aren't in the roadmap.

**Fix in `progress.ts`:**
- Line 155: Cap overall at 100%: `const overall = totalPhases > 0 ? Math.min(100, Math.round((doneCount / totalPhases) * 100)) : 0;`
- Additionally, in the phase scanning loop (lines 103-151), only count `doneCount++` when the phase exists in `roadmapPhases`. This is already the case since we iterate `roadmapPhases`, so the cap is the real fix.

**Fix in `projects.ts`:**
- Line 110: Cap percent at 100%: `const percent = totalPhases > 0 ? Math.min(100, Math.round((donePhases / totalPhases) * 100)) : 0;`
- Additionally, constrain `donePhases` to not exceed `totalPhases`: after the scan loop (after line 108), add: `donePhases = Math.min(donePhases, totalPhases);`
- Reason for capping donePhases: `donePhases` counts ALL phase directories on disk that look complete, but `totalPhases` only counts `### Phase \d+` lines in ROADMAP.md. Extra directories (decimal phases, renamed phases) inflate `donePhases`.
  </action>
