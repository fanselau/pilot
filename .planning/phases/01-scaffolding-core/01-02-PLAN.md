  <behavior>
The QUEUE.md v5 format uses `## ` headers with pipe-delimited fields and status emoji prefixes.

**Parsing rules:**
- `## project | mode | args` → status: pending
- `## 🔨 project | mode | args` → status: running
- `## ✅ DONE: project | mode | args` → status: done
- `## ❌ FAIL: project | mode | args` → status: failed
- Lines after `## ` header matching `key: value` pattern → metadata (depends-on, timeout)
- Lines after `## ` header NOT matching metadata → description
- Empty `|` section → empty string args

**Test cases (input → expected output):**

1. Simple pending entry:
   ```
   ## hub | continue
   ```
   → `{ lineNum: 1, project: "hub", mode: "continue", args: "", status: "pending" }`

2. Running entry:
   ```
   ## 🔨 resume-roast | continue-all
   ```
   → `{ lineNum: 1, project: "resume-roast", mode: "continue-all", args: "", status: "running" }`

3. Done entry with args:
   ```
   ## ✅ DONE: baby-predictor | build-full | AI baby face predictor tool
   ```
   → `{ lineNum: 1, project: "baby-predictor", mode: "build-full", args: "AI baby face predictor tool", status: "done" }`

4. Failed entry:
   ```
   ## ❌ FAIL: caricature | build-full | Caricature studio
   ```
   → `{ lineNum: 1, project: "caricature", mode: "build-full", args: "Caricature studio", status: "failed" }`

5. Entry with metadata:
   ```
   ## hub | continue
   depends-on: registry
   timeout: 120
   ```
   → `{ ..., dependsOn: ["registry"], timeout: 120 }`

6. Entry with description:
   ```
   ## ✅ DONE: baby-predictor | build-full | AI baby face predictor tool
   Created in 2h 15m, 10 phases complete
   ```
   → `{ ..., description: "Created in 2h 15m, 10 phases complete" }`

7. Full QUEUE.md with mixed entries → array of QueueEntry in order

8. Empty file → empty array

9. File with only comments/blank lines → empty array

**markEntry behavior:**
- `markEntry(file, lineNum, 'running')` → prepends `🔨 ` to the `## ` header at that line
- `markEntry(file, lineNum, 'done')` → replaces header prefix with `✅ DONE: `
- `markEntry(file, lineNum, 'failed')` → replaces header prefix with `❌ FAIL: `
- Must handle entries that already have a status prefix (e.g., running → done)
  </behavior>
  <implementation>
1. **parseQueue(content: string): QueueEntry[]** — Pure function. Split content by lines, iterate, detect `## ` headers, parse status prefix, split by `|`, collect metadata/description until next header or EOF.

2. **parseQueueFile(filePath: string): Promise&lt;QueueEntry[]&gt;** — Async wrapper: read file, call parseQueue.

3. **markEntry(filePath: string, lineNum: number, status: 'running' | 'done' | 'failed'): Promise&lt;void&gt;** — Read file lines, find the header at lineNum, strip existing prefix, apply new prefix, write file back. Use `node:fs/promises`.

Key regex for header detection: `/^## /`
Key regex for status prefix: `/^## (✅ DONE: |❌ FAIL: |🔨 )?(.+)$/`
Split remaining by ` | ` (space-pipe-space) for project, mode, args.
Trim all extracted values.

Import `QueueEntry` from `./types.js`.
  </implementation>
</feature>
