**2. `updateConfigFn` (POST):**
- inputValidator: `(d: { updates: Partial<ConfigFileSchema> }) => d`

  ```typescript

  import os from 'node:os'

  ```
- Returns `{ ok: boolean; errors?: Record<string, string> }` with field-level error messages
- After successful write, call `_resetConfigCache()` from `@pilot/core/config.js` to clear the cached config

**3. `getModelTableFn` (GET):**
- Import `AGENT_MODELS` from `@pilot/core/models.js`, `getProviderModes`, `getAllEntriesForMode` from `@pilot/core/model-store.js`
- Build full table: for each provider mode (3 built-in + custom from `getProviderModes()`), for each agent role, for each profile → model entry
- Return shape: `{ modes: string[]; customModes: string[]; table: Record<string, Record<string, Record<string, ModelEntry>>> }` (mode → agent → profile → entry)

**4. `updateModelMappingFn` (POST):**
- inputValidator: `(d: { providerMode: string; agent: string; profile: ModelProfile; model: string; variant?: string }) => d`
- Calls `setModelEntry(d.providerMode, d.agent, d.profile, d.model, d.variant ?? null)` from `@pilot/core/model-store.js`
- Returns `{ ok: boolean }`

**5. `getSkillsListFn` (GET):**
- Import `listSkills`, `PREDEFINED_CATEGORIES`, `CATEGORY_INFO` from `@pilot/core/skills.js`
- Returns `{ skills: SkillEntry[]; categories: typeof PREDEFINED_CATEGORIES; categoryInfo: typeof CATEGORY_INFO }`

**6. `installSkillFn` (POST):**
- inputValidator: `(d: { repo: string; skill: string; categories: string[] }) => d`

- Returns `{ ok: boolean; skill?: SkillEntry; error?: string }`

**7. `removeSkillFn` (POST):**
- inputValidator: `(d: { name: string }) => d`

**8. `updateSkillTagsFn` (POST):**
- inputValidator: `(d: { name: string; categories: string[] }) => d`
- Calls `tagSkill(d.name, d.categories)`
- Returns `{ ok: boolean; skill?: SkillEntry | null }`

**9. `getSystemInfoFn` (GET):**
- Uses `os.totalmem()` to get total system RAM in MB
- Returns `{ totalRamMb: number; totalRamGb: number }`

Create `web/src/hooks/use-settings.ts` — a React hook that manages the entire settings page state:

**Data fetching:**
- Uses `useQuery` from `@tanstack/react-query` to call `getFullConfigFn`, `getModelTableFn`, `getSkillsListFn`, `getSystemInfoFn` on mount
- Query keys: `['settings-config']`, `['settings-models']`, `['settings-skills']`, `['settings-system-info']`
- `staleTime: Infinity` (no auto-refetch — manual refetch on save)

**Dirty state tracking:**
- Maintains a `dirtyFields` Map tracking which config keys have been modified
- `formValues` state object: starts as a copy of the fetched config values
- `setField(key, value)` function: updates formValues and marks field as dirty
- `isDirty` computed: `dirtyFields.size > 0`
- `dirtyCount` computed: number of distinct sections with dirty fields
- `resetField(key)` function: reverts to original value, removes from dirtyFields

**Save flow:**
- `save()` async function:
  - Builds a `Partial<ConfigFileSchema>` from dirty fields only
  - Calls `updateConfigFn({ updates })` 
  - On success: invalidate `['settings-config']` query, clear dirtyFields, return `{ ok: true }`
  - On error: return `{ ok: false, errors }` with field-level errors
- `isSaving` state boolean

**Section helpers:**
- Map config keys to sections for dirty count per section:
  ```typescript
  const KEY_TO_SECTION: Record<string, string> = {
  ```
