Rewrite timeline composition around explicit step groups:

1. Build step attribution with deterministic fallback order:
   - primary: `job_steps.sessionId` identity match
   - secondary: `job_steps.sessionTitle` match
   - tertiary: step time window (`startedAt`/`completedAt`) when identity missing
   - final fallback: unattributed group
2. Keep chronological ordering inside each step group by `createdAt`.
3. Replace child fork/completion dual items with one lifecycle branch item per `childSessionId`.
   - Insert lifecycle item at child spawn position
   - Update same object with latest status/progress/completion fields instead of emitting a second completion row
4. Apply cursor/limit pagination consistently, then regroup paged items by step.
5. Preserve existing mutation wrappers (`retryJobAction`, `cancelJobAction`, `forceQuitJobAction`, `unblockProjectAction`) unchanged unless type changes require signature adjustments.

Avoid title-index heuristics for branch identity; use session IDs as the only merge key.
