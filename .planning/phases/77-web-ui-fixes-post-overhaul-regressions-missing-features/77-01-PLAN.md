- `onScrollToStep: (stepIndex: number) => void` — sidebar click triggers scroll in content pane
- `onVisibleStepChange: (stepIndex: number | null) => void` — content pane reports which step is visible

Use a ref-based approach: pass a `scrollToStepRef` (a `React.MutableRefObject<((idx: number) => void) | null>`) from the split-pane parent to the content pane, and a callback from content pane to parent for scroll-spy updates.

```tsx
const scrollToStepRef = useRef<((idx: number) => void) | null>(null)
const [visibleStepIndex, setVisibleStepIndex] = useState<number | null>(null)
```

Pass to sidebar: `highlightedStep={visibleStepIndex}` and `onClickStep={(idx) => scrollToStepRef.current?.(idx)}`
Pass to content pane: `scrollToStepRef={scrollToStepRef}` and `onVisibleStepChange={setVisibleStepIndex}`

Keep the `autoFollow` state for running jobs.

Change the component to ALWAYS render all groups in continuous scroll mode (remove the "selected step only" branch). Each group gets a section element with a `data-step-index` attribute and an `id` like `step-section-{stepIndex}`.

- When a section crosses the viewport threshold (e.g., 0.3 ratio or rootMargin), call `onVisibleStepChange` with its stepIndex
- Use `rootMargin: '-10% 0px -70% 0px'` to trigger when a section reaches the upper portion of the viewport
- Clean up observer on unmount

For the non-virtualized path, render each group as:

  </div>
  <div className="space-y-0.5 border-l-2 border-border/40 pl-3 ml-4">
    {group.items.map(...)}
  </div>
</section>

Remove the `selectedStep` prop. Add props: `scrollToStepRef`, `onVisibleStepChange`.

Keep the "Follow" button for auto-scrolling running jobs.
