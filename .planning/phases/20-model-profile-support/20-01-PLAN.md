  <name>Task 1: Add model_profile and provider_mode to DB schema + types</name>
  <files>src/core/types.ts, src/core/db.ts, test/core/db.test.ts</files>
  <action>
1. In `src/core/types.ts`:
   - Add `ModelProfile` type: `'quality' | 'balanced' | 'budget'`
   - Add `ProviderMode` type: `'hybrid' | 'claude-only' | 'openai-only'`
   - Add to `Job` interface:
     - `modelProfile: ModelProfile` (maps from `model_profile` column)
     - `providerMode: ProviderMode` (maps from `provider_mode` column)

2. In `src/core/db.ts`:
   - Add `model_profile TEXT DEFAULT 'balanced'` and `provider_mode TEXT DEFAULT 'claude-only'` to CREATE_TABLE_SQL
   - Add migration logic in `openPilotDb()` and `_getTestDb()`: After creating table, run:
     ```sql
     ALTER TABLE jobs ADD COLUMN model_profile TEXT DEFAULT 'balanced';
     ALTER TABLE jobs ADD COLUMN provider_mode TEXT DEFAULT 'claude-only';
     ```
     Wrap each ALTER TABLE in a try/catch (column already exists = no-op). This is the standard SQLite migration pattern since ALTER TABLE ADD COLUMN IF NOT EXISTS isn't supported.
   - Update `JobRow` interface to include `model_profile: string` and `provider_mode: string`
   - Update `rowToJob` to map `model_profile` → `modelProfile` and `provider_mode` → `providerMode` (cast to the union types)
   - Update `addJob` signature to accept optional `modelProfile?: ModelProfile` and `providerMode?: ProviderMode` parameters. Default to `'balanced'` and `'claude-only'` respectively. Include them in the INSERT statement.

3. In `test/core/db.test.ts`:
   - Add test: "addJob stores model_profile and provider_mode" — add a job with profile='budget', provider='hybrid', verify getJob returns them
   - Add test: "addJob defaults to balanced/claude-only" — add a job without profile/provider, verify defaults
  </action>
  <verify>npm run test:run -- test/core/db.test.ts</verify>
  <done>Job records have model_profile and provider_mode columns. addJob accepts and stores them. getJob returns them with correct types. Tests pass.</done>
