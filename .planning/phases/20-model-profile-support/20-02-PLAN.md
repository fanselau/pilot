1. In `src/core/runner.ts`, add a new function `writeModelProfileConfig`:
   ```typescript
   function writeModelProfileConfig(projectDir: string, job: Job): void {
     const configPath = path.join(projectDir, '.planning', 'config.json');
     let config: Record<string, unknown> = {};
     
     // Read existing config if present
     try {
       config = JSON.parse(readFileSync(configPath, 'utf8')) as Record<string, unknown>;
     } catch {
       // No existing config — start fresh
     }
     
     // Set model profile and provider mode from job
     config.model_profile = job.modelProfile;
     config.provider_mode = job.providerMode;
     
     // Ensure .planning/ directory exists
     mkdirSync(path.join(projectDir, '.planning'), { recursive: true });
     writeFileSync(configPath, JSON.stringify(config, null, 2) + '\n', 'utf8');
   }
   ```

2. Call `writeModelProfileConfig(projectDir, job)` in the `launch()` method, AFTER `markRunning` but BEFORE the delegation step. The delegation itself should use the parent session's model (which is always the opencode build agent model — typically opus). The config.json is read by GSD orchestrators when they spawn subagents, so it needs to be set before ANY opencode session runs in the project.

   IMPORTANT: Re-fetch the job from DB after markRunning (using `getJob(job.id)!`) to get the full Job with modelProfile/providerMode. The `job` parameter from `getNextPending()` already has these fields, but using fresh data from DB is safer.

   - Add test: "writeModelProfileConfig preserves existing config fields" — create config.json with `{"mode":"yolo"}`, call writeModelProfileConfig, verify mode is still present alongside model_profile and provider_mode
   - Export `writeModelProfileConfig` for testing (or test it through the runner if easier)
