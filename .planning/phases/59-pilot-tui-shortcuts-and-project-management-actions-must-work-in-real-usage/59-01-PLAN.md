<task type="auto">
  <name>Task 2: Fix keyboard handler for shortcut reliability + add remove-project action</name>
  <files>src/tui/app.tsx, src/tui/components/projects-panel.tsx</files>
  <action>
1. In `src/tui/app.tsx`, import `deregisterProject` from `./data/pilot-db.js`.

2. Enhance the confirm overlay rendering to use `state.confirmMessage()` instead of the hardcoded kill job message. Change the ConfirmOverlay `message` prop from:
   ```
   message={`Kill job ${state.selectedJob()?.id ?? ''} ...`}
   ```
   to:
   ```
   message={state.confirmMessage()}
   ```

3. In the keyboard handler in `app.tsx`, add a `d` key handler for remove-project (projects panel only):
   ```typescript
   // d — remove project from management (projects panel only)
   if (key.sequence === 'd' && state.panelFocus() === 'projects') {
     const idx = state.selectedIndex();
     const project = state.projects()[idx];
     if (project) {
       state.setConfirmMessage(`Remove project ${project.path.replace(process.env['HOME'] ?? '', '~')} from management?`);
       state.setPendingConfirmAction(() => async () => {
         deregisterProject(project.path);
         state.setProjects(fetchProjectData());
       });
       state.setShowConfirm(true);
     }
     return;
   }
   ```
   Place this BEFORE the `u` unblock handler (which also requires projects panel focus).

4. Update the existing `K` (force-quit) handler to also set `state.setConfirmMessage(...)` before showing the confirm overlay:
   ```typescript
   state.setConfirmMessage(`Kill job ${job.id} (${job.project.replace(process.env['HOME'] ?? '', '~')})?`);
   ```

5. In `src/tui/components/projects-panel.tsx`, add a hint for the `d` key on selected items:
   Below the existing `<text fg={theme.muted}>Press u to unblock</text>` for blocked projects, add a general hint for all selected projects:
   ```tsx
   <Show when={isSelected()}>
     <text fg={theme.muted}>Press d to remove</text>
   </Show>
   ```
   This should appear after the owner/status line, visible for ALL selected projects (not just blocked ones).

6. Ensure the keyboard handler does NOT silently swallow action keys. The existing `r`, `x`, `K` handlers already return early after their `if (job && ...)` check which means they DO return without action — but they also return UNCONDITIONALLY even when the action doesn't apply. This is the correct behavior (prevents keys from triggering unintended fallthrough). No change needed here — the "shortcuts don't work" report is likely about:
   - Being on the projects panel (selectedJob() returns null)
   - Being on items where the action doesn't apply (e.g. `r` on a running job)
   The fix is making the footer context-aware (Plan 02) so users know what's available.

7. Verify that pressing `r`/`x`/`K` from the projects panel correctly falls through (returns early) without error. The existing code already handles this via `if (!job)` early returns on the `K` handler and `if (job && job.status === 'pending')` on `x`. The `r` handler also checks `if (job && (job.status === 'failed' || ...))`. All correct.
