**Required sections (in this order):**

1. **Title + Role framing** (`# Pilot — Autonomous Dev Pipeline`)
   - One paragraph: what Pilot is, who the agent is (the CTO/orchestrator), the golden rule: "You NEVER write code directly. You write requirements, queue work, monitor progress, and review results."

2. **Your Role** (`## Your Role`)
   - You are the CTO. Think, plan, write requirements, queue work, monitor, review.
   - Never open files and edit them. Queue jobs via `pilot add`.
   - The pipeline spawns developer agents (opencode sessions) that do coding.
   - Your tools: `pilot add`, `pilot status`, `pilot log`, `pilot retry`, `pilot cancel`.

3. **First-Time Setup** (`## First-Time Setup`)
   - `pilot init` — interactive provider detection, creates `~/.pilot/config.json`
   - `pilot setup <project-dir> --owner <agentId>` — registers a project
   - `pilot doctor` — validates health
   - `pilot service start` — starts the daemon

4. **Queuing Work** (`## Queuing Work`)
   - Core `pilot add` command with all flags: scope, provider, profile, categories, notify, next, dry-run
   - Practical examples (not just a table):
     - Queue feature from requirement file
     - Quick fix without requirement file
     - High-priority with quality models
     - Budget mode for low-risk work
     - With categories for skill injection
   - Sub-sections for:
     - **Scope** (`--as quick|phase|milestone`) — when to use each, with decision guide
     - **Provider Modes** (`--provider hybrid|claude-only|openai-only`) — what each does. hybrid = Claude codes + Codex reviews, claude-only = all Claude, openai-only = all OpenAI/Codex
     - **Quality Profiles** (`--profile quality|balanced|budget`) — model tier mapping table matching current skill
     - **Categories** (`--categories frontend,testing`) — how categories map to skills injected into dev sessions. Examples.
     - **Priority** (`--next`, `pilot bump <id>`)
     - **Dry Run** (`--dry-run`)

5. **Monitoring** (`## Monitoring`)
   - `pilot status [project]` — dashboard overview
   - `pilot queue` — pending/running jobs
   - `pilot log <id>` — build transcript (flags: `--follow`, `--last N`, `-v`, `--delegation`)
   - `pilot projects` / `pilot project <path>` — project-level status

6. **When Things Go Wrong** (`## When Things Go Wrong`)
   - Job failed → `pilot log <id>` to diagnose → `pilot retry <id>`
   - Job stuck → check log first → `pilot cancel <id>` → re-queue
   - Project blocked → `pilot retry <id>` or `pilot project <path> --unblock`
   - Daemon died → `pilot service start`

7. **Notification Pipeline** (`## Notification Pipeline`)
   - How `--notify` works with OpenClaw hooks
   - Agent ID format (plain IDs like `main`, not full session keys)
   - Owner-based default: if project has owner, `--notify` is optional
   - What the agent receives on completion/failure

8. **Writing Good Requirements** (`## Writing Good Requirements`)
   - Requirement file template (# Title, ## Problem, ## Goal, ## Requirements with Must Have/Nice to Have, ## Technical Notes, ## Do NOT)
   - Rules: specific enough agents build without asking, include acceptance criteria

9. **Project Management** (`## Project Management`)
   - Registering: `pilot setup <dir> --owner <agentId>`
   - Status: `pilot projects`, `pilot project <path>`
   - Blocking: `pilot project <path> --block "reason"` / `--unblock`
   - Phase continuation: when to use requirement files vs phase numbers
   - NEVER pass requirement file when plans already exist → creates duplicate phase

10. **Daemon Management** (`## Daemon Management`)
    - `pilot service start|stop|status` — always use this
    - NEVER pkill + manual setsid, NEVER nohup
    - Restart: stop → rebuild → start

11. **Quick Reference** (`## Quick Reference`)
    - Compact command table at the END (not the beginning)
    - Include all commands: add, status, queue, log, cancel, kill, retry, bump, projects, project, setup, service, update, doctor, gc

- Delegation AI internals, WAL read timing details
- Deprecated commands section

- Practical, not theoretical — every concept gets a code example
