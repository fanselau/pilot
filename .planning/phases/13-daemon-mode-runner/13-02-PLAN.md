  **4. Rewrite `mainLoop()` for daemon mode:**
  The key change: when queue is empty and no jobs running, instead of breaking (exiting), the daemon sleeps for `pollInterval` then rescans. Only `--once` mode breaks.

  ```typescript
  private async mainLoop(): Promise<void> {
    let lastIdleLog = 0;  // timestamp of last idle log message
    const IDLE_LOG_INTERVAL = 5 * 60 * 1000;  // 5 minutes

    while (!this.state.isShuttingDown) {
      // Step 1: Reap dead processes
      await this.reap();

      // Step 2: Check per-job timeouts on active jobs
      await this.checkTimeouts();

      // Step 3: Scan for next launchable item (atomic: holds lock during read+mark)
      this.emit('scan');
      const item = await this.scan();

      if (item !== null) {
        if (this.state.activeJobs.size > this.opts.maxParallel) {
          // Already at capacity (scan returned item but we launched too many)
          // This shouldn't happen with atomic findLaunchable, but guard anyway
          await this.waitForAnyCompletion();
          continue;
        }

        // Launch (item is already marked running by findLaunchableAtomic)
        if (this.opts.dryRun) {
          this.emit('dry-run', item);
        } else {
          await this.launch(item);
        }

        // Dry-run once mode: keep scanning for all launchable
        if (this.opts.once && this.opts.dryRun) {
          continue;
        }
      } else {
        // No launchable item found

        if (this.state.activeJobs.size > 0) {
          // Jobs still running — wait for any to finish, then rescan
          await this.waitForAnyCompletion();
          continue;
        }

        // Queue empty and no jobs running
        if (this.opts.once) {
          break;  // --once: exit
        }

        // Daemon mode: log idle status periodically, then sleep and rescan
        const now = Date.now();
        if (now - lastIdleLog >= IDLE_LOG_INTERVAL) {
          this.emit('idle');
          lastIdleLog = now;
        }

        await sleep(this.opts.pollInterval * 1000);
        continue;
      }

      // Small delay between launches to avoid CPU spin
      await sleep(1000);
    }

    // Wait for all running jobs to complete before exiting
    if (!this.state.isShuttingDown) {
      while (this.state.activeJobs.size > 0) {
        await this.reap();
        if (this.state.activeJobs.size > 0) {
          await sleep(2000);
        }
      }
    }
  }
  ```

  **8. Fix graceful shutdown** — do NOT kill active jobs (spec: "Active jobs are NOT killed — they finish naturally"):

  The shutdown flow works as follows:
  1. `shutdown()` sets `isShuttingDown = true` and emits 'shutdown'
  2. `mainLoop()` while condition `!this.state.isShuttingDown` fails → exits while loop
  3. The post-loop drain block waits for all active jobs to finish naturally

  Remove all SIGTERM/SIGKILL-to-children logic from `shutdown()`. The `pilot stop --force` command handles force-kill externally. If the runner is SIGKILL'd, active child processes become orphans — they'll be detected as stuck by stuck detection.

  **`shutdown()` implementation (final):**
  ```typescript
  async shutdown(): Promise<void> {
    if (this.state.isShuttingDown) return;
    this.state.isShuttingDown = true;
    this.emit('shutdown');
    // Active jobs drain in the post-loop block of mainLoop()
    // PID file cleaned up in start() finally block
  }
  ```

  **Critical fix in `mainLoop()`:** The post-loop drain block must ALWAYS run (even during shutdown). Change:
  ```typescript
  // REMOVE this guard: if (!this.state.isShuttingDown) { ... }
  // REPLACE with unconditional drain:

  ```
  This ensures that on SIGINT/SIGTERM, the runner waits for active jobs to finish before exiting.

  **9. Add `checkTimeouts()` method** — replaces individual setTimeout per job:
  ```typescript
  private async checkTimeouts(): Promise<void> {
    for (const [pid, job] of this.state.activeJobs) {
      const timeoutMinutes = typeof job.item.meta['timeout'] === 'number'
        ? job.item.meta['timeout']
        : this.config.defaultTimeout;

      // timeout=0 means no timeout
      if (timeoutMinutes === 0) continue;

      const elapsedMs = Date.now() - job.startTime;
      const timeoutMs = timeoutMinutes * 60 * 1000;

      if (elapsedMs > timeoutMs) {
        this.emit('error', `Job ${job.title} timed out after ${timeoutMinutes} minutes`);

        if (pid > 0) {
          // Real PID — kill the entire process tree with SIGTERM first
          try { process.kill(-pid, 'SIGTERM'); } catch { /* process group may not exist */ }
          // Wait briefly then force kill
          await sleep(5000);
          if (isProcessAlive(pid)) {
            await killProcessTree(pid);
          }
        }
        // For synthetic PIDs, set exit code to trigger reap
        this.state.exitCodes.set(pid, -1);
      }
    }
  }
  ```
  Note: `process.kill(-pid, 'SIGTERM')` sends to the process GROUP (negative PID). This is more reliable than tree-kill for immediate descendants.

  Remove the individual `setTimeout` calls from `launchLifecycleMode` and `launchDirectSpawn` — timeout is now handled centrally in `checkTimeouts()`.
