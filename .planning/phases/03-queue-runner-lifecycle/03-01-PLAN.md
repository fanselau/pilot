**src/core/lock.ts** — proper-lockfile wrapper for QUEUE.md:

Create a `withQueueLock` function that wraps any async callback with proper-lockfile locking on the QUEUE.md file path.

```typescript
import { lock, unlock } from 'proper-lockfile';
import { getConfig } from './config.js';

async function withQueueLock<T>(fn: () => Promise<T>): Promise<T> {
  const config = getConfig();
  const release = await lock(config.queueFile, { stale: 30000, retries: { retries: 5, minTimeout: 100, maxTimeout: 1000 } });
  try {
    return await fn();
  } finally {
    await release();
  }
}
```

Use named export. Use proper-lockfile's lock/unlock API. Stale timeout: 30s per spec. Retry with backoff for contention.

**src/core/spawn.ts** — AI session spawning with all pre-spawn checks from spec §5 `pilot run`:

**`truncateTitle(project: string, command: string, args?: string): string`**
- Format: `${project}-${command}${sanitizedArgs}` where sanitizedArgs replaces non-alphanumeric with `-`
- Truncate to 80 chars max (ENAMETOOLONG prevention)
- Named export

**`preSpawnChecks(projectDir: string): Promise<void>`**
Runs ALL 5 pre-spawn checks sequentially. Throws descriptive error if any fail.

1. **git gc disable on snapshot repos:**
   - Glob `~/.local/share/opencode/snapshot/*/` and run `git -C "$repo" config gc.auto 0` on each
   - ALSO run on `~/.local/share/opencode/snapshot/global` separately (NOT matched by `*/` glob — this is critical per spec)
   - Use execa for git commands. Swallow errors gracefully (repos may not exist).

2. **Memory check:**
   - Read `/proc/meminfo` → extract `MemAvailable` line → parse kB value → convert to MB
   - If < 500MB, log warning and poll every 30s until available
   - Set a max wait of 10 minutes (20 polls) to avoid infinite blocking
   - Throw if memory never frees

3. **Config validation:**
   - Read `${projectDir}/opencode.json` (or `Claude.json` — check both, prefer opencode.json)
   - Parse JSON. Validate:
     - `permission` field exists (NOT `permissions` — singular!)
     - All permission types have `"**": "allow"` (`read`, `write`, `edit`, `bash`, `external_directory`)
     - If `instructions` field exists, it must be an array (NOT a string — causes silent crash)
   - Throw with specific error message if validation fails

4. **Binary check:**
   - Check if `opencode` or `claude` is available. Check these paths in order:
     - `which opencode` / `which claude` (in current PATH)
     - `~/.opencode/bin/opencode` / `~/.claude/bin/claude` (default install locations)
   - Store the resolved binary path for use by spawnSession
   - Throw if neither found: "Error: opencode/claude not found in PATH. Install: npm install -g @anthropic/claude-ai"

5. **Title truncation:** Already handled by truncateTitle function.

**`spawnSession(opts: SpawnOptions): Promise<SpawnResult>`**
- Use execa to spawn the AI binary (resolved by preSpawnChecks)
- Detached: true, stdin: 'ignore', stdout/stderr to log file (use fs.openSync for file descriptors)
- Unref the child so parent can exit if needed
- Write PID file via process.ts writePidFile
- Return SpawnResult with pid, title, logFile

Important: Use `import { execa } from 'execa'`. Open log file with `openSync(logFile, 'a')` for append mode.

The resolved binary path should be cached at module level after first preSpawnChecks call. Export a `getResolvedBinary(): string | null` for consumers that need it.

**src/core/phase-state.ts** — Phase state detection with STATE files + inference fallback.

Port of bash `get_phase_state` from gsd-queue-v5.sh.

**`writePhaseState(projectDir: string, phase: number, state: string): Promise<void>`**
- Write state string to `.planning/phases/${padded}-*/STATE` (find the phase dir first)
- Pad phase to 2 digits (3 → 03)
- Valid states: 'planning', 'planned', 'executing', 'executed', 'verifying', 'verified', 'needs-gaps'

**`getPhaseState(projectDir: string, phase: number): Promise<PhaseState>`**
Logic (mirrors bash get_phase_state):

1. Pad phase to 2 digits
2. Find phase directory: glob `.planning/phases/${padded}-*` — if no dir → return `'needs-plan'`
3. Check for explicit STATE file in phase dir. If exists, map:
   - 'planning' | 'planned' → check if plans exist, if not `'needs-plan'`, else `'needs-execute'`
   - 'executing' → `'needs-execute'` (was interrupted)
   - 'executed' → `'needs-verify'`
   - 'verifying' → `'needs-verify'` (was interrupted)
   - 'verified' → `'done'`
   - 'needs-gaps' → `'needs-gaps'`
4. If NO STATE file, fall back to inference:
   a. Check for UAT file (`*-UAT.md`):
      - Parse content for `result: fail` and `failed:` / `issues:` counts
      - If UAT exists with 0 failures → `'done'`
      - If UAT exists with failures > 0 → `'needs-gaps'`
   b. Count plan `.md` files (excluding UAT, VERIFICATION, SUMMARY, CONTEXT, RESEARCH, STATE files)
      - If 0 plans → `'needs-plan'`
   c. Check git commits for phase execution evidence:
      - Run `git log --oneline -20` in projectDir via execa
      - Look for pattern: `(feat|fix|refactor|chore)(${padded}` or `phase.?${padded}|phase.?${phaseNum}`
      - If commits found → `'needs-verify'`
      - If no commits → `'needs-execute'`

**`findPhaseDir(projectDir: string, phase: number): Promise<string | null>`**
Helper that finds the phase directory by padded phase number. Try both padded (03) and unpadded (3). Return null if not found.

**`getLastPhase(projectDir: string): Promise<number>`**
Helper to find the highest phase number from `.planning/phases/` directory names. Used by add-and-build mode to find newly added phases.

Use named exports. Pure core module (no UI deps). Use execa for git commands, readFile/readdir for filesystem.
