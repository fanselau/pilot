**src/core/runner.ts** — Port of gsd-queue-v5.sh scan→launch→reap loop.

**Core structure:**

```typescript
import { EventEmitter } from 'node:events';
// ... imports from lock, spawn, queue-parser, process, config, postmortem, types

interface RunnerState {
  activeJobs: Map<number, RunnerJob>;  // pid → job
  isShuttingDown: boolean;
}

class Runner extends EventEmitter {
  private state: RunnerState;
  private opts: RunnerOptions;
  private queuePidFile: string;  // gsd-queue-pid
  
  constructor(opts: RunnerOptions) { ... }
  
  async start(): Promise<void> { ... }   // Main loop
  private async scan(): Promise<QueueEntry | null> { ... }
  private async launch(entry: QueueEntry): Promise<void> { ... }
  private async reap(): Promise<void> { ... }
  private async handleJobCompletion(job: RunnerJob, exitCode: number): Promise<void> { ... }
  async shutdown(): Promise<void> { ... }
}

export function createRunner(opts: RunnerOptions): Runner { ... }
```

**Main loop (`start`):**
1. Write runner PID file: `$PILOT_LOG_DIR/gsd-queue-pid`
2. Check for existing runner PID (if alive and not --force → exit with error)
3. Set up SIGTERM handler → call shutdown()
4. Loop:
   a. Reap dead processes (check all active PIDs with isProcessAlive)
   b. Scan queue for next launchable entry
   c. If found AND active count < maxParallel → launch
   d. If found but at capacity → wait for any completion, then rescan
   e. If not found and jobs running → wait for any completion, then rescan
   f. If not found and no jobs → exit (queue empty)
   g. If --once flag: process one full cycle then exit
   h. Small delay (1s) between scan cycles to avoid CPU spin

**Scan logic (`scan`):**
1. Parse QUEUE.md via parseQueueFile
2. Find first entry where:
   - status === 'pending'
   - No other entry for same project is in activeJobs
   - (Phase 2 enhancement) All dependsOn projects have their entries marked 'done' above this one
3. Return entry or null

**Launch logic (`launch`):**
1. Run preSpawnChecks(projectDir)
2. Determine what to spawn based on entry.mode:
   - For lifecycle modes (build-full, continue, etc.): delegate to lifecycle.ts
   - For run-command: direct spawn with entry.args as command
3. Mark entry as running in QUEUE.md via withQueueLock → markEntry
4. Count git commits before spawn (for success detection): `git rev-list --count HEAD`
5. Spawn session via spawnSession
6. Add to activeJobs map
7. Set up per-job timeout timer (entry.timeout or default 60 min)

**Reap logic (`reap`):**
For each job in activeJobs:
1. Check if PID is still alive (isProcessAlive)
2. If dead: get exit code, call handleJobCompletion, remove from activeJobs

**handleJobCompletion (matches spec §8 exactly, minus ≥8 messages heuristic):**
1. Clear timeout timer
2. Count new commits: `git rev-list --count HEAD` minus preCommitCount
3. Check for uncommitted .planning changes: `git status --porcelain .planning/`
   - If dirty: commit them automatically (`git add .planning/ && git commit -m "auto-commit planning changes"`)
4. Determine result:
   - newCommits > 0 OR planningChanges → success
   - exitCode === 0 and no artifacts → success_no_artifacts (suspicious but accept)
   - exitCode !== 0 and retries < maxRetries → retry (mark entry back to pending)
   - exitCode !== 0 and retries >= maxRetries → failed (mark entry ❌ FAIL)
5. Mark entry in QUEUE.md via withQueueLock → markEntry
6. Log via logPostmortem
7. Remove PID file

**Graceful shutdown (`shutdown`):**
1. Set isShuttingDown = true (stop scan loop)
2. For each active job:
   - Send SIGTERM via process.kill(pid)
   - Wait up to 15 seconds
   - If still alive: use tree-kill with SIGKILL
3. Mark running entries back to pending in QUEUE.md
4. Clean up all PID files
5. Remove runner PID file
6. Exit cleanly

**Dry-run mode:** scan returns entries but launch only logs what would run, doesn't spawn.

**Important implementation details:**
- Use `import treeKill from 'tree-kill'` for killing process trees (not just parent PID)
- tree-kill callback API: `treeKill(pid, 'SIGKILL', (err) => { ... })` — wrap in Promise
- For waiting: use a simple polling loop with setTimeout, NOT process.on('exit') on children (detached processes don't emit events on parent)
- The runner tracks child process exit codes by polling isProcessAlive. When a PID disappears, try `waitpid` or just treat as exit code -1 (unknown). For detached processes, the exit code tracking is best-effort.
- Actually, for exit code tracking with detached processes: spawn with `{ detached: true }` but keep a reference to the ChildProcess. Listen for its 'exit' event. Store exit code when received. The process is detached (survives parent death) but events still fire while parent is alive.

**src/core/lifecycle.ts** — Port of bash lifecycle_* functions from gsd-queue-v5.sh.

**`runLifecycleMode(projectDir: string, mode: string, args: string): Promise<void>`**
Main dispatch function. Routes to specific mode handler.

Valid modes: `build-full`, `continue`, `continue-all`, `build-to-phase`, `add-and-build`, `run-command`

**Mode: build-full**
1. Check if `.planning/` exists in projectDir
2. If YES → throw Error: `".planning/ already exists in ${project}. Use 'continue-all' for existing projects or delete .planning/ to start fresh."` — this is a HARD requirement (AUTO-19)
3. If NO:
   - Create project dir if needed
   - Spawn gsd-new-project with args as description (--auto flag)
   - Wait for completion
   - Then loop: findNextPhase → runPhaseCycle → repeat until all done

**Mode: continue**
1. findNextPhase(projectDir) — find first incomplete phase
2. If none → log "all phases done", return
3. runPhaseCycle(projectDir, phase)

**Mode: continue-all**
Loop `continue` until findNextPhase returns null.

**Mode: build-to-phase**
1. Parse target phase N from args
2. Loop phases 1..N: if getPhaseState !== 'done', runPhaseCycle
3. Stop after phase N is done

**Mode: add-and-build**
1. Check if description's first keyword already exists in ROADMAP.md (skip check from bash)
2. Spawn gsd-add-phase with args as description
3. Wait for completion
4. Get newly created phase number via getLastPhase
5. runPhaseCycle(projectDir, newPhase)

**Mode: run-command**
1. Parse command from args (strip gsd- prefix if present)
2. Direct spawn: `opencode run --command gsd-${command} ${remaining_args}`

**`findNextPhase(projectDir: string): Promise<number | null>`**
1. Read ROADMAP.md, extract phase numbers
2. For each phase: getPhaseState
3. Return first phase where state !== 'done'
4. If all done → return null

**`runPhaseCycle(projectDir: string, phase: number): Promise<void>`**
Port of bash run_phase_cycle. Loop:

```
while true:
  state = getPhaseState(projectDir, phase)
  switch state:
    'done':          return (success)
    'needs-plan':    writePhaseState('planning')
                     spawn gsd-plan-phase <N> --auto
                     writePhaseState('planned')
    'needs-execute': writePhaseState('executing')
                     spawn gsd-execute-phase <N> --auto
                     writePhaseState('executed')
    'needs-verify':  writePhaseState('verifying')
                     spawn gsd-verify-auto <N>
                     // State set by verification result
    'needs-gaps':    gapClosure (max 3 cycles):
                     1. Rename existing *-UAT.md to *-UAT.prev.md (stale UAT fix)
                     2. spawn gsd-plan-phase <N> --gaps
                     3. spawn gsd-execute-phase <N> --gaps-only --auto
                     4. spawn gsd-verify-auto <N>
                     5. If still needs-gaps and cycles < 3: repeat
                     6. If cycles >= 3: log warning, mark as best-effort done
```

**Spawning within lifecycle modes:**
Use spawnSession from core/spawn.ts for detached spawning (runner context). Each spawn:
- Creates a title: `${project}-${gsdCommand}-phase-${phase}`
- Logs to `$PILOT_LOG_DIR/gsd-${title}.log`
- Waits for child process to exit before continuing cycle

**Important: Lifecycle spawning is SYNCHRONOUS (wait for completion).**
Unlike the runner's top-level spawning (fire and forget), lifecycle mode spawning within a phase cycle must wait for each step to complete before moving to the next. Use `execa` with `await` (not detached) for these inner spawns. The detached spawning is only for the runner's top-level job management.

So lifecycle.ts should have its own spawn helper that runs synchronously:
```typescript
async function spawnAndWait(projectDir: string, command: string, args: string): Promise<number> {
  const config = getConfig();
  const title = truncateTitle(path.basename(projectDir), command, args);
  const logFile = path.join(config.logDir, `gsd-${title}.log`);
  
  const result = await execa('opencode', [
    'run', '--format', 'default', '--title', title,
    '--command', `gsd-${command}`,
    ...(args ? [args] : [])
  ], {
    cwd: projectDir,
    stdin: 'ignore',
    stdout: fs.openSync(logFile, 'a'),
    stderr: fs.openSync(logFile, 'a'),
  });
  
  return result.exitCode ?? 1;
}
```

Note: NOT detached, NOT stdio:'inherit' (this runs in runner context, not interactive).
