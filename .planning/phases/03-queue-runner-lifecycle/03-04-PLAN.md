**src/commands/add.ts** — pilot add <project> <mode> [args]

1. Validate mode is one of: `build-full`, `continue`, `continue-all`, `build-to-phase`, `add-and-build`, `run-command`
   - If invalid → exit 2 with: `Error: Invalid mode '${mode}'. Valid: build-full, continue, continue-all, build-to-phase, add-and-build, run-command`
2. Resolve project dir from PILOT_PROJECT_DIR + project name
   - Validate dir exists (except for build-full which may create it)
3. If --dry-run: output what would be added and exit
4. Build queue entry line: `## ${project} | ${mode}${args.length > 0 ? ' | ' + args.join(' ') : ''}`
5. Use withQueueLock to safely append to QUEUE.md:
   ```typescript
   await withQueueLock(async () => {
     const content = await readFile(config.queueFile, 'utf8').catch(() => '');
     const newContent = content.trimEnd() + '\n\n' + entryLine + '\n';
     await writeFile(config.queueFile, newContent);
   });
   ```
6. Output: `✓ Added to queue: ${project} | ${mode}` (human) or JSON with entry details

**--json output:**

**src/commands/stop.ts** — pilot stop

1. Read runner PID from `$PILOT_LOG_DIR/gsd-queue-pid` using readPidFile
2. If PID is null or not alive:
   - Clean up stale PID file if it exists
   - Output: "Runner not running" (human) or `{ "status": "not_running" }` (JSON)
   - Exit 0
3. Send SIGTERM to runner PID: `process.kill(pid, 'SIGTERM')`
4. Wait up to 30s for process to die (poll isProcessAlive every 1s)
5. If still alive after 30s and --force:
   - Import tree-kill, kill entire tree with SIGKILL
   - `treeKill(pid, 'SIGKILL')`
6. If still alive after 30s and NOT --force:
   - Output: "Runner still alive after 30s. Use --force to kill."
   - Exit 1
7. Clean up PID file
8. Output: `✓ Runner stopped (PID ${pid})` (human) or `{ "status": "stopped", "pid": N }` (JSON)

Import tree-kill: `import treeKill from 'tree-kill'`. Wrap callback in promise:
```typescript
function treeKillAsync(pid: number, signal: string): Promise<void> {
  return new Promise((resolve, reject) => {
    treeKill(pid, signal, (err) => err ? reject(err) : resolve());
  });
}
```

**src/commands/run.ts** — pilot run

1. Parse options from commander (already registered in index.ts):
   - `--max-parallel N` (default 5)
   - `--max-retries N` (default 3)
   - `--once`
   - `--dry-run`
   - `--force`
2. Convert to RunnerOptions:
   ```typescript
   const runnerOpts: RunnerOptions = {
     maxParallel: parseInt(opts.maxParallel as string, 10) || 5,
     maxRetries: parseInt(opts.maxRetries as string, 10) || 3,
     once: opts.once === true,
     dryRun: opts.dryRun === true,
     force: opts.force === true,
   };
   ```
3. Create runner: `const runner = createRunner(runnerOpts);`
4. Start runner: `await runner.start();`
5. The runner handles everything (scan, launch, reap, shutdown)
6. On clean exit: exit 0
7. On error: log error, exit 1

For --json mode: The runner is a long-running process, so --json doesn't really apply to its normal operation. However, if --dry-run is set, output the dry-run results as JSON.

Human output during run (emitted by runner via events or console):

**src/commands/build.ts** — pilot build <project> [desc]

Convenience command that detects mode, adds to queue, optionally starts runner.

1. Resolve project dir
2. Detect mode:
   - If `.planning/` exists in project dir → mode = `continue-all`, no args
   - If `.planning/` does NOT exist → mode = `build-full`, args = description
3. **build-full with existing .planning/ → EXIT 1** with: `Error: .planning/ already exists in ${project}. Use 'continue-all' for existing projects.`
   Actually: the detection already handles this. If .planning exists → continue-all. If not → build-full. The user can't accidentally build-full on existing projects through this command.
4. Call add command logic (or reuse addCommand directly) to add entry to queue
5. Unless `--no-run`:
   - Check if runner is active: read gsd-queue-pid, check isProcessAlive
   - If runner NOT active: start it (spawn runner as a child or use createRunner)
   - If runner IS active: output "Runner already active, entry queued"
6. Output: `✓ Queued: ${project} | ${mode}` and `✓ Runner started` or `Runner already active`

**For starting the runner from build:** The cleanest approach is to spawn `pilot run` as a detached child process (so it survives the build command exiting):

```typescript
import { execa } from 'execa';
const pilotBin = process.argv[1]!; // path to pilot binary
await execa('node', [pilotBin, 'run'], {
  detached: true,
  stdin: 'ignore',
  stdout: 'ignore',
  stderr: 'ignore',
}).unref();
```

Or use the resolved path from the bin. The key: it must be detached so `pilot build` exits immediately while runner continues.
