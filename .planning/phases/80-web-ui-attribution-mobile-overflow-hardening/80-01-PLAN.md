  <action>
    **Root cause investigation:** The current `resolveStepIndex()` has three attribution tiers:
    1. Match by `candidate.sessionId === step.sessionId`
    2. Match by `candidate.sessionTitle === step.sessionTitle`
    3. Match by time window: `candidate.createdAt >= step.startedAtMs && candidate.createdAt <= step.completedAtMs`

    **The gap:** Tier 3 (time window) fails when:
    - A step has `completedAtMs === null` (still running) — the window ends at `POSITIVE_INFINITY`, which IS handled. BUT...
    - A step has completed but the candidate's `createdAt` is from a child session that was CREATED during the step but UPDATED after the step completed (e.g., a judge sub-session that wraps up after the parent step is marked done)
    - When ALL steps have completed, late activity (e.g., from judge sessions) falls after every time window

    **The fix — add two additional attribution tiers:**

    **Tier 4 — Child session transitivity:** If a candidate's `sessionId` matches a child session of any step's root session, attribute to that step. This requires looking up parent-child relationships. In the BFS loop where children are discovered, build a `Map<childSessionId, parentStepIndex>` that tracks which step "owns" which child sessions transitively.

    **Tier 5 — Last-step fallback:** If no tier matches but the candidate's `createdAt` is AFTER the last step's `startedAtMs`, attribute to the last step (by `startedAtMs` order). This catches late judge/wrap-up activity that fires after all step windows close.

    **Implementation steps:**

    1. In `getJobTimeline()`, after building `allStepRefs`, build a `childToStepIndex: Map<string, number>` during the BFS traversal. When processing children of a session, look up which stepRef owns that session (via sessionId match) and record `childToStepIndex.set(child.id, owningStepIndex)`.

    2. Update `resolveStepIndex()` to accept an additional parameter `childToStepIndex: Map<string, number>` and add:
       - After tier 3 (time window), check `childToStepIndex.get(candidate.sessionId)` — if found, return that step index
       - After tier 4, as final fallback: find the step with the latest `startedAtMs` and if `candidate.createdAt >= latestStep.startedAtMs`, return that step's index

    3. Update the call site in `getJobTimeline()` to pass the new map.

    **Important constraints:**
    - Do NOT remove the unattributed bucket — it must remain for genuinely unassignable content
    - Do NOT hardcode special cases for specific job IDs
    - Do NOT change the rendering logic — this is purely data-layer attribution
    - Preserve backward compatibility: existing 3-tier attribution must work identically
  </action>
