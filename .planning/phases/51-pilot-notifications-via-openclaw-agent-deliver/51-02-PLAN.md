Create a small core module that owns all `openclaw agent --deliver` subprocess execution details.

1. Add `src/core/openclaw-deliver.ts` with:
   - an args builder from canonical route + prompt
   - executor using `execa('openclaw', args, { timeout: 30000, reject: false })`
   - typed result surface (`ok` + optional error text) for callback use

2. Always use explicit argument arrays (never shell-concatenated command strings) and include:
   - `agent --agent <agentId> --message <prompt> --deliver`
   - `--reply-channel <channel> --reply-to <to>`
   - `--reply-account <accountId>` only when present

3. Cover failure surfaces in tests:
   - non-zero exit from openclaw command
   - missing binary / spawn failure
   - account flag omitted when accountId absent

Why: isolating subprocess behavior here keeps callback logic simple and testable.

<task type="auto">
  <name>Task 2: Rewrite notifyJobCompletion to route-first OpenClaw delivery</name>
  <files>src/core/callback.ts, test/core/callback.test.ts</files>
  <action>
Convert callback transport to resolved-route delivery and enforce strict no-silent-fallback behavior.

1. In `src/core/callback.ts`:
   - resolve route via `notify-route` helpers (job snapshot -> project route -> safe legacy derive)
   - build a deterministic prompt that includes:
     `job_id`, `project`, `description`, final `status`, verdict/confidence when available, and concise next-step guidance
   - include explicit natural-response instruction for the target agent chat
   - call `openclaw-deliver` executor and return success/failure boolean

2. Remove `/hooks/wake` dependency for OpenClaw deliver targets:
   - do not derive `/wake` URLs
   - do not silently fall back to wake when route validation fails
   - surface precise configuration errors to stderr and return `false` (never throw)

3. Update callback tests for new contract:
   - group-target route invokes deliver with telegram group `to`
   - DM-target route invokes deliver with direct-chat `to`
   - invalid route logs actionable config error and does not attempt wake
   - prompt includes required context fields and natural-response instruction
   - function remains fire-and-forget safe (`false`, no throw) on delivery/runtime errors

Why: this is the requirement-critical runtime switch from wake semantics to reliable agent-chat delivery.
