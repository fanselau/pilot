<objective>
Fix ui-phase completion misclassification in the runner step lifecycle.

Purpose: When a ui-phase session produces its UI-SPEC artifact but then hits an interactive prompt (detected as HungSessionError), the step is currently marked `failed` even though the work succeeded. This creates false failure signals in `pilot status`, `pilot info`, and `pilot log`, making operators think the UI phase is broken when the run proceeds normally into plan-phase.

Output: Corrected `executeCommandStep` in runner.ts with artifact-aware HungSessionError handling for ui-phase steps, plus regression tests.
</objective>
