Replace with:

```typescript
if (this.activeJobs.size < this.options.maxParallel) {
  const job = getNextPending();
  if (job && !this.activeJobs.has(job.id)) {
    // Same-project serialization guard: check if any CURRENTLY ACTIVE job has the same
    // project name. Compare job.project (string) — NOT job.id. This prevents two jobs
    // for 'my-project' from running in parallel even if they have different IDs.
    const projectAlreadyActive = [...this.activeJobs.values()].some(
      ({ job: activeJob }) => activeJob.project === job.project,
    );
    if (projectAlreadyActive) {
      process.stderr.write(
        `[runner] Skipping ${job.id} (${job.project}): same-project job already active\n`,
      );
    } else {
      // Track BEFORE async launch so --once mode sees active jobs
      this.activeJobs.set(job.id, { job, title: '' });
      // Launch without awaiting — allows parallel jobs
      this.launch(job).catch(() => {
        // Error already handled in launch() via markFailed
      });
      continue; // Check for more immediately
    }
  }
}
```

**Critical design choice — in-memory guard via `this.activeJobs`, NOT `getRunningJobsForProject`:**

The `getRunningJobsForProject` function from Plan 25-01 is NOT used here. The guard iterates `this.activeJobs.values()` to check `activeJob.project === job.project`. This is correct because:
1. `this.activeJobs` is the runner's authoritative record of what IT is currently managing
2. `getRunningJobsForProject` queries the DB, which may include stale-running jobs from a crashed previous runner — those are handled by `reconcileStaleJobs`, not the launch guard
3. A single runner instance should only check its own state for launch decisions

The key_link in frontmatter referencing `getRunningJobsForProject` is for the reconciliation path (Task 2), not this launch guard.

The guard condition is `activeJob.project === job.project` (string equality on project name). Do NOT use `activeJob.id === job.id` — that is already handled by `this.activeJobs.has(job.id)` above it and solves a different problem (duplicate job ID). This guard specifically serializes DIFFERENT jobs targeting the SAME project.

// Periodic reconciliation: reset ghost-running jobs every N cycles
this.pollCycle++;

The `reconcileStaleJobs` function compares DB's running jobs against `this.activeJobs`. Any job in DB as 'running' but NOT in `this.activeJobs` is stale — it's reset to 'pending' so it gets retried.
