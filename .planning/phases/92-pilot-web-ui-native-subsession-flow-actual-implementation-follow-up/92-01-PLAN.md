    **Goal:** Make subsession content render at the same effective indentation as step-level content, integrated into the main scroll stream, not as a nested widget.

    **1. Rewrite `branch-lifecycle-block.tsx` — flatten the nesting:**

    The current component wraps content in TWO nested `border-l` divs plus SessionActivity adds a THIRD. This creates the "nested gutter" feel. Rewrite to:

    a) Remove the outer `<div className={`border-l ${config.borderClass} ${depthBg}`}>` wrapper entirely. The Collapsible should be the top-level element.

    b) Keep the CollapsibleTrigger sticky header — it's the ONLY visual separator between subsession content and parent content. Keep `position: sticky` with `top: ${(depth + 1) * 2.25}rem` and `zIndex: 20 - depth`. The header should use a very subtle background tint (`${depthBg}`) and a bottom border, but NOT a left border.

    c) Replace the CollapsibleContent wrapper. Current code:
    ```tsx
    <CollapsibleContent>
      <div className={`border-l ${config.borderClass} ${depthBg}`}>
        <SessionActivity ... />
        {children}
      </div>
    </CollapsibleContent>
    ```
    Change to:
    ```tsx
    <CollapsibleContent>
      <div className={`${depthBg}`}>
        <SessionActivity ... />
        {children}
      </div>
    </CollapsibleContent>
    ```
    Remove the `border-l` from the CollapsibleContent inner div. The content should flow at the same left edge as step-level content. Only use the subtle depth pastel background tint to maintain visual hierarchy.

    d) Simplify the DEPTH_PASTELS to be even more subtle — the goal is that subsession content feels like part of the same stream, with only a very faint tint difference:
    ```tsx
    const DEPTH_PASTELS = [
      '',                                     // depth 0: no tint (same as step content)
      'bg-slate-50/15 dark:bg-slate-900/8',   // depth 1: barely visible tint
      'bg-slate-50/10 dark:bg-slate-900/5',   // depth 2: even subtler
      'bg-slate-50/5 dark:bg-slate-900/3',    // depth 3+: nearly invisible
    ]
    ```

    **2. Rewrite `session-activity.tsx` — remove extra indentation:**

    The current component wraps content in `border-l-2 border-border/40 pl-2 ml-2 sm:pl-3 sm:ml-4`. This extra indentation inside an already-indented subsession is what creates the "separate lane" feel.

    Change the main content wrapper from:
    ```tsx
    <div className="min-w-0 max-w-full overflow-hidden py-3 px-1">
      <div className="space-y-0.5 border-l-2 border-border/40 pl-2 ml-2 sm:pl-3 sm:ml-4 max-w-full overflow-hidden">
    ```
    To:
    ```tsx
    <div className="min-w-0 max-w-full overflow-hidden py-1 px-2 sm:px-3">
      <div className="space-y-0.5 max-w-full overflow-hidden">
    ```
    Remove `border-l-2`, `pl-2`, `ml-2`, `sm:pl-3`, `sm:ml-4`. The content should sit at the same indentation as step-level items. Use minimal `px-2 sm:px-3` for breathing room, matching the step content pane's item padding. Reduce `py-3` to `py-1` to tighten spacing.

    **3. Verify `step-content-pane.tsx` — ensure fork-card items are not double-indented:**

    In the step content pane (around line 442-458), each step group's items are wrapped in:
    ```tsx
    <div className={[
      'space-y-0.5 border-l-2 pl-2 ml-2 sm:pl-3 sm:ml-4 max-w-full overflow-hidden',
      getSemanticColors(group).borderClass,
    ].join(' ')}>
    ```
    This is correct for regular activity/tool items but creates redundant indentation for fork-card items (which are BranchLifecycleBlock components).

    **Do NOT remove the border-l from the step content wrapper** — it provides the step-level visual structure. Instead, ensure that when a fork-card (BranchLifecycleBlock) is rendered within this wrapper, the BranchLifecycleBlock itself doesn't add MORE left indentation (which we addressed in step 1 above).

    The combination should be: step content has border-l-2 → BranchLifecycleBlock header is flush → SessionActivity content is flush → content reads at roughly the same indentation as step-level text items.

    **4. Verify `timeline-stream.tsx` — StepGroupSection alignment:**

    In the StepGroupSection (line 260), the item wrapper also has:
    ```tsx
    <div className="relative min-w-0 max-w-full overflow-hidden space-y-0.5 border-l-2 border-border/40 pl-2 sm:pl-4">
    ```
    This is the equivalent wrapper used in the TimelineStream (non-split-pane) view. Same principle applies: fork-cards rendered here should NOT receive additional left indentation from BranchLifecycleBlock.

    **5. Verify follow mode still works inside expanded subsessions:**

    The follow mode in `step-content-pane.tsx` auto-scrolls to `parentRef.current.scrollHeight` — this naturally includes content from expanded subsessions since they're in the same DOM flow. Verify this works after the layout changes. The key mechanism:
    - `autoFollow` state drives `parentRef.current.scrollTo({ top: scrollHeight })`
    - This works regardless of whether the newest content is inside a subsession or at step level
    - The 80px upward scroll cancellation threshold should still work since we're not changing the scroll container structure

    No code changes should be needed for follow mode — it already operates on the parent scroll container which includes all expanded subsession content. But verify by reading the `useEffect` at line 212-219 of step-content-pane.tsx.

    **6. Preserve semantic hierarchy:**

    Keep the sticky header content (semantic icon, label, status badge, role badge, duration, model) intact. Keep the SEMANTIC_TYPE_CONFIG integration. The visual hierarchy should come from:
    - Sticky headers stacking by depth (already works via position:sticky + computed top)
    - Very subtle depth-based pastel background tints
    - NOT from structural indentation or border-l nesting

    **Anti-patterns to avoid:**
    - Do NOT add new wrapper divs that create indentation
    - Do NOT remove the Collapsible — subsessions must remain foldable
    - Do NOT remove the sticky header — it's the primary hierarchy cue
    - Do NOT change the depth-based `top` calculation for sticky headers — `(depth + 1) * 2.25rem` works correctly
    - Do NOT change the `zIndex: 20 - depth` — it correctly stacks headers
  </action>
