Update `src/core/runner.ts` with these changes:

1. **Extend the `JudgeVerdict` interface (line ~87):**
   ```typescript
   interface JudgeVerdict {
     verdict: 'succeeded' | 'failed' | 'doubting' | 'pass' | 'fail' | 'partial';
     confidence: number;
     reason: string;
     retryRecommendation?: string;  // 'retry-resume' | 'retry-full' | 'none'
     retryHint?: string;
     failureFingerprint?: string[];
   }
   ```
   Note: `retryRecommendation`, `retryHint`, and `failureFingerprint` are optional (with `?`) because legacy judge output won't have them and the parser must not reject old-format verdicts.

2. **Update `parseJudgeVerdict` validation (line ~1525):**
   Change from: `if (!['succeeded', 'failed', 'doubting'].includes(verdict.verdict)) return null;`
   Change to: `if (!['succeeded', 'failed', 'doubting', 'pass', 'fail', 'partial'].includes(verdict.verdict)) return null;`
   This accepts both old and new verdict values.

3. **Update `runJudgeAndHandleResult` (line ~872) to handle new verdict values:**
   The current logic checks `judgeVerdict.verdict === 'succeeded'` and `judgeVerdict.verdict === 'doubting'`. Update to also handle new values:
   ```typescript
   // Pass verdicts
   if (judgeVerdict.verdict === 'succeeded' || judgeVerdict.verdict === 'pass') {
     updateJudgeVerdict(job.id, JSON.stringify(judgeVerdict));
   }
   // Partial with decent confidence = pass (same as 'doubting' >= 50)
   else if (
     (judgeVerdict.verdict === 'doubting' || judgeVerdict.verdict === 'partial')
     && judgeVerdict.confidence >= 50
   ) {
     updateJudgeVerdict(job.id, JSON.stringify(judgeVerdict));
     // Treat as pass — fall through
   }
   // Failed, or low-confidence doubt/partial
   else {
     updateJudgeVerdict(job.id, JSON.stringify(judgeVerdict));
     throw new Error(judgeVerdict.reason);
   }
   ```

**Do NOT change the `runJudge` method itself yet** — that's Plan 03. This plan only updates types and validation.
