In `web/src/routes/jobs.$jobId.tsx`, move the `isActive` computation below the `useQuery` call and derive it from `snapshot` instead of `loaderData`.

Current (broken):
```typescript
const isActive =
  loaderData?.job.status === 'running' ||
  loaderData?.job.status === 'pending'

const { data: snapshot } = useQuery({
  queryKey: ['job-detail', jobId],
  queryFn: () => getJobDetailFn({ data: jobId }),
  initialData: loaderData,
  refetchInterval: isActive ? 3000 : false,
})
```

New (fixed):
```typescript
const { data: snapshot } = useQuery({
  queryKey: ['job-detail', jobId],
  queryFn: () => getJobDetailFn({ data: jobId }),
  initialData: loaderData,
  // Always start with polling enabled — we'll use refetchInterval callback below
  refetchInterval: (query) => {
    const data = query.state.data
    const active = data?.job.status === 'running' || data?.job.status === 'pending'
    return active ? 3000 : false
  },
})
```

This uses TanStack Query's callback form of `refetchInterval` which receives the query instance. The callback re-evaluates on every fetch cycle, reading the latest data from the query cache. This completely eliminates the stale closure problem.

Remove the standalone `const isActive = ...` line that was above the query (it's no longer needed here since the layout route only uses isActive for the query interval).
