<feature>
  <name>Extended opencode DB queries</name>
  <files>src/core/opencode-db.ts, test/core/opencode-db.test.ts</files>
  <behavior>
Add these new functions to the existing opencode-db.ts (keep all existing functions):

**`getSessionMessages(sessionId: string, since?: number): SessionMessage[]`**
- Query the `message` table for session, parse `data` JSON column
- Extract role, content from the parsed data
- If `since` provided, only return messages after that epoch timestamp
- Order by time_created ASC

**`getLastMessage(sessionId: string): SessionMessage | null`**
- Return the most recent message for a session
- Useful for monitoring — "what's the AI doing right now?"

**`isSessionActive(sessionId: string): boolean`**
- Check if a session has any running parts (status='running' in part table)
- This replaces PID tracking — if opencode shows active parts, the session is alive

**`getSessionTokens(sessionId: string): { input: number; output: number }`**
- Aggregate token usage from the message table's `data` JSON column
- Parse `usage.input_tokens` and `usage.output_tokens` from assistant messages
- Return totals

**`getRecentSessions(limit: number): SessionInfo[]`**
- Return last N sessions ordered by time_updated DESC
- Include message count (COUNT from message table)

**Clean up existing functions:**
- Remove the `message_count` from SessionInfo where it was optional — keep it as always-present in getRecentSessions results
- Ensure all functions use the same cachedDb pattern
- Update the `SessionInfo` return type to include optional tokenUsage

**Test cases (using in-memory DB with schema matching opencode):**
- getSessionMessages returns messages in chronological order
- getSessionMessages with `since` filters correctly
- getLastMessage returns most recent message
- getLastMessage returns null for empty session
- isSessionActive returns true when running parts exist
- isSessionActive returns false when all parts completed
- getSessionTokens aggregates correctly across messages
- getRecentSessions returns sessions ordered by updated desc
- All functions return safe defaults when DB unavailable (empty arrays, null, false, zeros)
  </behavior>
  <implementation>
Use the existing cachedDb/openDb pattern. Create an in-memory DB in tests with the opencode schema (session, message, part tables). Parse JSON data columns with try/catch for safety.

Token aggregation: opencode stores message data as JSON. Assistant messages have a `usage` field with `input_tokens` and `output_tokens`. Sum these across all assistant messages for a session.

Session activity: query part table for any row with status='running' for the session.
  </implementation>
</feature>
