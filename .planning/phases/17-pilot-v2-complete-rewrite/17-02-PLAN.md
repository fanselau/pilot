  <behavior>
The db module wraps better-sqlite3 for pilot.db at ~/.pilot/pilot.db:

**Schema** (from requirements/pilot-v2-master.md):
```sql
CREATE TABLE IF NOT EXISTS jobs (
  id TEXT PRIMARY KEY,
  project TEXT NOT NULL,
  scope TEXT NOT NULL CHECK(scope IN ('quick', 'phase', 'milestone')),
  description TEXT NOT NULL,
  requirement_path TEXT,
  status TEXT NOT NULL DEFAULT 'pending' CHECK(status IN ('pending', 'running', 'completed', 'failed', 'cancelled')),
  priority INTEGER DEFAULT 0,
  depends_on TEXT REFERENCES jobs(id),
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  started_at TEXT,
  completed_at TEXT,
  error TEXT,
  attempts INTEGER DEFAULT 0,
  max_attempts INTEGER DEFAULT 3,
  delegation_plan TEXT,
  current_step INTEGER DEFAULT 0,
  session_titles TEXT
);
```

**ID generation**: 4 alphanumeric chars (same shortId pattern from v1 queue-store).

**Functions (all synchronous — better-sqlite3 is sync):**
- `addJob(project, scope, description, requirementPath?)` → returns Job with generated id
- `getJob(id)` → Job | null
- `getNextPending()` → next job by priority DESC, created_at ASC where status='pending'
- `markRunning(id)` → sets status='running', started_at=now, attempts++
- `markCompleted(id)` → sets status='completed', completed_at=now
- `markFailed(id, error)` → sets status='failed', completed_at=now, error=error
- `cancel(id)` → sets status='cancelled'
- `retry(id)` → sets status='pending', clears started_at/completed_at/error
- `getQueue()` → all pending + running jobs, ordered by priority DESC, created_at ASC
- `getRecent(limit=20)` → last N completed/failed/cancelled jobs
- `updateDelegationPlan(id, plan: DelegationPlan)` → stores JSON string
- `advanceStep(id)` → increments current_step
- `bump(id)` → sets priority to max(priority)+1 for this job (moves to front)
- `updateSessionTitles(id, titles: string[])` → stores JSON array in session_titles column. Called by runner after each spawnAndWait to track which opencode sessions a job spawned. Used by log.ts to find sessions associated with a job.
- `openPilotDb()` → returns Database instance, auto-creates DB + table on first call
- `_getTestDb()` → returns in-memory DB for testing

**Auto-creation:** On first `openPilotDb()` call, create ~/.pilot/ directory and pilot.db with the schema. Cache the connection at module level.

**Test cases:**
- addJob creates a job and returns it with valid 4-char id
- getNextPending returns highest priority pending job
- getNextPending returns oldest when priorities equal
- getNextPending returns null when no pending jobs
- markRunning sets status, started_at, increments attempts
- markCompleted sets status and completed_at
- markFailed sets status, completed_at, and error message
- cancel sets status to cancelled
- retry resets job to pending state
- getQueue returns only pending+running, ordered correctly
- getRecent returns completed/failed/cancelled in reverse chrono
- updateDelegationPlan stores and retrieves JSON plan
- advanceStep increments current_step
- bump moves job to front of queue
- addJob with requirementPath stores the path
- updateSessionTitles stores and retrieves JSON array of session titles
- updateSessionTitles appends to existing titles (does not overwrite)
  </behavior>
  <implementation>
Use better-sqlite3 synchronous API. In-memory DB (':memory:') for tests.

DB auto-creation pattern:
```typescript
let cachedDb: Database.Database | null = null;

function openPilotDb(): Database.Database {
  if (cachedDb) return cachedDb;
  const config = getConfig();
  mkdirSync(dirname(config.pilotDbPath), { recursive: true });
  cachedDb = new Database(config.pilotDbPath);
  cachedDb.pragma('journal_mode = WAL');
  cachedDb.exec(CREATE_TABLE_SQL);
  return cachedDb;
}
```

Map DB rows to Job type using a simple rowToJob mapper.
