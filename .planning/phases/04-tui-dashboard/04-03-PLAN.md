  <name>Task 2: Create useStatusData hook and App shell</name>
  <files>src/tui/useStatusData.ts, src/tui/App.tsx</files>
  <action>
Create `src/tui/` directory, then create the two files:

**`src/tui/useStatusData.ts`** — A custom React hook that fetches all dashboard data on a configurable interval:

```typescript
import { useState, useEffect, useCallback } from 'react';
```

Export a `StatusData` interface containing:
- `running`: Array of `{ session: string; pid: number; runtimeSeconds: number; logStaleSeconds: number; score: number; verdict: string }` — from scanPidFiles() cross-referenced with stuck scoring
- `queue`: Array of `QueueEntry` from parseQueueFile()
- `completed`: Array of `SessionInfo` — sessions NOT matched to PID files, sorted by updated desc, take 10
- `runner`: `{ active: boolean; pid: number | null }` — from readPidFile('queue')
- `summary`: `{ running: number; stuck: number; queued: number; done: number; failed: number }`
- `loading`: boolean (true during initial fetch)
- `error`: string | null
- `refresh`: `() => void` — manual refresh callback

Export a `useStatusData` hook that accepts `{ intervalMs: number }` and returns `StatusData`.

Implementation:
1. Import from `../core/sessions.js` (listSessions), `../core/queue-parser.js` (parseQueueFile), `../core/stuck.js` (scoreFromSignals), `../core/process.js` (scanPidFiles, readPidFile, isProcessAlive, getProcessRuntime), `../core/config.js` (getConfig). Also import `getLogStaleness` from `../core/stuck.js`, and `getProcessRss`, `getSystemFreeMem` from `../core/stuck.js`. Import `readFile, stat` from `node:fs/promises` for log file stat.
2. Use `useState` for data, loading, and error states.
3. Create a `fetchData` function wrapped in `useCallback`:
   - Call `getConfig()` for paths
   - Call `listSessions()` to get all sessions
   - Call `scanPidFiles()` to get running PIDs
   - Call `parseQueueFile(config.queueFile)` (catch errors gracefully — queue file may not exist)
   - Call `readPidFile('queue')` to check runner status, then `isProcessAlive()` on that PID
   - For each PID entry from scanPidFiles: compute a quick stuck score. Do NOT call `computeStuckScore()` — it does CPU sampling which takes 30s per process. Instead:
     a. Get log staleness via `getLogStaleness()` (reads log file mtime — fast)
     b. Get process runtime via `getProcessRuntime()` (reads /proc — fast)
     c. Read process RSS via `getProcessRss()` (reads /proc — fast)
     d. Read system free memory via `getSystemFreeMem()` (reads /proc — fast)
     e. Call `scoreFromSignals({ logStaleness, runtime, cpuSamples: [], messageCount: null, processRss, systemFreeMb, procState: null, wchan: null })` — empty cpuSamples skips CPU signal, null messageCount skips message signal. Gives quick score based on log staleness + memory only.
   - Cross-reference sessions with PID entries to build running array
   - Filter non-running sessions for completed array (sort by updated desc, take 10)
   - Build summary counts from queue entries
   - Set all state, set loading=false
   - On error: set error message, set loading=false, don't crash
4. Use `useEffect` with `setInterval` at `intervalMs`. Call `fetchData()` immediately on mount, then on each interval tick. On cleanup, clear the interval.
5. Return the `StatusData` object from the hook.

**IMPORTANT:** All imports from local `.ts` files must use `.js` extension (ESM). This file is `.ts` (no JSX needed).
