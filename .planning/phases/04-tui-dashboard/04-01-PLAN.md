Create `src/tui/useStatusData.ts` — a custom React hook that fetches all dashboard data on an interval:

```typescript
import { useState, useEffect, useCallback } from 'react';
```

The hook accepts `{ intervalMs: number }` and returns a typed `StatusData` object containing:
- `running`: Array of `{ session: string; pid: number; runtimeSeconds: number; logStaleSeconds: number; score: number; verdict: string }` — from scanPidFiles() cross-referenced with computeStuckScore()
- `queue`: Array of `QueueEntry` from parseQueueFile()  
- `completed`: Array of `SessionInfo` — sessions NOT matched to PID files, sorted by updated desc, take 10
- `runner`: `{ active: boolean; pid: number | null }` — from readPidFile('queue')
- `summary`: `{ running: number; stuck: number; queued: number; done: number; failed: number }`
- `loading`: boolean (true during initial fetch)
- `error`: string | null
- `refresh`: () => void — manual refresh callback

Implementation:
1. Import from `../core/sessions.js`, `../core/queue-parser.js`, `../core/stuck.js`, `../core/process.js`, `../core/config.js`
2. Use `useState` for data + loading + error
3. Use `useEffect` with `setInterval` at `intervalMs` (default 3000)
4. Wrap the fetch logic in `useCallback` named `fetchData`
5. In fetchData: call `listSessions()`, `scanPidFiles()`, `parseQueueFile(config.queueFile)`, `readPidFile('queue')` — catch errors gracefully (set error state, don't crash)
6. For stuck scoring: call `computeStuckScore(pid, session)` for each PID entry. **Important:** This does CPU sampling which takes 30s per process. For TUI refresh, skip CPU sampling — use a lightweight version. Instead of calling computeStuckScore directly, just read log staleness and process state without CPU sampling. Create a `quickStuckCheck` function inline that reads `/proc/pid/status` state and log file mtime only (no sampleCpu). Score: log stale >5min = 40pts, process state T/Z = 50pts. This keeps refresh under 1s.
7. On `useEffect` cleanup, clear the interval
8. Export `useStatusData` as named export, and export the `StatusData` interface

Create `src/tui/Dashboard.tsx`:

The Dashboard is the main layout component. It manages:
- Which panel is "active" (for highlighting border): `activePanel` state cycling through `'running' | 'queue' | 'log' | 'completed'`
- Which item is selected within the active panel: `selectedIndex` state (number)
- Whether log panel is expanded: `logExpanded` state (boolean)
- Selected session for log viewing: `selectedSession` state (string | null)

Layout (using Ink's `<Box>`):
- Use `useInput` from ink for keyboard handling (this is needed here for panel-level state management)
- `Tab` cycles `activePanel` in order: running → queue → log → completed → running
- `j`/`↓` increments selectedIndex (clamped to panel item count)
- `k`/`↑` decrements selectedIndex (clamped to 0)
- `Enter` on running panel: sets `selectedSession` to that session name, sets `logExpanded = true`
- `Enter` on log panel when expanded: collapses log panel
- `K` (capital): if a running session is selected, call `treeKill(pid)` after confirmation state
- `r`: calls `data.refresh()`
- `q`: calls `process.exit(0)` (Ink handles cleanup via useApp().exit())

Layout structure:
```
┌─ Running ──────────────┬─ Queue ──────────────────┐
│                        │                           │
│                        │                           │
├─ Log ──────────────────┴───────────────────────────┤
│ (expandable — takes full width)                    │
├─ Completed ────────────────────────────────────────┤
│                        │                           │
└────────────────────────┴───────────────────────────┘
```

Use `process.stdout.columns` and `process.stdout.rows` for responsive sizing:
- Top row: Running (50% width) + Queue (50% width), height = 40% of rows
- Middle: Log panel, full width, height = collapsed 1 line / expanded 40% of rows
- Bottom: Completed, full width, height = remaining rows

Panels receive: `active: boolean` (for border highlight), `items: Array`, `selectedIndex: number`, `width: number`, `height: number`.

Active panel gets a bright border (use Ink's `borderStyle="round"` + `borderColor="green"` when active, `borderColor="gray"` when inactive).

Call `useStatusData({ intervalMs })` here and pass data down to panels.

Header line above panels: `" Pilot Dashboard  │  {running} running  {stuck} stuck  {queued} queued  │  ↑↓/jk:select  Tab:panel  Enter:expand  q:quit"`
