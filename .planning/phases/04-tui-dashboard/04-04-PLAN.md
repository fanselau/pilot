**`src/tui/RunningPanel.tsx`**:

Props: `{ sessions: Array<{ session: string; pid: number; runtimeSeconds: number; logStaleSeconds: number; verdict: string }>; active: boolean; selectedIndex: number; width: number; height: number }`

Renders a `<Box>` with border and title "Running":
- Each session on its own line: `● {session}  {formatDuration(runtimeSeconds)}  {logActivityIndicator}`
- Log activity indicator: if logStaleSeconds < 60 → `<Text color="green">◆</Text>` (active), 60-300 → `<Text color="yellow">◆</Text>`, >300 → `<Text color="red">◆</Text>` (stale)
- Selected item (when panel is active): prefix with `>` and use `<Text inverse>` or `<Text bold>`
- If no sessions: `<Text dimColor>No active sessions</Text>`
- Import `formatDuration` from `../util/format.js` (pure string formatting, no color deps)
- Use Ink's `<Text color="...">` for all colors — do NOT import picocolors

**`src/tui/QueuePanel.tsx`**:

Props: `{ entries: QueueEntry[]; active: boolean; selectedIndex: number; width: number; height: number; summary: { done: number; failed: number; total: number } }`

Where `total = done + failed + pending + running` (computed by Dashboard before passing).

Renders:
- Title: "Queue"
- Progress bar line: `████░░░░░░ {done}/{total}` — calculate ratio = done/total, barWidth = Math.min(width - 10, 20), fill = Math.round(ratio * barWidth). Use `<Text color="green">{'█'.repeat(fill)}</Text><Text dimColor>{'░'.repeat(barWidth - fill)}</Text> {done}/{total}`
- Pending entries: `<Text dimColor>○</Text> {project}: {mode}` (truncate project+mode to fit width - 6)
- Running entries: `<Text color="cyan">⟳</Text> {project}: {mode}`
- If no entries: `<Text dimColor>Queue empty</Text>`
- Selected item highlight when active

**`src/tui/LogPanel.tsx`**:

Props: `{ sessionName: string | null; expanded: boolean; active: boolean; width: number; height: number }`

When collapsed (expanded=false): single line: `<Text dimColor>Log: select a session and press Enter</Text>`

When expanded (expanded=true + sessionName set):
1. Use `useState<string[]>` for logLines state
2. Use `useEffect` triggered by `sessionName` changes:
   - Import `getConfig` from `../core/config.js`
   - Construct path: `path.join(config.logDir, \`gsd-\${sessionName}.log\`)`
   - Read the file with `fs.readFile` (from `node:fs/promises`), split into lines
   - Store last `(height - 2)` lines in state
   - If file doesn't exist: set logLines to `['Log file not found']`
3. Also re-read on a 3-second interval when expanded (to show new log lines)
4. Render: Title `"Log: {sessionName}"`, each line as `<Text>{line}</Text>`
5. If sessionName is null but expanded: `<Text dimColor>No session selected</Text>`

**`src/tui/CompletedPanel.tsx`**:

Props: `{ sessions: SessionInfo[]; active: boolean; selectedIndex: number; width: number; height: number }`

Renders:
- Title: "Completed"
- Each session: `<Text color="green">✓</Text> {title}  <Text dimColor>{relativeTime}</Text>`
- Relative time calculation: `const ago = Date.now() - session.updated; if (ago < 60000) '{Math.round(ago/1000)}s ago'; else if (ago < 3600000) '{Math.round(ago/60000)}m ago'; else '{Math.round(ago/3600000)}h ago'`
- If no sessions: `<Text dimColor>No recent completions</Text>`
- Flash effect for new completions: use `useRef<Set<string>>` for prevIds and `useState<Set<string>>` for flashIds. On render, compare current session IDs to prevIds ref. New IDs → add to flashIds. For each flash ID, `setTimeout` 3000ms to remove from flashIds. Items in flashIds render with `<Text color="green" bold>`.
- Selected item highlight when active

**`src/tui/Dashboard.tsx`** (replace placeholder from Plan 04-03):

Props: `{ intervalMs: number }`

State management:
- `activePanel`: `'running' | 'queue' | 'log' | 'completed'` — starts at `'running'`
- `selectedIndex`: number — 0 initially, reset to 0 when activePanel changes
- `logExpanded`: boolean — false initially
- `selectedSession`: `string | null` — null initially
- `killConfirm`: `{ session: string; pid: number } | null` — null initially

Call `useStatusData({ intervalMs })` to get data.

Keyboard handling with `useInput` from `ink`:
- `Tab`: cycle activePanel in order running → queue → log → completed → running. Reset selectedIndex to 0.
- `j` or key.downArrow: increment selectedIndex (clamp to item count - 1 for active panel)
- `k` or key.upArrow: decrement selectedIndex (clamp to 0)
- `Enter`: if activePanel is 'running' and a session is selected → set selectedSession to that session name, set logExpanded = true, switch activePanel to 'log'. If activePanel is 'log' and logExpanded → set logExpanded = false.
- `K` (capital K, detected via input === 'K'): if activePanel is 'running' and a running session is selected → set killConfirm to `{ session, pid }`. If killConfirm is already set, ignore.
- When killConfirm is active: `y` → dynamically `import('tree-kill')`, get `.default`, call `treeKill(pid, 'SIGTERM')`, clear killConfirm, call data.refresh(). `n` or any other key → clear killConfirm.
- `r`: call `data.refresh()` for immediate data fetch
- `q`: call `useApp().exit()` from ink

Layout using Ink's `<Box>`:
- Use `process.stdout.columns` and `process.stdout.rows` for sizing
- Header line: `<Text bold> Pilot Dashboard  │  {data.summary.running} running  {data.summary.stuck} stuck  {data.summary.queued} queued  │  ↑↓/jk:select  Tab:panel  Enter:expand  q:quit</Text>`
- Top row: `<Box>` with flexDirection="row" — RunningPanel (50% width) + QueuePanel (50% width), height ~40% of rows
- Middle: LogPanel, full width, height = 1 line when collapsed / ~40% when expanded
- Bottom: CompletedPanel, full width, remaining height
- Active panel gets `borderColor="green"`, inactive gets `borderColor="gray"`
- If `killConfirm` is set, render a line: `<Text color="yellow">Kill {killConfirm.session}? (y/n)</Text>`
- If data.loading: show `<Text dimColor>Loading...</Text>`
- If data.error: show `<Text color="red">Error: {data.error}</Text>`

Pass appropriate props to each panel including `active` (whether it's the current activePanel), `selectedIndex` (only meaningful when active), width/height computed from terminal dimensions.

**CRITICAL CONSTRAINTS:**
- Do NOT import picocolors or cli-table3 anywhere in src/tui/. Use Ink's `<Text>` with color props.
- Do NOT import anything from src/commands/.
- Only import from src/core/, src/util/format.ts, ink, react.
- All files use named exports (no default exports).
- Use `.js` extension for all local imports.

interface TuiOpts {

  json?: boolean;

Implementation of `tuiCommand(opts: TuiOpts)`:

1. If `opts.json` → write error to stderr and exit 1: `"Error: TUI does not support --json mode"`

2. Parse interval: `const interval = Number(opts.interval) || 3;`

3. **Lazy import ink and App** — this is the critical pattern. Use dynamic `import()` inside the function body, NOT static imports at the top of the file:
```typescript
const { createElement } = await import('react');
const { render } = await import('ink');
const { App } = await import('../tui/App.js');
```

This ensures ink and react are ONLY loaded when `pilot tui` is invoked. All other commands (`pilot status`, `pilot queue`, etc.) never load React.

4. Render with createElement (not JSX — this file is .ts not .tsx):
```typescript
const { waitUntilExit } = render(
  createElement(App, { interval }),
  { exitOnCtrlC: true }
);
await waitUntilExit();
```

5. Export `tuiCommand` as named export.

**IMPORTANT:** This file MUST remain `.ts` (not `.tsx`). The index.ts already imports it as `./commands/tui.js`. Using createElement() instead of JSX avoids needing to change the extension.

**Verify lazy loading**: After this change, `pilot --help` should still run fast because ink/react are only imported inside the async tuiCommand function body.
