1. **Daemon status in `pilot status` (src/commands/status.ts):**
   - Check for the runner PID file at `~/.pilot/pilot.pid` (or the configured location — check config.ts for the PID file path).
   - If PID file exists, read the PID, check if process is alive via `process.kill(pid, 0)`.
   - Display in status output: `Runner: active (PID 12345)` if alive, `Runner: stopped (stale PID file)` if PID file exists but process dead, `Runner: stopped — run: pilot service start` if no PID file.
   - Also check `systemctl --user is-active pilot.service 2>/dev/null` as alternative detection.
   - Add this info near the top of the status output, before job listings.

2. **Setup owner hint (src/core/setup.ts):**
   - After `pilot setup` completes successfully, if `--owner` was NOT provided:
   - Print: `\n  Hint: Register this project with an owner to enable notifications:\n  pilot setup --owner <agent-id>\n`
   - Only print when setup succeeds (not on error paths).

3. **Scope auto-detection feedback (src/commands/add.ts):**
   - When auto-detecting scope in `pilot add`, print the detected scope and a brief reason before queuing.
   - Pattern: `process.stderr.write(\`  Detected scope: ${scope} (${reason})\n\`);`
   - Reasons: "requirements directory" for milestone, "has ## sections / large file" for phase, "short description or small file" for quick.
   - Only print in non-JSON, non-silent mode.

4. **TUI footer keybindings (src/tui/components/footer-bar.tsx):**
   - Read the footer-bar.tsx file and identify all keybinding hints shown.
   - Remove hints for non-functional keys: `a` (add), `r` (retry), `x` (cancel), `s`/`3` (split view).
   - Only keep keybindings that are actually wired in app.tsx keyboard handler: `q` (quit), arrows/`j`/`k` (navigate), `Enter` (detail), `K` (kill), `Tab` (cycle panels), `?` (help), `Esc` (back), `f` (filter) — verify each against app.tsx.

5. **Fix `pilot kill` (src/commands/kill.ts):**
   - Currently requires `--force` flag mandatorily.
   - Change to: `pilot kill <id>` works without `--force` — it should prompt for confirmation (or just perform the kill directly since this is a CLI tool, not a web app).
   - Simplest fix: make `--force` optional, defaulting to true (always force kill). Remove the "must specify --force" error check.
   - Keep `--force` as a recognized flag for backward compatibility but make it the default behavior.

6. **Service PATH warning (src/commands/service.ts):**
   - In `pilot service install`, after generating the systemd unit file, print a warning:
   - `\n  Warning: The systemd unit bakes in the current PATH. If you update Node.js/Bun or change PATH, run:\n  pilot service install\n  to regenerate the unit file.\n`

7. Run `npm test` to verify changes don't break anything.
