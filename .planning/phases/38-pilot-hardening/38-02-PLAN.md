  <files>

  <action>
1. **Unhandled rejection/exception handlers in `run()`:**
   - At the top of the `run()` method (before the main loop), add:
     ```ts
     process.on('unhandledRejection', (reason) => {
       process.stderr.write(`[runner] Unhandled rejection: ${errMsg(reason)}\n`);
       // attempt cleanup
       try { this.releaseLock?.(); } catch { /* best effort */ }
       for (const [, aj] of this.activeJobs) {
         try { process.kill(aj.pid, 'SIGTERM'); } catch { /* ignore */ }
       }
       process.exit(1);
     });
     process.on('uncaughtException', (err) => {
       process.stderr.write(`[runner] Uncaught exception: ${errMsg(err)}\n`);
       try { this.releaseLock?.(); } catch { /* best effort */ }
       for (const [, aj] of this.activeJobs) {
         try { process.kill(aj.pid, 'SIGTERM'); } catch { /* ignore */ }
       }
       process.exit(1);
     });
     ```
   - Clean up these handlers in the `finally` block of `run()` to avoid leaks if run() is called multiple times in tests.

2. **PID file management:**
   - After spawning a session process (where the PID is known), write the PID to `~/.pilot/pids/<jobId>.pid` using `writeFileSync`.
   - Create the `~/.pilot/pids/` directory on runner startup if it doesn't exist (`mkdirSync(..., { recursive: true })`).
   - On cleanup (job complete/fail), delete the PID file.
   - On startup reconciliation, scan the PID directory for `.pid` files and cross-reference with DB — kill any orphaned processes.

3. **Watchdog catch block logging (around lines 308-315):**
   - Find all bare `catch {}` or `catch { /* ignore */ }` in the watchdog/memory monitoring section.
   - Replace with `catch (err) { process.stderr.write(\`[runner] watchdog error: ${errMsg(err)}\n\`); }`.
   - If `resetToPending` fails inside the watchdog, remove the job from `this.activeJobs` so reconciliation picks it up on the next cycle.

4. **Replace `process.exit(1)` in `acquireRunnerLock` with thrown error:**
   - Find the `process.exit(1)` call in `acquireRunnerLock`.
   - Replace with `throw new Error('Failed to acquire runner lock: another instance is running')`.
   - This allows the `finally` block in `run()` to handle cleanup.

5. **Wrap `markFailed` in `launch()`:**
   - In the `launch()` method's catch/finally block, wrap the `markFailed()` call in its own try/catch so that if `blockProject()` (called within markFailed) fails, the job doesn't get stuck in `running` state.
   - Pattern: `try { markFailed(job.id, error); } catch (markErr) { process.stderr.write(\`[runner] markFailed also failed: ${errMsg(markErr)}\n\`); }`

6. **getDynamicMaxParallel logging:**
   - When `getDynamicMaxParallel` returns 0, log a message explaining why (low memory). 
   - Use a flag to only log once per state change (log when transitioning to 0, not every cycle): `if (maxParallel === 0 && !this.loggedLowMemory) { process.stderr.write('[runner] Low memory — not launching new jobs\n'); this.loggedLowMemory = true; } else if (maxParallel > 0) { this.loggedLowMemory = false; }`

7. Run `npm test` to verify runner tests still pass.

1. **delegate.ts — Log errors in bare catch blocks:**
   - Find all ~8 bare `catch {` blocks in delegate.ts (lines 68, 118, 135, 158, 249, 353, 432, 506).
   - Replace each with `catch (err) { process.stderr.write(\`[delegate] ${contextDescription}: ${errMsg(err)}\n\`); return null/default; }` where contextDescription describes what operation failed (e.g., "readFileSync failed", "stat check failed", etc.).
   - Import `errMsg` from `../util/errors.js` (should already be done by Plan 01).

2. **delegate.ts — waitForDelegationResult PID monitoring:**
   - In `waitForDelegationResult`, accept an optional `pid?: number` parameter.
   - Each poll cycle, if `pid` is provided, check `process.kill(pid, 0)` (signal 0 = existence check). If it throws (process is dead), bail immediately with a failure result instead of waiting the full 120s.
   - Pattern: `try { process.kill(pid, 0); } catch { /* process is dead, bail */ return { success: false, reason: 'spawned process died' }; }`
   - **Update call site (delegate.ts ~line 460):** Where `waitForDelegationResult` is called after spawning a process, pass the spawned PID: `await waitForDelegationResult(title, spawnedPid)`. Ensure the PID is captured from the spawn result (e.g., `const spawnedPid = child.pid;`) and threaded through to the call.

3. **opencode-db.ts — DB reconnection on corruption:**
   - Find the cached DB pattern (likely `let cachedDb: Database | null = null`).
   - In the catch blocks where DB-level errors occur, check for `SQLITE_CORRUPT`, `SQLITE_IOERR`, or similar error codes.
   - When detected, set `cachedDb = null` so the next call retries the connection.
   - Pattern: `catch (err) { if (errMsg(err).includes('SQLITE_CORRUPT') || errMsg(err).includes('SQLITE_IOERR')) { cachedDb = null; } throw err; }`

4. **callback.ts — Webhook URL validation + token protection:**
   - When `callbackUrl` is set and differs from `config.openclawHooksUrl`:
     a. Validate it's HTTPS: `if (!callbackUrl.startsWith('https://')) { process.stderr.write('[callback] Rejecting non-HTTPS callback URL\n'); return; }`
     b. Validate it's not a private IP: check against `10.`, `172.16.`-`172.31.`, `192.168.`, `127.`, `localhost`, `0.0.0.0` patterns.
     c. Only include `Authorization: Bearer ${token}` header when URL matches `config.openclawHooksUrl`. For custom URLs, omit the auth header entirely.
   - Add `signal: AbortSignal.timeout(10_000)` to any fetch calls (both the callback fetch and any Telegram fetch if present in this file).

5. **add.ts — File size limit on requirement reads:**
   - Before reading a requirement file in `pilot add`, check: `statSync(path).size < 1_048_576` (1MB).
   - If exceeded, print error: `process.stderr.write(\`Error: Requirement file exceeds 1MB limit: ${path}\n\`); process.exit(1);`
   - Import `statSync` from `node:fs`.

6. Run `npm test` to verify all tests pass.
