  The bug: `scan()` calls `findLaunchableAtomic()` which marks items as `running` + increments attempts. In dry-run mode, this consumes queue items that should be untouched.

  **Fix the `scan()` method** (around line 467): Add a conditional based on `this.opts.dryRun`:

  ```typescript
  private async scan(): Promise<QueueJsonItem | null> {
    const runningProjects = new Set<string>();
    for (const job of this.state.activeJobs.values()) {
      runningProjects.add(job.item.project);
    }

    try {
      if (this.opts.dryRun) {
        // Read-only scan — don't mark items as running
        return await findLaunchable(
          runningProjects,
          this.opts.maxParallel,
          this.state.activeJobs.size,
        );
      }
      return await findLaunchableAtomic(
        runningProjects,
        this.opts.maxParallel,
        this.state.activeJobs.size,
      );
    } catch (err) {
      this.emit('error', `Failed to scan queue: ${String(err)}`);
      return null;
    }
  }
  ```


  Do NOT change the dry-run emission logic (the `if (this.opts.dryRun) { this.emit('dry-run', item); }` block around line 400 is fine).
  Do NOT touch the main loop logic — only the scan method and the import.

<task type="auto">
  <name>Task 2: Harden build blocking with history lookup</name>
  <files>src/commands/build.ts</files>
  <action>
  The current build.ts tracks `addResult.id` via the runner's `complete` event. This works when the runner fires `complete` for the specific item. But there's an edge case: if `itemResult` is null after `runner.start()` returns (the event didn't fire for our item), the code falls through to `getItemById` which checks active items — but the item has already moved to history.

  **Fix the history fallback** (around line 100-108): Replace the current fallback logic with an explicit history check:

  ```typescript
  // Step 3: Check final status of our specific item
  if (itemResult === null) {
    // Check active items first
    const item = await getItemById(addResult.id!);
    if (item !== null) {
      itemResult = item.status === 'completed' ? 'success' : item.status;
    } else {
      // Item moved to history — check history for final status
      const { getHistory } = await import('../core/queue-store.js');
      const history = await getHistory(50);
      const historyItem = history.find((h) => h.id === addResult.id);
      if (historyItem) {
        itemResult = historyItem.status === 'completed' ? 'success' : 'failed';
      } else {
        itemResult = 'unknown';
      }
    }
  }
  ```

  Also update the import at the top to include `getHistory` if calling it directly (or use the dynamic import as shown above).

  **Verify the result checking** (lines 117-124): The current checks are:
  - `'success'` or `'success_no_artifacts'` → exit 0 ✓
  - `'failed'` → exit 1 ✓
  - else → print status (catches 'unknown' and other edge cases) ✓

  This is correct. No changes needed to the result checking logic.
  </action>
