Create `src/commands/kill.ts` implementing `killCommand(id: string, opts: { force?: boolean }): Promise<void>`.

Implementation:

```typescript
import { killJobSession } from '../core/runner.js';

```

Logic:

1. Look up job by `id`. If not found: write to stderr "Job not found: <id>" + exit 1.

2. Check `opts.force`. If NOT `--force`: write to stderr:
   ```
   Error: Use --force to terminate a running job.
   This will kill the active opencode session and mark the job as failed.
   Example: pilot kill <id> --force
   ```
   Then exit 1.

3. Check job status. If status is NOT 'running':
   - Write to stderr: `Job <id> is not running (status: <status>). Use 'pilot cancel <id>' for pending jobs.`
   - Exit 1.

4. **Kill sequence (order matters):**
   a. First: call `killJobSession(job)` — attempt to terminate the OS process.
      - If `{ killed: false }`: log a warning to stderr but CONTINUE to step (b). The process may already be gone.
   b. Then: call `forceQuitJob(id, 'cli')` — update DB state regardless of kill result.
      - If `{ ok: false }`: write error to stderr and exit 1.

5. Output:
   - Human mode: `  ✓ Killed job <id> (<project>): <killResult.reason>`
   - JSON mode: `{ killed: id, project, killResult: { killed, reason }, dbResult: { ok } }`

6. Exit 0 on success. Exit 1 if DB update failed (step b returns ok:false).

The kill-then-update order is important: always attempt process kill first, then always update DB. This prevents ghost-running jobs even if kill fails (process may already be dead).
