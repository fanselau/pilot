**Part A: Event-driven wake-up**

Add a DB file watcher that wakes the runner when new jobs are inserted. The runner currently always sleeps the full `pollInterval` between checks. With an fs.watch, new queue insertions can wake the loop within ~1s.

Implementation in the `run()` method:

1. Add a `wakeFlag` mechanism using a `Promise` that can be resolved early:
```typescript
let wakeResolve: (() => void) | null = null;

const wakeOrTimeout = (ms: number): Promise<void> => {
  return new Promise(resolve => {
    wakeResolve = resolve;
    setTimeout(() => {
      wakeResolve = null;
      resolve();
    }, ms);
  });
};

const triggerWake = () => {
  if (wakeResolve) {
    wakeResolve();
    wakeResolve = null;
  }
};
```

2. Watch the pilot.db file using `node:fs` `watch()`:
```typescript
import { watch as fsWatch } from 'node:fs';
// ...
const dbPath = config.pilotDbPath;
let dbWatcher: ReturnType<typeof fsWatch> | null = null;
try {
  dbWatcher = fsWatch(dbPath, { persistent: false }, () => {
    triggerWake();
  });
  dbWatcher.on('error', () => { /* ignore — DB may not exist yet */ });
} catch {
  // fs.watch may fail if DB doesn't exist yet — fallback to pure polling
}
```

3. Replace `await this.sleep(this.options.pollInterval * 1000)` with `await wakeOrTimeout(this.options.pollInterval * 1000)`.

4. In the `finally` block (after the main loop), add `dbWatcher?.close()` to clean up.

This gives event-driven dispatch for the common case (new job added → watcher fires → wake → dispatch) with polling as the fallback when watcher misses events or DB doesn't exist yet.

**Part B: killJobSession**

Add and export `killJobSession(job: Job): Promise<{ killed: boolean; reason: string }>`.

This function finds and terminates the opencode process for a running job:

1. Parse `job.sessionTitles` JSON to get the list of session title strings.
2. For each title: use `pgrep -f <title>` (via execa) to find PIDs running that title as part of their command line. Take the most recent session title first (last in array).
3. If no PID found via pgrep: return `{ killed: false, reason: 'Process not found for session titles' }`.
4. Send SIGTERM: `process.kill(pid, 'SIGTERM')`.
5. Wait 5 seconds (check every 500ms if process still alive via `kill(pid, 0)`).
6. If still alive: send SIGKILL via `process.kill(pid, 'SIGKILL')`.
7. Return `{ killed: true, reason: 'Sent SIGTERM/SIGKILL to PID <pid>' }`.

Handle errors:
- `pgrep` exits non-zero = no process found → return not killed
- `kill()` throws ESRCH = process already gone → return killed (it's gone)
- Any other error → return `{ killed: false, reason: error message }`

Import `execa` (already imported). Use `reject: false` on the pgrep call.

Export `killJobSession` in the exports block at the bottom of runner.ts.
