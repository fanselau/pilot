<task type="auto">
  <name>Task 1: Add types + DB schema + seed migration</name>
  <files>src/core/types.ts, src/core/db.ts</files>
  <action>
  1. In `src/core/types.ts`, add these interfaces:

  ```typescript
  /** Row shape for the model_profiles table. */
  export interface ModelProfileRow {
    provider_mode: string;
    agent_or_scope: string;
    profile: string;        // 'quality' | 'balanced' | 'budget'
    model: string;          // e.g. 'anthropic/claude-opus-4-6'
    variant: string | null; // e.g. 'xhigh', 'high', or null
  }

  /** Row shape for the provider_modes table. */
  export interface ProviderModeRow {
    name: string;
    description: string;
    is_builtin: number;    // 1 = built-in, 0 = user-created
    created_at: string;
  }
  ```

  2. In `src/core/db.ts`:

  a. Add two new CREATE TABLE IF NOT EXISTS statements (above the existing `openPilotDb` function):

  ```sql
  CREATE TABLE IF NOT EXISTS model_profiles (
    provider_mode TEXT NOT NULL,
    agent_or_scope TEXT NOT NULL,
    profile TEXT NOT NULL CHECK(profile IN ('quality', 'balanced', 'budget')),
    model TEXT NOT NULL,
    variant TEXT,
    PRIMARY KEY (provider_mode, agent_or_scope, profile)
  );

  CREATE TABLE IF NOT EXISTS provider_modes (
    name TEXT PRIMARY KEY,
    description TEXT NOT NULL DEFAULT '',
    is_builtin INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
  );
  ```

  b. In `openPilotDb()`, after the existing `db.exec(CREATE_PROJECTS_TABLE_SQL)` line, add `db.exec()` calls for both new table SQL constants.

  c. In `_getTestDb()`, similarly add `db.exec()` calls for both new table SQL constants (so tests get the tables too).

  d. Add a new function `seedModelTables(db)` that:
     - Checks if provider_modes table has any rows: `SELECT COUNT(*) as cnt FROM provider_modes`
     - If cnt > 0, return early (user data exists — preserve customizations)
     - If cnt === 0, seed both tables:
       - INSERT the 3 built-in provider modes: `claude-only` ("Anthropic Claude models only"), `openai-only` ("OpenAI models only"), `hybrid` ("Claude for build, Codex for check") — all with `is_builtin = 1`
       - Iterate `AGENT_MODELS` from `src/core/models.ts`: for each providerMode → agentOrScope → profile, INSERT into model_profiles with (provider_mode, agent_or_scope, profile, model, variant)
     - Import `AGENT_MODELS` from `./models.js` at the top of db.ts

  e. Call `seedModelTables(cachedDb!)` in `openPilotDb()` AFTER `migrateSchema()`.
  f. Call `seedModelTables(cachedDb!)` in `_getTestDb()` AFTER `migrateSchema()`.

  IMPORTANT: The seed function must be idempotent — only seeds when tables are empty. This ensures user customizations survive app upgrades.
  </action>

<task type="auto">
  <name>Task 2: Create model-store.ts CRUD module</name>
  <files>src/core/model-store.ts</files>
  <action>
  Create `src/core/model-store.ts` with these exports:

  1. `getModelEntry(providerMode: string, agentOrScope: string, profile: ModelProfile): ModelProfileRow | null`
     - SELECT from model_profiles WHERE provider_mode=? AND agent_or_scope=? AND profile=?
     - Returns null if not found

  2. `setModelEntry(providerMode: string, agentOrScope: string, profile: ModelProfile, model: string, variant?: string | null): void`
     - INSERT OR REPLACE into model_profiles
     - This is how `pilot models edit` will write changes

  3. `getAllEntriesForMode(providerMode: string): ModelProfileRow[]`
     - SELECT * FROM model_profiles WHERE provider_mode=?
     - ORDER BY agent_or_scope, profile
     - Used by `pilot models show` and `pilot models export`

  4. `getAllEntriesForModeAndProfile(providerMode: string, profile: ModelProfile): ModelProfileRow[]`
     - SELECT * FROM model_profiles WHERE provider_mode=? AND profile=?
     - ORDER BY agent_or_scope
     - Used by resolveAllAgentModels

  5. `getProviderModes(): ProviderModeRow[]`
     - SELECT * FROM provider_modes ORDER BY is_builtin DESC, name ASC (built-in first)

  6. `getProviderMode(name: string): ProviderModeRow | null`
     - SELECT from provider_modes WHERE name=?

  7. `addProviderMode(name: string, description: string, isBuiltin: boolean): void`
     - INSERT INTO provider_modes (name, description, is_builtin) VALUES (?, ?, ?)
     - Throws if name already exists (PRIMARY KEY constraint)

  8. `removeProviderMode(name: string): void`
     - DELETE FROM provider_modes WHERE name=? AND is_builtin=0
     - Also DELETE FROM model_profiles WHERE provider_mode=?
     - Throws if the mode is built-in (is_builtin=1) — check first with getProviderMode

  9. `resetProviderMode(providerMode: string): void`
     - DELETE all model_profiles rows for this provider_mode
     - Re-seed from AGENT_MODELS[providerMode] if it exists in the hardcoded constant
     - If providerMode is not in AGENT_MODELS (user-created), just delete (leaves empty)

  10. `resetAllToDefaults(): void`
      - DELETE all rows from model_profiles
      - DELETE all rows from provider_modes WHERE is_builtin=0 (keep built-in mode rows, delete custom)
      - Re-seed all built-in modes from AGENT_MODELS
      - Note: This re-inserts the 3 built-in provider_modes rows AND all 126 model_profiles rows

  11. `isCustomized(providerMode: string, agentOrScope: string, profile: ModelProfile): boolean`
      - Compare DB value to AGENT_MODELS[providerMode]?.[agentOrScope]?.[profile]
      - If AGENT_MODELS entry doesn't exist (custom provider), always returns true
      - If model or variant differs, returns true
      - Used to highlight customized entries in `pilot models` display

  12. `cloneProviderMode(sourceName: string, targetName: string): void`
      - Copy all model_profiles rows from source to target (change provider_mode column)
      - Used by `pilot models add-provider` when cloning from existing

  All functions should import `getDb` from `./db.js`. Follow the synchronous pattern used throughout the codebase (better-sqlite3 is sync).

  Import types: `ModelProfile` from `./types.js`, `ModelProfileRow` and `ProviderModeRow` from `./types.js`, `AGENT_MODELS` from `./models.js`.
  </action>
