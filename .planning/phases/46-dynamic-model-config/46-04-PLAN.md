  **Add these command handlers to `src/commands/models.ts`:**

  **1. `modelsAddProviderCommand(name: string, opts: { clone?: string; json?: boolean })`**
  - Validate name: must be lowercase alphanumeric + hyphens, 2-50 chars
  - Check if name already exists via `getProviderMode(name)` — error if so
  - If `--clone <existing>` flag: clone entries from existing mode via `cloneProviderMode(source, target)`
  - If no --clone: Interactive flow using readline:
    - For each of the 14 agent/scope keys (from AGENT_MODELS['claude-only'] keys as reference):
      - For each profile (quality, balanced, budget):
        - Prompt: `{agent} ({profile}): ` with default from claude-only mode

        - Parse variant from colon suffix if present
        - Call `setModelEntry(name, agent, profile, model, variant)`

  - Print: "Created provider mode '{name}' with {N} model entries."
  - `--json`: output `{ created: true, name, entries: N }`

  **2. `modelsRemoveProviderCommand(name: string, opts: { json?: boolean })`**
  - Check if mode exists and is NOT built-in
  - If built-in: error "Cannot remove built-in provider mode '{name}'. Only custom modes can be removed."
  - If not found: error "Provider mode '{name}' not found."
  - Call `removeProviderMode(name)` from model-store
  - Print: "Removed provider mode '{name}' and all its model entries."
  - `--json`: output `{ removed: true, name }`

  **3. `modelsDiffCommand(opts: { json?: boolean; providerMode?: string })`** (Nice to Have)

      ```

        Default: anthropic/claude-sonnet-4-6
        Current: anthropic/claude-opus-4-6
      ```
  - If no customizations: "No customizations found."
  - `--json`: output array of `{ mode, agent, profile, default: { model, variant }, current: { model, variant } }`

  **4. `modelsExportCommand(opts: { json?: boolean })`** (Nice to Have)
  - Export all model_profiles and provider_modes as JSON to stdout
  - Format:
    ```json
    {
      "version": 1,
      "provider_modes": [...],
      "model_profiles": [...]
    }
    ```
  - Always outputs JSON regardless of --json flag (it IS a JSON export)

  **5. `modelsImportCommand(file: string, opts: { json?: boolean })`** (Nice to Have)
  - Read JSON file from path
  - Validate structure: must have version, provider_modes, model_profiles arrays

  <name>Task 2: Make --provider flag accept custom mode names</name>
  <files>src/commands/add.ts</files>
  <action>
  Currently `pilot add --provider` validates against the hardcoded `ProviderMode` union ('hybrid' | 'claude-only' | 'openai-only'). Update to validate dynamically:

  1. Find the provider mode validation in `add.ts`. It likely checks against a hardcoded array or the type directly.

  2. Replace with dynamic validation:
     ```typescript
     import { getProviderModes } from '../core/model-store.js';

     // In the validation logic:
     if (opts.provider) {
       try {
         const validModes = getProviderModes().map(m => m.name);
         if (!validModes.includes(opts.provider)) {
           process.stderr.write(`Invalid provider mode: ${opts.provider}\n`);
           process.stderr.write(`Available modes: ${validModes.join(', ')}\n`);
           process.exit(2);
         }
       } catch {
         // DB unavailable — fall back to hardcoded validation
         const hardcoded = ['hybrid', 'claude-only', 'openai-only'];
         if (!hardcoded.includes(opts.provider)) {
           process.stderr.write(`Invalid provider mode: ${opts.provider}\n`);
           process.exit(2);
         }
       }
     }
     ```

  3. Also update the `--provider` option description in `src/index.ts` to reflect dynamic support:
     Change from listing the 3 modes to: `'Provider mode (run pilot models to see available modes)'`

  IMPORTANT: The `addJob()` function in db.ts accepts `providerMode?: ProviderMode`. Since ProviderMode is still the 3-member union, the add command should pass the provider string as-is (TypeScript will need a type assertion `as ProviderMode` for custom modes, or the addJob parameter type should be widened to `string`). Widen the `providerMode` parameter in `addJob` from `ProviderMode` to `string` since the DB column is TEXT with no CHECK constraint for provider_mode.
