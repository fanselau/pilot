<task type="auto">
  <name>Task 1: Make ProviderMode a validated string type</name>
  <files>src/core/types.ts</files>
  <action>
  The requirements say: "The ProviderMode type in src/core/types.ts will need to become dynamic (string union → validated string)."

  However, changing ProviderMode from `'hybrid' | 'claude-only' | 'openai-only'` to `string` would break type safety everywhere it's used (Job, ConfigFileSchema, ConfigFileDefaults, addJob params, etc.).

  **Approach:** Keep `ProviderMode` as the 3-member union for type-safe internal use. Add a new type alias:

  ```typescript
  /** ProviderMode including custom user-defined modes from provider_modes table. */
  export type DynamicProviderMode = string;
  ```

  This is used by:
  - `resolveAgentModel`, `resolveAllAgentModels`, `resolveTopLevelModel` — accept `DynamicProviderMode` for the providerMode parameter
  - The `pilot models` CLI commands
  - The `--provider` flag validation (needs to accept custom names)

  Also update the `ConfigFileSchema.defaults.providerMode` type to `string` (so config file can reference custom modes). Leave `ProviderMode` union intact for the hardcoded AGENT_MODELS type and Job type.

  In `src/core/config.ts`, update `validateConfigFile()`: instead of checking `providerMode` against the 3 hardcoded values, use `getProviderModes()` from model-store to validate dynamically. Import `getProviderModes` lazily (try/catch) so config validation doesn't hard-fail if DB is unavailable during early startup.
  </action>
  <verify>
  - `npm run build` passes
  - Existing code that uses `ProviderMode` type still compiles
  </verify>
  <done>
  - DynamicProviderMode type exported from types.ts
  - ConfigFileSchema.defaults.providerMode accepts string
  - Config validation checks against DB provider_modes (with fallback)
  </done>
</task>

<task type="auto">
  <name>Task 2: Rewire resolve functions to read from DB</name>
  <files>src/core/models.ts</files>
  <action>
  Update the three resolve functions in `src/core/models.ts` to read from the model-store DB module, falling back to AGENT_MODELS if DB read fails.

  **Pattern for each function:** Try DB first → catch → fall back to hardcoded constant.

  1. `resolveAgentModel(agentName, profile, providerMode)`:
     ```typescript
     try {
       const row = getModelEntry(providerMode, agentName, profile);
       if (row) return { model: row.model, variant: row.variant ?? undefined };
     } catch {
       // DB unavailable — fall through to hardcoded
     }
     // Fallback to AGENT_MODELS
     const providerTable = AGENT_MODELS[providerMode as ProviderMode];
     // ... existing logic ...
     ```
     Note: For custom provider modes not in AGENT_MODELS, if DB read fails there is NO fallback — throw an error.

  2. `resolveAllAgentModels(profile, providerMode)`:
     ```typescript
     try {
       const rows = getAllEntriesForModeAndProfile(providerMode, profile);
       if (rows.length > 0) {
         const models: Record<string, ModelEntry> = {};
         for (const row of rows) {
           if (row.agent_or_scope.startsWith('_top:')) continue; // Skip scope entries
           models[row.agent_or_scope] = { model: row.model, variant: row.variant ?? undefined };
         }
         return models;
       }
     } catch {
       // DB unavailable — fall through to hardcoded
     }
     // Fallback to AGENT_MODELS (existing code)
     ```

  3. `resolveTopLevelModel(scope, profile, providerMode)`:
     ```typescript
     const key = scope === 'milestone' ? '_top:phase' : `_top:${scope}`;
     try {
       const row = getModelEntry(providerMode, key, profile);
       if (row) return { model: row.model, variant: row.variant ?? undefined };
     } catch {
       // DB unavailable — fall through to hardcoded
     }
     // Fallback to AGENT_MODELS (existing code)
     ```

  Import at top of models.ts:
  ```typescript
  import { getModelEntry, getAllEntriesForModeAndProfile } from './model-store.js';
  ```

  **IMPORTANT:** The function signatures change to accept `string` (DynamicProviderMode) instead of `ProviderMode` for the providerMode parameter. Update the type annotations:
  - `resolveAgentModel(agentName: string, profile: ModelProfile, providerMode: string): ModelEntry`
  - `resolveAllAgentModels(profile: ModelProfile, providerMode: string): Record<string, ModelEntry>`
  - `resolveTopLevelModel(scope: ..., profile: ModelProfile, providerMode: string): ModelEntry`

  **Keep AGENT_MODELS exported** — it remains as seed data and fallback. Do NOT delete it.
  **Keep patchAgentFrontmatter unchanged** — it consumes `Record<string, ModelEntry>`, doesn't care about source.
  </action>
