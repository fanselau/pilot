Add the following TypeScript interfaces at the end of types.ts (after the existing PilotStatusJson interface). These are the concrete compact DTO shapes required by the spec:

**JobDetailSnapshot** — root return type of `getJobDetail()`:
```typescript
interface JobDetailSnapshot {
  job: {
    id: string;
    project: string;
    description: string;
    scope: JobScope;
    status: JobStatus;
    verdict: string | null;       // from judgeVerdict
    confidence: number | null;    // from judgeVerdict
    createdAt: string;
    startedAt: string | null;
    completedAt: string | null;
    durationMs: number | null;
    currentStep: number;
    modelProfile: ModelProfile;
    providerMode: string;
    error: string | null;
  };
  steps: JobStepSummary[];
  rootSessions: SessionSummary[];
  subagents: SessionSummary[];
  activityPreview: ActivityPreviewItem[];
  cursor: string;                 // opaque cursor for getJobDetailEvents
}
```

**JobStepSummary** — compact step timeline entry:
```typescript
interface JobStepSummary {
  stepIndex: number;
  command: string;
  args: string;
  status: string;
  sessionId: string | null;
  durationMs: number | null;
  verdictReason: string | null;
}
```

**SessionSummary** — compact session card (used for root sessions AND subagent cards):
```typescript
interface SessionSummary {
  sessionId: string;
  title: string;
  role: 'root' | 'subagent';
  status: 'active' | 'done' | 'unknown';
  parentSessionId: string | null;
  startedAt: number;            // epoch ms
  updatedAt: number;            // epoch ms
  durationMs: number | null;
  latestMessagePreview: string | null;  // first ~200 chars of last assistant message
  messageCount: number;
  childCount: number;
  tokenTotal: number;
  models: string[];
}
```

**ActivityPreviewItem** — compact activity snippet for the main scroll pane:
```typescript
interface ActivityPreviewItem {
  sessionId: string;
  partId: string;
  type: 'text' | 'tool' | 'patch';
  role: string;
  createdAt: number;
  preview: string;               // truncated to ~300 chars
  tool?: string;
  toolInput?: string;
}
```

**SessionActivityPage** — paginated session activity:
```typescript
interface SessionActivityPage {
  parts: SessionPart[];          // reuse existing SessionPart type
  hasMore: boolean;
  nextCursor: string | null;
}
```

**SessionActivityOptions** — options for getSessionActivity:
```typescript
interface SessionActivityOptions {
  cursor?: string;               // opaque pagination cursor (epoch ms as string)
  limit?: number;                // default 50
  includeToolDetails?: boolean;  // default false — exclude toolInput/toolOutput for compact view
}
```

**JobDetailEvent** — incremental update delta:
```typescript
interface JobDetailEvent {
  type: 'job-update' | 'step-update' | 'session-update' | 'activity-new';
  timestamp: number;
  data: Record<string, unknown>;  // varies by type
}
```

**JobDetailEventsResponse** — return of getJobDetailEvents:
```typescript
interface JobDetailEventsResponse {
  events: JobDetailEvent[];
  cursor: string;
}
```

<task type="auto">
  <name>Task 2: Implement the 5 query functions in job-detail-query.ts</name>
  <files>src/core/job-detail-query.ts</files>
  <action>
Create `src/core/job-detail-query.ts` — a pure core module with no UI dependencies. Import from existing core modules:
- `db.ts` for job/step queries (getJobById, getJobSteps)
- `opencode-db.ts` for session queries (getSessionParts, getChildSessions, getSessionTokens, getLastMessage, findSessionByTitle, etc.)
- `job-observability.ts` for token/model aggregation
- `types.ts` for DTO types

**Function 1: `getJobDetail(jobId: string): JobDetailSnapshot | null`**
- Load job from pilot.db via getJobById
- Load job_steps via getJobSteps
- Parse sessionTitles from job to find root session IDs (via findSessionByTitle)
- For each root session: build SessionSummary via summarizeSession
- For each root session: get immediate children via getChildSessions → build subagent SessionSummary cards
- Build activityPreview: take the most recent ~10 parts from the first root session (using getSessionParts), map to ActivityPreviewItem with truncated preview text (300 chars)
- Parse judgeVerdict JSON for verdict/confidence
- Compute cursor as `String(Date.now())`
- Return null if job not found

**Function 2: `summarizeSession(sessionId: string): SessionSummary`**
- Get child sessions count via getChildSessions().length
- Get last message via getLastMessage → truncate to 200 chars for latestMessagePreview
- Get token totals via getSessionTokensRecursive
- Get models via getSessionModelsRecursive
- Determine status: check isSessionDone() → 'done', else 'active'
- Get message count via getAssistantMessageCount
- Look up session metadata (title, timestamps) by querying opencode DB session table directly

Note: For root sessions, role='root'. For children, role='subagent'. The caller specifies which.

**Function 3: `getSessionActivity(sessionId: string, options?: SessionActivityOptions): SessionActivityPage`**
- Call getSessionParts with optional `since` based on cursor (parse cursor as epoch ms)
- Apply limit (default 50)
- If `includeToolDetails` is false (default), strip toolInput/toolOutput from returned parts
- Return { parts, hasMore: parts.length === limit, nextCursor }
- nextCursor is the createdAt of the last part as a string

**Function 4: `getSessionChildren(sessionId: string): SessionSummary[]`**
- Call getChildSessions(sessionId) for immediate children only
- Map each child through summarizeSession with role='subagent'
- Return array

**Function 5: `getJobDetailEvents(jobId: string, sinceCursor: string): JobDetailEventsResponse`**
- Parse sinceCursor as epoch ms timestamp
- Reload job from DB → if status/step/verdict changed since cursor, emit 'job-update' event
- Reload steps → if any step changed, emit 'step-update' events
- Get new activity parts (since cursor) from root sessions → emit 'activity-new' events
- Compute new cursor = Date.now()
- Return compact deltas only, NOT full job re-serialization

Implementation notes:
- Keep this module synchronous where possible (better-sqlite3 is sync)
- For session lookups that may fail (DB unavailable), gracefully degrade with empty arrays/nulls
- Use existing truncateNullable from util/format.ts for text truncation
- The cursor is intentionally opaque to clients (just a timestamp string) for future flexibility
- Do NOT recursively inline sub-agent transcripts — this is the key design difference from TUI

Helper needed: A small `getSessionInfo(sessionId)` query that reads the session table for title, time_created, time_updated. Add this to opencode-db.ts or inline it.

Export all 5 functions.
