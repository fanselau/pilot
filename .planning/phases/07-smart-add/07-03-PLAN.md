**`parseRequirementsFile(content: string): { itemCount: number; hasPhaseHeaders: boolean }`**
- Count lines matching `/^\s*- \[ \]/` regex (unchecked checkbox items)
- Detect phase headers: lines matching `/^#{1,3}\s+Phase\s+\d+/i`
- Count `### Must Have` or `## Must Have` sections (case-insensitive match on `/^#{2,3}\s+Must Have/i`). If 2+ such sections → `hasPhaseHeaders = true` (multiple must-have sections indicate milestone-level scope)
- Return `{ itemCount, hasPhaseHeaders }`

**`detectScope(opts: { content: string | null; description: string | null; isDirectory: boolean }): ScopeDetectionResult`**
- If `isDirectory` is true → milestone. Rationale: "Directory of requirements files detected"
- If `content` is provided:
  - Parse with `parseRequirementsFile(content)`
  - If `itemCount >= 10 && hasPhaseHeaders` → milestone. Rationale: `"${itemCount} requirement items with phase/section headers"`
  - If `itemCount >= 3` → phase. Rationale: `"${itemCount} requirement items (focused feature)"`
  - If `itemCount < 3` → quick. Rationale: `"${itemCount} items (small task)"`
- If no content and description is provided → quick. Rationale: "String description (no requirements file)"
- If neither → quick. Rationale: "No input provided, defaulting to quick"
- Return `{ scope, itemCount, hasPhaseHeaders, isDirectory, rationale }`

**`generateRequirementsContent(description: string): string`**
- Title-case first significant words for heading (capitalize first letter of each word, up to ~6 words)
- Generate minimal valid requirements markdown:
```
# {Title}

## Problem
{description}

## Requirements
### Must Have
- [ ] {description}

## Do NOT
- Break existing functionality
```

**`detectProjectState(project: string, config: PilotConfig): Promise<ProjectStateResult>`**

1. Build `projectDir = path.join(config.projectDir, project)`
2. Check projectDir exists via `access()`. If not → return early with `exists: false`, all other fields false/null
3. Check `.opencode/` exists via `access(path.join(projectDir, '.opencode'))`
4. Check `.planning/` exists via `access(path.join(projectDir, '.planning'))`
5. If `.planning/` exists: call `detectPlanningState(path.join(projectDir, '.planning'))` from `projects.ts`
   - If result.state === 'complete' → `allPhasesDone = true`
   - If result.state === 'active' → `phasesIncomplete = true`
6. For queue status: call `parseQueueFile(config.queueFile)` from `queue-parser.ts` (wrapped in try/catch — queue file may not exist)
   - Filter entries where `entry.project === project`
   - If any entry has `status === 'pending'` → `isQueued = true`, `queuedMode = entry.mode`
   - If any entry has `status === 'running'` → `isRunning = true`, `runningPhase = entry.args || null`
7. `needsSetup = exists && !hasOpencode`
8. `needsInit = exists && hasOpencode && !hasPlanning`
9. Return the full `ProjectStateResult`

**`resolveInternalMode(scope: SmartAddScope, projectState: ProjectStateResult): string`**
- If `!projectState.exists` → 'build-full'
- If `scope === 'quick'` → 'quick'
- If `scope === 'milestone'`:
  - If `!projectState.hasPlanning` → 'build-full'
  - If `projectState.allPhasesDone` → 'build-full' (new milestone)
  - If `projectState.phasesIncomplete` → 'continue-all'
  - Fallback → 'build-full'
- If `scope === 'phase'`:
  - If `!projectState.hasPlanning` → 'build-full'
  - Otherwise → 'add-and-build'
- Fallback → 'build-full'

Export all 5 functions as named exports.
