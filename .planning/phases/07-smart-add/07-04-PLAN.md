**Completely rewrite `src/commands/add.ts`** — replace the old mode-based command.

New signature: `addCommand(project: string, input: string, opts: Record<string, unknown>): Promise<AddResult>`

Define `AddResult` interface in this file:
```typescript
export interface AddResult {
  project: string;
  scope: SmartAddScope;
  internalMode: string;
  description: string;
  requirementsPath: string | null;
  dryRun: boolean;
}
```

Where `input` is either:
- A file path (e.g., `requirements/dark-mode.md`) — detected by checking if file exists via `stat()`
- A directory path (e.g., `requirements/v2/`) — detected by checking if directory exists via `stat()`
- A string description (e.g., `"fix the favicon"`) — fallback if neither file nor dir

**Implementation flow (14 steps):**

1. Get config. Build projectDir = `path.join(config.projectDir, project)`.

2. Determine input type: try `stat(path.resolve(input))`.
   - If `isDirectory()` → set `isDirectory=true`, `requirementsPath=inputPath`. Count `.md` files in dir for description.
   - If `isFile()` → read content, set `requirementsPath=inputPath`. Extract first heading as description, fallback to filename.
   - If `stat()` throws → treat as string description (`content=null`, `requirementsPath=null`, `description=input`).

3. Check for `--as` scope override: validate against `['quick', 'phase', 'milestone']`. If invalid, `process.stderr.write` + `process.exit(2)`.

4. Detect scope: if override exists, build `ScopeDetectionResult` manually with override. Otherwise call `detectScope({ content, description, isDirectory })`.

5. Detect project state: `await detectProjectState(project, config)`.

6. Handle missing project directory: if `!projectState.exists` → `process.stderr.write` error + `process.exit(1)`.

7. Auto-setup if `projectState.needsSetup`: call `setupProject(projectDir)` silently (just print dim arrow in non-JSON mode).

8. Warn if already queued/running (non-JSON mode only):
   - `projectState.isQueued` → yellow warning with queuedMode
   - `projectState.isRunning` → yellow warning with runningPhase

9. Handle requirements file: if `requirementsPath` exists and is NOT a directory, and source is outside projectDir → copy to `<projectDir>/requirements/<basename>`.

10. Handle string description for non-quick scopes: generate requirements file via `generateRequirementsContent(description)`, write to `<projectDir>/requirements/<safe-slug>.md`.

11. Resolve internal mode: `resolveInternalMode(scopeResult.scope, projectState)`.

12. Log the scope detection decision in non-JSON mode: `dim('→') Detected: ${scope} (${rationale})`.

13. Dry-run check: if `opts['dryRun'] === true`:
    - JSON mode: `outputJson({ action: 'dry-run', project, scope, internalMode, description, ... })`
    - Human mode: print what would be queued
    - Return `{ project, scope, internalMode, description, requirementsPath, dryRun: true }`

14. **Write to QUEUE.md** (NOT queue-store.ts):
```typescript
const argsStr = description || '';
const entryLine = argsStr.length > 0
  ? `## ${project} | ${internalMode} | ${argsStr}`
  : `## ${project} | ${internalMode}`;

await withQueueLock(async () => {
  const content = await readFile(config.queueFile, 'utf8').catch(() => '');
  const newContent = content.trimEnd() + '\n\n' + entryLine + '\n';
  await writeFile(config.queueFile, newContent);
});
```

15. Output result:
    - JSON mode: defer to caller (index.ts action handler or buildCommand)
    - Human mode: `✓ Queued: ${project} | ${scope} → ${internalMode}` + requirements path + "Run \`pilot run\` to start building"

16. Return `AddResult`.

**Key design notes:**
- `addCommand` returns `AddResult` so `buildCommand` can compose JSON output with runner status
- Queue writes use `withQueueLock` + `readFile`/`writeFile` on `config.queueFile` — identical pattern to current add.ts
- NO import of `queue-store.ts` — it doesn't exist
- The `VALID_MODES` array is completely removed — modes are internal details set by `resolveInternalMode`

**Rewrite `src/commands/build.ts`** — becomes `add + run` convenience:

```typescript
/**
 * pilot build <project> <requirement-or-description> — Smart add + run.
 * Convenience: calls addCommand then starts runner if not active.
 */

import { execa } from 'execa';
import { readPidFile, isProcessAlive } from '../core/process.js';
import { isJsonMode, outputJson, outputHuman } from '../util/output.js';
import { addCommand } from './add.js';

export async function buildCommand(
  project: string,
  input: string | undefined,
  opts: Record<string, unknown>,
): Promise<void> {
  if (!input) {
    process.stderr.write('Error: Provide a requirements file or description\n');
    process.exit(2);
  }

  // Run smart add (queues the work)
  const addResult = await addCommand(project, input, opts);

  // Unless --no-run, check if runner is active and start if not
  const shouldRun = opts['run'] !== false;
  let runnerStarted = false;

  if (shouldRun && !addResult.dryRun) {
    const runnerPid = await readPidFile('queue');
    const runnerAlive = runnerPid !== null && isProcessAlive(runnerPid);

    if (runnerAlive) {
      if (!isJsonMode()) {
        outputHuman(`Runner already active (PID ${runnerPid})`);
      }
    } else {
      try {
        const pilotBin = process.argv[1]!;
        const child = execa('node', [pilotBin, 'run'], {
          detached: true,
          stdin: 'ignore',
          stdout: 'ignore',
          stderr: 'ignore',
        });
        child.unref();
        runnerStarted = true;
        if (!isJsonMode()) {
          outputHuman('✓ Runner started');
        }
      } catch (err) {
        if (!isJsonMode()) {
          outputHuman(`Warning: Failed to start runner: ${err instanceof Error ? err.message : String(err)}`);
        }
      }
    }
  }

  if (isJsonMode()) {
    outputJson({
      action: addResult.dryRun ? 'dry-run' : 'build',
      ...addResult,
      runner_started: runnerStarted,
    });
  }
}
```
