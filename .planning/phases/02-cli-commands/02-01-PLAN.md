<task type="auto">
  <name>Task 2: Status, queue, stuck, and config commands</name>
  <files>src/commands/status.ts, src/commands/queue.ts, src/commands/stuck.ts, src/commands/config.ts</files>
  <action>
Create 4 command files in `src/commands/`. Each follows the same pattern: import from core/, import from util/, check `isJsonMode()`, output JSON via `outputJson()` or human via `outputHuman()`.

**src/commands/status.ts** — `export async function statusCommand(opts)`
1. Call `listSessions()` from core/sessions.ts
2. Call `scanPidFiles()` from core/process.ts — get live PID entries
3. Cross-reference: a session is "running" if its title matches a PID entry's session name (match on session name from PID file). Cross-reference by checking if any PID session name appears in any session title (contains match, case-insensitive).
4. Call `parseQueueFile(config.queueFile)` — count pending entries
5. For each PID entry, call `computeStuckScore(pid, session)` from core/stuck.ts. Classify: stuck (score >= 70), suspect (40-69), healthy (< 40).
6. Get completed sessions: sessions NOT matched to PIDs, sorted by `.updated` desc, take first 5.
7. Check runner status: try `readPidFile('queue')` and `isProcessAlive()` for the queue runner PID.

**JSON mode:** Output full `PilotStatusJson` schema from types.ts. Map QueueEntry to QueueItem (rename lineNum → line_num, add empty description if missing).

**Human mode (compact):**
```
📊 Pilot Status
────────────────────────────────────────────────────────

3 running  0 stuck  2 queued

Running
  ● session-title-1
  ● session-title-2

Queued
  ○ project-name
  ... and N more

Recently Completed
  ✓ session-title (done)
```
Use colors: green for running count, red for stuck count, yellow for queued count. Green for `●`, dim for `○`, green for `✓`.

**Verbose mode:** When `opts.verbose`, show cli-table3 table with PID, SESSION, RUNTIME, LOG IDLE, SCORE columns for running sessions. Import `Table` from `cli-table3`.

**src/commands/queue.ts** — `export async function queueCommand(opts)`
1. Call `parseQueueFile(config.queueFile)` — handle ENOENT → exit 1 with `Error: Queue file not found: <path>`
2. Group entries by status: running → pending → done → failed
3. **JSON mode:** `outputJson({ queue: entries.map(toQueueItem), active_count })`
4. **Human mode:** Match spec format exactly. Header shows path. Group sections with icons: `⟳` running, `○` queued, `✓` done, `✗` failed. Each entry: `  ⟳ project: mode | args` (args omitted if empty). Footer: `N active item(s)` (active = running + pending).

**src/commands/stuck.ts** — `export async function stuckCommand(opts)`
1. Call `scanPidFiles()` — get all PID entries
2. For each, call `computeStuckScore(pid, session)` from core/stuck.ts
3. Separate into stuck (score >= 70) and suspect (40-69)
4. **JSON mode:** `outputJson({ threshold_minutes, stuck: [...], suspect: [...] })`
5. **Human mode:** Header line with threshold. Table with PID, SESSION (truncated to 25 chars with `…`), RUNTIME (formatDuration), LOG IDLE (formatDuration of log_staleness_seconds), SCORE. Use colors: red for stuck scores, yellow for suspect. Separate "Suspect (monitoring)" section below.
6. **--kill mode:** If `opts.kill`, filter to stuck only. If not `opts.force` and stdin is TTY (`process.stdin.isTTY`): prompt "Kill N stuck process(es)? [y/N]" using readline. If not TTY and not force: exit 1 with error. For each stuck PID: `process.kill(pid, 'SIGTERM')`, then `removePidFile(session)`. Report what was killed.

**src/commands/config.ts** — `export async function configCommand(opts)`
1. Call `getConfig()` from core/config.ts
2. Check if `claude` binary exists: use `execa('which', ['claude'])` in try/catch, or check `~/.claude/bin/claude` exists
3. **JSON mode:** `outputJson({ config: { PILOT_QUEUE_FILE: config.queueFile, ... }, claude_binary: { found, path } })`
4. **Human mode:** Match spec format. Two-column layout with env var name (padded to 22 chars) and value. Show `(minutes)` after stuck threshold. Show `(not set)` for NO_COLOR if unset. Show claude binary path with `(found)` or `(not found)`.
