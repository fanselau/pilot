  <files>src/commands/log.ts, src/commands/tail.ts</files>
  <action>
**src/commands/log.ts** — `export async function logCommand(session: string, opts)`

1. Call `findSession(session)` from core/sessions.ts. If null → `process.stderr.write('Error: Session not found: ' + session + '\n'); process.exit(1);`
2. Call `exportSession(found.id)` — wrap in try/catch, on failure → exit 1 with `Failed to export session: <id>`
3. **JSON mode:** `outputJson({ session: found, export: exported })`
4. **Human mode:** Format transcript matching the spec:
   - Header: `{session.title} — Session Log` + separator line `────...`
   - Parse exported data: expect `{ messages: [...] }` where each message has `role` and `content` fields. Also look for `tool_calls` or `tool_use` entries.
   - User messages: `╔ User ════...╗` header in cyan, then content
   - Assistant messages: `╔ Assistant ════...╗` header in green, then content
   - Tool use: dim text `  [{tool_name}] {status}` (e.g., `[Read] completed`, `[Write] completed`)
   - Handle the case where exported format has `type: 'human'` or `type: 'assistant'` instead of `role`
   - Truncate very long message content to first 500 chars with `... (truncated)` in verbose=false mode

**src/commands/tail.ts** — `export async function tailCommand(session: string, opts)`

1. Resolve log file path: `path.join(config.logDir, 'gsd-' + session + '.log')`
2. Check file exists using `fs.access()`. If not → `process.stderr.write('Error: Log file not found: ' + logPath + '\n'); process.exit(1);`
3. Implement native file following using `fs.watch` + `fs.createReadStream`:
   - Track current file position (start at end of file: use `fs.stat()` to get initial size)
   - On 'change' event from `fs.watch()`, create a read stream from the tracked position, pipe new bytes to stdout
   - Update position after each read
   - Do NOT use `tail -f` child process — implement natively per spec
4. Handle Ctrl-C: register `process.on('SIGINT', ...)` that prints `\nStopped following: ${session}` and calls `watcher.close()` then `process.exit(0)`
5. Print initial message: `Following: ${logPath}` (suppressed in json mode but tail doesn't have json mode per spec)
  </action>

`tsc --noEmit` passes for both files.
`npx tsx src/index.ts log nonexistent-session 2>&1; echo $?` — exit code 1, error message.
`npx tsx src/index.ts tail nonexistent-session 2>&1; echo $?` — exit code 1, error message.
  </verify>
  <done>
`pilot log <session>` finds session via fuzzy match, exports and formats transcript with user/assistant/tool-use styling. `pilot tail <session>` follows log file in real-time via fs.watch, exits cleanly on Ctrl-C. Both handle missing session/file with exit 1.
  </done>

  <files>src/commands/projects.ts, src/commands/progress.ts</files>
  <action>
**src/commands/projects.ts** — `export async function projectsCommand(opts)`

1. Call `scanProjects()` from core/projects.ts
2. **JSON mode:** `outputJson({ projects: projectInfos })`
3. **Human mode:** Match spec format using cli-table3:
   - Header: `Projects (${config.projectDir})` + separator
   - Table with columns: PROJECT (20 chars), BRANCH (10), GIT (5), STATE (15), PROGRESS
   - Import `Table` from `cli-table3` with `{ chars: { ... } }` configured for borderless/minimal style (no borders — set all chars to empty string or spaces). Use column widths and alignment.
   - For each ProjectInfo:
     - PROJECT: `project.name` (truncated to 20 chars)
     - BRANCH: `project.branch` (truncated to 10)
     - GIT: `project.gitState` — color green if 'clean', yellow if 'dirty'
     - STATE: Format from planningState + currentPhase + currentPhaseState. E.g., `Phase 3 exec`, `complete`, `no planning`
     - PROGRESS: `formatProgressBar(project.progress)` + ` ${project.progress}%`
   - If no projects found: `outputHuman('No projects found')`

**src/commands/progress.ts** — `export async function progressCommand(project: string | undefined, opts)`

1. Resolve project path:
   - If `project` arg given: `path.join(config.projectDir, project)`
   - If no arg: detect from cwd — check if `.planning/` exists in cwd or parent. If not found → exit 1: `Error: No project specified and no .planning/ found in current directory`
2. Call `getProgress(projectPath)` from core/progress.ts
3. **JSON mode:** `outputJson({ progress: progressInfo })`
4. **Human mode:** Match spec format:
   - Header: `{project} — Progress` + separator
   - Overall: `Overall: ${formatProgressBar(overall, 10)} ${overall}% (${doneCount}/${totalCount} phases)`
   - Empty line
   - Phase table (NOT cli-table3 — simple formatted text for alignment):
     ```
     Phase  Status     Description
       1    ✅ done     Project setup
       2    ✅ done     Core engine  
       3    🔨 exec     AI generation
       4    ○ pending   Payment
     ```
     - Status icons: `✅ done` for done, `🔨 {state}` for in-progress (use currentPhaseState if available, else `exec`), `○ pending` for pending
   - Footer lines: `Current: Phase N — {state}`, `Next action: {nextAction}`, `Blockers: {blockers.length > 0 ? blockers.join(', ') : 'none'}`
  </action>
