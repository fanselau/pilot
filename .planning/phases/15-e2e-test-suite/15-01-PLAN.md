  <name>Task 1: E2E test harness + mock opencode binary</name>
  <files>test/e2e/helpers.ts, test/e2e/fixtures/mock-opencode.sh</files>
  <action>
Create the E2E test infrastructure:

**test/e2e/fixtures/mock-opencode.sh** — A trivial shell script:
```bash
#!/bin/bash
# Mock opencode binary for E2E tests
# Accepts any args, writes them to stdout, exits 0
echo "mock-opencode: $*"
exit 0
```
Make it executable (chmod +x in test setup).

**test/e2e/helpers.ts** — Export these utilities:

1. `runPilot(args: string[], env?: Record<string, string>): Promise<{stdout, stderr, exitCode}>` — Runs `node dist/index.js ...args` via execa with `reject: false`. Merges provided env with defaults. Sets `PATH` to include the mock-opencode fixture dir (so `opencode` resolves to the mock). Always sets `NO_COLOR=1` to strip ANSI.

2. `createTempEnv(): Promise<TempEnv>` — Creates a temp directory via `fs.mkdtemp(os.tmpdir() + '/pilot-e2e-')`. Inside it creates:
   - `projects/` (for PILOT_PROJECT_DIR)
   - `logs/` (for PILOT_LOG_DIR)
   - `home/.pilot/` (for queue.json location)
   - `gsd/commands/`, `gsd/agents/`, `gsd/get-shit-done/` (for PILOT_GSD_DIR mock)
   - `bin/` dir with mock-opencode symlinked as `opencode`
   Returns a `TempEnv` object with `{ dir, projectDir, logDir, pilotDir, gsdDir, binDir, env }` where `env` is a Record with all PILOT_* vars set to these temp paths + PATH prepended with binDir.

3. `createFakeProject(env: TempEnv, name: string, opts?: { planning?: boolean, phases?: number[], git?: boolean }): Promise<string>` — Creates a project directory under `env.projectDir/name`. If `planning: true`, creates `.planning/STATE.md`, `ROADMAP.md`, `PROJECT.md` with stub content. If `phases` array provided, creates `.planning/phases/NN-phase/` dirs with plan+summary files. If `git: true` (default true), runs `git init -q`.

4. `createFakeQueue(env: TempEnv, items: Array<{project, description, status?}>): Promise<void>` — Writes a valid queue.json to `env.pilotDir/queue.json` with the given items as QueueJsonFile format (version 1, items array with shortIds, status defaults to 'queued').

5. `cleanupTempEnv(env: TempEnv): Promise<void>` — `rm -rf env.dir`. Call in afterEach/afterAll.

6. `TempEnv` type exported.

Use execa for running pilot. The binary path is `path.resolve(process.cwd(), 'dist/index.js')` — assumes tests run from project root after `npm run build`. Use `node` as the command with the dist/index.js as first arg (avoids shebang issues on some systems).

  </verify>

<task type="auto">
  <name>Task 2: E2E tests for all monitoring commands</name>
  <files>test/e2e/monitoring.test.ts</files>
  <action>
Create comprehensive E2E tests for all monitoring/read-only commands. Use `describe` blocks per command. Set vitest timeout to 30_000 per test.

**Setup:** Each describe block uses `beforeAll` to build the project (`npm run build`), `beforeEach` to create a fresh TempEnv, `afterEach` to clean up. The build can be a shared `beforeAll` at file level (run once).

**Test cases (each is an `it()`):**

**pilot status:**
- `pilot status` with empty state (no processes, no queue) — exits 0, output contains "0 running"
- `pilot status --json` — exits 0, output parses as JSON, has `timestamp`, `summary` object with running/stuck/queued/completed fields
- `pilot status --verbose` — exits 0 (no crash)

**pilot queue:**
- `pilot queue` with empty queue — exits 0, contains "empty" or "0"
- `pilot queue` with items — create 2 queued items via createFakeQueue, output shows project names
- `pilot queue --json` — parses as JSON, has `timestamp` and `queue` array
- `pilot queue --history` — exits 0

**pilot stuck:**
- `pilot stuck` with no PID files — exits 0, output mentions no stuck or threshold
- `pilot stuck --threshold 1` — exits 0 (custom threshold accepted)
- `pilot stuck --json` — parses as JSON

**pilot log:**
- `pilot log nonexistent` — exits 1 (session not found)
- Exit code 1 for missing session (stderr contains error)

**pilot projects:**
- `pilot projects` with 2 fake projects (one with .planning, one without) — exits 0, output contains both project names
- `pilot projects --json` — parses as JSON, has `timestamp` and `projects` array

**pilot progress:**
- `pilot progress fake-project` with a fake project that has .planning/ and phases — exits 0
- `pilot progress nonexistent` — exits 1

**pilot config:**
- `pilot config` — exits 0, output contains "PILOT_QUEUE_FILE" and "PILOT_LOG_DIR"
- `pilot config --json` — parses as JSON, has `timestamp`

**pilot version:**
- `pilot --version` — exits 0, output matches /\d+\.\d+\.\d+/

**pilot help:**
- `pilot --help` — exits 0, output contains "Monitoring" and "Setup" group headers
- `pilot status --help` — exits 0
- `pilot nonexistent-command` — exits non-zero (unknown command)

For JSON tests, parse with `JSON.parse(result.stdout)` and assert specific fields exist. Use relaxed assertions — don't assert exact counts since the temp env may have varying state, but do assert the structure is correct.
  </action>
