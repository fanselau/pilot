<task type="auto">
  <name>Task 2: Wire E2E tests into build system</name>
  <files>vitest.config.ts, package.json</files>
  <action>
**vitest.config.ts** — Update to exclude E2E tests from the default `vitest run`:

```typescript
import { defineConfig } from 'vitest/config';
export default defineConfig({
  test: {
    globals: true,
    include: ['test/**/*.test.{ts,tsx}'],
    exclude: ['test/e2e/**'],
  },
});
```

This keeps `npm test` and `npm run test:run` running only unit tests (fast). E2E runs separately.

**package.json** — Add these scripts:

- `"test:e2e": "vitest run --dir test/e2e --timeout 120000"` — runs all E2E tests with 2-minute timeout
- `"test:all": "vitest run && vitest run --dir test/e2e --timeout 120000"` — runs unit + E2E

This follows the requirements: "Run separately from unit tests: vitest run --dir test/e2e".

Note: The `--dir test/e2e` flag with vitest may require the E2E tests to match the global include pattern. Since `test/e2e/*.test.ts` already matches `test/**/*.test.{ts,tsx}`, the --dir flag just limits the scope. But we also exclude `test/e2e/**` from the default run. So:
- `npm run test:run` → unit tests only (exclude e2e)
- `npm run test:e2e` → e2e tests only (--dir scopes to e2e, and the exclude won't apply since we're using --dir)

Verify this works correctly. If vitest's --dir doesn't override the exclude, use a separate vitest config or use `vitest run --config vitest.e2e.config.ts` approach instead. In that case, create a minimal `vitest.e2e.config.ts`:

```typescript
import { defineConfig } from 'vitest/config';
export default defineConfig({
  test: {
    globals: true,
    include: ['test/e2e/**/*.test.ts'],
    testTimeout: 120_000,
  },
});
```

And change the script to: `"test:e2e": "vitest run --config vitest.e2e.config.ts"`.

Choose whichever approach works cleanly. The goal: `npm run test:run` is fast (unit only), `npm run test:e2e` runs E2E separately.
  </action>

Both complete without configuration errors.
