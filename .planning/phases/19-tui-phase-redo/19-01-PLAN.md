<task type="auto">
  <name>Task 2: Fix TUI import paths to use source files</name>
  <files>src/commands/tui.ts, src/index.ts</files>
  <action>
  1. In src/commands/tui.ts, change the dynamic import path from `'../tui/index.js'` to `'../tui/index.ts'`. Bun resolves .ts imports natively at runtime. This is the critical path — when `pilot tui` runs, bun loads `src/tui/index.ts` from source, which then loads `src/tui/app.tsx` etc. — all handled natively by bun without tsc.

  NOTE: The tui.ts file also does `const { plugin } = await import('bun')` and `const { default: solidPlugin } = await import('@opentui/solid/bun-plugin')` — leave these as-is, they're bun-specific and correct.

  2. In src/index.ts, the tui command registration (line ~178) does `await import('./commands/tui.js')`. This is fine — it imports the compiled `dist/commands/tui.js` which then at runtime does the dynamic import of source TUI files. No change needed here. But verify this import chain works.

  3. However, there's a subtlety: `dist/commands/tui.js` will contain `import('../tui/index.ts')`. When bun runs `dist/index.js`, it will resolve `../tui/index.ts` relative to `dist/commands/`. That path would be `dist/tui/index.ts` — which doesn't exist. 

  The fix: Change the import in src/commands/tui.ts to use an absolute or properly resolved path. Two approaches:
  
  **Approach A (recommended):** Use `import.meta.url` to resolve back to source:
  ```typescript
  const tuiPath = new URL('../../src/tui/index.ts', import.meta.url).pathname;
  const { startTui } = await import(tuiPath);
  ```

  **Approach B:** Use a path that works when running from either src/ or dist/:
  Since bun is the runtime and it resolves .ts natively, compute the path relative to the project root. The entry point knows it's at `dist/index.js` or `src/index.ts`, so use `path.resolve(__dirname, '..', 'src', 'tui', 'index.ts')`.

  Go with Approach A using import.meta.url — it's idiomatic ESM and works regardless of where the binary lives.

  4. Test the full chain:
     - `npm run build` (compiles non-TUI to dist/)
     - `bun dist/index.js tui` should attempt to launch TUI (may fail if no terminal/DB, but should NOT fail with "Cannot find module")

  If the import.meta.url approach causes issues with dynamic import (ESM dynamic imports need file:// URLs), use:
  ```typescript
  const tuiUrl = new URL('../../src/tui/index.ts', import.meta.url);
  const { startTui } = await import(tuiUrl.href);
  ```
  </action>

  - `bun dist/index.js status --json 2>&1 | head -3` still works (non-TUI command)
  </verify>
  <done>TUI command properly imports source .tsx files via bun at runtime. The import chain dist/index.js → dist/commands/tui.js → src/tui/index.ts → src/tui/app.tsx works.</done>
