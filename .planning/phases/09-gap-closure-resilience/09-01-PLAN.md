  <name>Gap Closure Execution Evidence Guard</name>
  <files>src/core/phase-state.ts, src/core/lifecycle.ts, src/core/postmortem.ts, src/core/types.ts, test/core/phase-state.test.ts</files>
  <behavior>
    Two new exported functions in phase-state.ts:

    1. `countSummaryFiles(phaseDir: string): Promise<number>`
       - Counts files matching `*-SUMMARY.md` in the phase directory
       - Excludes files containing "Status: Superseded" in their content (per requirements)
       - Returns 0 if directory doesn't exist or is empty

    2. `countNonGapPlanFiles(phaseDir: string): Promise<number>`
       - Counts PLAN.md files that do NOT have `gap_closure: true` in their frontmatter
       - These are the "original" plans that must have summaries before gap closure can work
       - Returns 0 if directory doesn't exist or is empty
       - Reads first 20 lines of each PLAN.md to check frontmatter for gap_closure field

    Guard logic in lifecycle.ts `runPhaseCycle` needs-gaps case (line 365):
    - Before entering gap closure, call `findPhaseDir` to get the phase directory
    - Call `countNonGapPlanFiles(phaseDir)` to get original plan count
    - Call `countSummaryFiles(phaseDir)` to get executed summary count
    - If summaryCount < originalPlanCount:
      - Log to stderr: `[lifecycle] Phase ${phase}: needs gap closure but only ${summaryCount}/${originalPlanCount} original plans have summaries. Skipping gap closure — running full execute.`
      - Write STATE to 'executing'
      - Run full `execute-phase ${phase} --auto` (NOT --gaps-only)
      - Write STATE to 'executed'
      - Continue loop (next iteration will re-verify)
    - If summaryCount >= originalPlanCount:
      - Proceed with existing gap closure logic (unchanged)

    PostmortemEntry update:
    - Add optional `gap_closure_attempts?: number` field to PostmortemEntry interface

    Cases:
    - Phase with 3 plans, 0 summaries, state=needs-gaps → runs full execute
    - Phase with 3 plans, 3 summaries, state=needs-gaps → enters gap closure
    - Phase with 3 plans, 2 summaries, state=needs-gaps → runs full execute (not all executed)
    - Phase with 3 plans + 2 gap plans, 3 summaries (original), state=needs-gaps → enters gap closure
    - Phase with superseded summary → not counted (content check)
    - countSummaryFiles on empty dir → 0
    - countNonGapPlanFiles on dir with only gap plans → 0
  </behavior>
