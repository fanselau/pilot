Create src/core/shell-exposure.ts with the following exports:

**Types:**
```typescript
interface ShellExposureFinding {
  tool: 'pilot' | 'node' | 'pnpm';
  status: 'pass' | 'created' | 'refreshed' | 'fail';
  stablePath: string;       // ~/.local/bin/<tool>
  resolvedTarget: string;   // where the symlink points
  detail: string;           // human-readable explanation
}

interface ShellExposureResult {
  findings: ShellExposureFinding[];
  fnmNote: string;  // explanation that fnm is not supported in plain shells
}
```

**ensureShellExposure(): Promise<ShellExposureResult>**

For each tool (pilot, node, pnpm):
1. Resolve the current canonical binary location:
   - **pilot:** Use the same resolution chain as resolvePilotBinary() in service.ts:
     - import.meta.url → package root dist/index.js
     - Then `which pilot` fallback
   - **node:** `which node` (will find fnm-managed node)
   - **pnpm:** `which pnpm` (will find corepack-managed pnpm)
2. Determine the stable target path: `~/.local/bin/<tool>`
3. Check if stable path already exists:
   - If it's a symlink pointing to the correct target → status: 'pass'
   - If it's a symlink pointing to a DIFFERENT target → unlink + re-create → status: 'refreshed'
   - If it doesn't exist → create symlink → status: 'created'
   - If it exists but is NOT a symlink (real file) → status: 'pass' (don't touch real files)
   - If the source binary can't be resolved → status: 'fail' with detail
4. For pilot specifically: use `realpathSync()` to resolve through any existing symlinks to the actual file, so the stable symlink points to the real binary, not to another symlink chain.
5. Set fnmNote to: "fnm is not exposed in plain shells — node and pnpm are the supported interface for non-interactive contexts."

Important: 
- Use `import { execSync } from 'node:child_process'` for `which` calls (same pattern as service.ts)
- Use `lstat` to check if target is a symlink vs real file (same pattern as setup.ts)
- Create ~/.local/bin directory if it doesn't exist (mkdir -p equivalent)
- Do NOT symlink fnm — it's explicitly out of scope
- Use `os.homedir()` for ~ resolution, not hardcoded paths

**verifyShellExposure(): Promise<ShellExposureResult>**

Read-only version — checks stable paths exist and resolve, but never creates/modifies symlinks. Same logic as ensureShellExposure but skips create/refresh steps.
- If stable path exists and resolves → 'pass'
- If stable path missing → 'fail' with "Not found — run: pilot setup --refresh"
- If stable path is broken symlink → 'fail' with "Broken symlink"
