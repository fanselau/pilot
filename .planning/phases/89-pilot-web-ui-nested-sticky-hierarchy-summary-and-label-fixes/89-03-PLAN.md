  <action>
**Goal: Make the Unattributed bucket empty for all well-formed jobs (like 82bg).**

The current 6-tier attribution system (in `resolveStepIndex`) leaves some sessions unattributed. The main causes:

1. **Post-judge continuation sessions** — after a judge step completes, the runner may spawn a continuation delegation. This session often falls outside the judge step's time window and isn't linked by sessionId. Fix: add a 7th tier that assigns orphan sessions occurring AFTER the last step's completion to that step (or to a synthesized "Continuation Delegation" step).

2. **Activity between steps** — brief gaps between step completedAt and next step startedAt can leave activity orphaned. Fix: expand step time windows to be contiguous (each step's window extends until the next step starts, not just until its own completedAt).

Read the existing `resolveStepIndex()` function carefully. Then make these specific changes:

**a) Make step time windows contiguous:**

In the step window resolution (tier 3), after sorting steps by startedAtMs, set each step's effective endMs to `Math.min(completedAtMs, nextStep.startedAtMs)` for completed steps, or `nextStep.startedAtMs` if completedAt is null. For the LAST step, extend endMs to `Infinity` so nothing falls through after it.

**b) Add delegation-after-judge fallback (tier 5.5):**

After the existing last-step-fallback (tier 5), add a new check: if the candidate session was created AFTER the last step's startedAt, and the last step is a judge step, attribute to the last step. This catches continuation sessions that spawn after judge completes.

**c) Make the Unattributed group render as the LAST group only if it has genuinely unattributable items:**

In the `getJobTimeline()` function, at the end where the unattributed group is assembled, add a log or metric for debugging. Ensure the unattributed bucket is only created when `unattributedItems.length > 0`, and the group renders at the end of the groups array.

**d) Update computeSemanticLabel for delegation steps from judge sources:**

This was done in Plan 01. Verify it's correct: `computeSemanticLabel('delegation', 'judge:gaps')` should return `'Continuation Delegation'`.
  </action>
