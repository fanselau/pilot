<task type="auto">
  <name>Task 1: Queue management actions in TUI</name>
  <files>src/tui/app.tsx, src/tui/components/queue-panel.tsx, src/tui/views/dashboard.tsx</files>
  <action>
  1. Add queue management keyboard handlers in app.tsx (Dashboard view only):

     **`a` — Add job:**
     - Show an inline input overlay (similar to FilterOverlay but for job creation)
     - Fields: project name, scope (quick/phase/milestone), description
     - On submit: call `addJob(project, scope, description)` from core/db.ts
     - On Esc: cancel
     - Implementation: create a simple `AddJobOverlay` component with an `<input>` element
     - Flow: `a` → show overlay → type project → Tab → type scope → Tab → type description → Enter → job added → overlay closes → queue refreshes on next poll

     **`r` — Retry:**
     - Only active when selected job is failed
     - Call `retry(job.id)` from core/db.ts
     - Show brief confirmation: flash the retried job in the queue

     **`x` — Cancel:**
     - Only active when selected job is pending or running
     - Show confirmation: "Cancel job #id? (y/n)"
     - On `y`: call `cancel(job.id)` from core/db.ts
     - On `n` or Esc: dismiss

     **`J`/`K` — Reorder:**
     - Only active in QueuePanel on pending jobs
     - `J` moves job down (decrease priority), `K` moves job up (increase priority)
     - Call `bump(job.id)` for moving to top, or implement a `setPriority` function
     - Since db.ts only has `bump` (moves to front), implement reorder as:
       - `K` (move up): bump the job to max priority + 1
       - `J` (move down): set priority to one less than the job below it
     - For simplicity in v1: `K` bumps to top of queue, `J` is a no-op or moves to bottom
     - Queue refreshes on next poll to reflect new order

     **`p` — Pause:**
     - Toggle a `paused` signal
     - When paused, show "PAUSED" in StatusBar in yellow
     - The TUI doesn't directly control the runner — "pause" here is informational
     - If runner integration exists in future, this would write a pause flag to pilot.db

  2. Add confirmation dialog pattern:
     - Create a lightweight inline confirmation: render a text prompt at the bottom of the screen
     - Wait for `y` or `n` keypress
     - Pattern:
       ```tsx
       <Show when={confirmAction()}>
         <box position="absolute" bottom={1} left={0}>
           <text content={`Cancel job #${confirmAction()!.id}? (y/n)`} fg={statusColors.failed} />
         </box>
       </Show>
       ```

  3. Update QueuePanel to show visual feedback:
     - When a job is retried: briefly flash green
     - When a job is cancelled: briefly flash red then disappear on next poll

  IMPORTANT: All mutations (addJob, cancel, retry, bump) are synchronous (better-sqlite3). They take effect immediately. The UI updates on the next poll cycle (1 second).
  </action>
  <verify>
  - `a` opens add job overlay, typing and Enter creates a job
  - `r` on a failed job retries it (status changes to pending on next poll)
  - `x` on a job shows confirmation, `y` cancels it
  - `K` bumps selected pending job to top of queue
  - `p` toggles PAUSED indicator in StatusBar
  </verify>
