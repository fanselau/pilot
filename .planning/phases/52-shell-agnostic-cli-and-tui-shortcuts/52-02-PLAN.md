  **Import `cancel`, `retry`, `getJob` from `../core/db.js`** at the top of the file alongside the existing `unblockProject`, `forceQuitJob` imports.

  **`r` — Retry failed/cancelled job:**
  ```typescript
  // r — retry failed/cancelled job
  if (key.sequence === 'r') {
    const job = state.selectedJob();
    if (job && (job.status === 'failed' || job.status === 'cancelled')) {
      try {
        retry(job.id);
        // Also unblock the project if it was blocked by this failure
        try { unblockProject(job.project); } catch { /* project may not be blocked */ }
        // Force immediate queue refresh
        const { pending, running } = fetchQueueData();
        const recent = fetchCompletedData();
        batch(() => {
          state.setQueue(pending);
          state.setRunning(running);
          state.setCompleted(recent);
        });
      } catch (err) {
        process.stderr.write(`[tui] retry error: ${String(err)}\n`);
      }
    }
    return;
  }
  ```

  **`x` — Cancel pending job:**
  ```typescript
  // x — cancel pending job
  if (key.sequence === 'x') {
    const job = state.selectedJob();
    if (job && job.status === 'pending') {
      try {
        cancel(job.id);
        // Force immediate queue refresh
        const { pending, running } = fetchQueueData();
        batch(() => {
          state.setQueue(pending);
          state.setRunning(running);
        });
      } catch (err) {
        process.stderr.write(`[tui] cancel error: ${String(err)}\n`);
      }
    }
    return;
  }
  ```

  **Important details:**
  - Both shortcuts work from any panel/view where `selectedJob()` returns a job (same as `K` force-quit).
  - They validate job status before acting (retry only on failed/cancelled, cancel only on pending) — matching the CLI behavior in `cancel.ts` and `retry.ts`.
  - `retry` also tries `unblockProject` because Phase 33 (managed projects) blocks projects on failure — retrying should unblock.
  - After mutation, immediately refresh the data signals so the UI updates without waiting for the next poll cycle.
  - `fetchQueueData` and `fetchCompletedData` are the existing data-fetching functions already used in the poll interval. Check the imports at the top of app.tsx — they're imported from the data layer.

  **Do NOT implement `a` (add) or `f` (follow mode):**
  - `a` (add) would need a full input form (project path, description) — far too complex for a keyboard shortcut. Remove from help overlay.
  - `f` (follow mode / log tailing in detail view) — would need new state signals and a streaming log mechanism. Out of scope for this phase. Remove from help overlay.
