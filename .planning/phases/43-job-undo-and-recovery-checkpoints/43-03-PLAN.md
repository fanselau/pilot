<task type="auto">
  <name>Task 2: Implement guarded undo pipeline with dry-run preview</name>
  <files>src/commands/undo.ts</files>
  <action>
Implement undo behavior as a strict safety pipeline:

1. Load job by ID and require recovery metadata availability.
2. Validate stored commits with `resolveCommitOrNull`; fail clearly if missing/unresolvable.
3. Determine whether the job produced commits (`gitBaseCommit !== gitHeadCommit`, with null-safe handling).
4. If no effective commit delta, return a "nothing to undo" outcome.
5. Resolve current repo head and relation vs checkpoint head using `classifyHeadRelation`.
6. Default refusal rules:
   - dirty worktree for destructive path
   - newer/diverged work after checkpoint head
   - dirty-start jobs (`startedDirty=true`)
7. `--force` behavior:
   - allow override for newer/diverged-work and dirty-start guards with explicit destructive warning text
   - keep dirty-worktree destructive refusal conservative unless explicitly implemented and documented
8. `--dry-run`:
   - print base/head/current relation
   - list changed files (`listChangedFiles`) and what would be reset
   - no git mutation
9. Non-dry-run execute path:
   - if already at base commit, return idempotent no-op success
   - otherwise run `git reset --hard <gitBaseCommit>`

If practical, add suggestion text when newer-work refusal occurs (e.g. undo newer same-project jobs first).

Do NOT add auto-stash, auto-commit, or hidden git rewrites.
  </action>
  <verify>npx vitest run test/commands/undo.test.ts</verify>
  <done>`pilot undo` supports dry-run preview, safe-path reset, and conservative default refusals with clear explanations.</done>
</task>
