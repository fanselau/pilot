<task type="auto">
  <name>Task 2: Enforce runner preflight safety and record base/head checkpoints</name>
  <files>src/core/runner.ts, test/core/runner-recovery.test.ts</files>
  <action>
Integrate checkpoint capture and clean-worktree safety into `Runner.launch(job)`:

- Before delegation/execution:
  - Verify target project is a git worktree; fail clearly if not.
  - Resolve `gitBaseCommit` (nullable for no-commit repos).
  - Check dirty state and call `updateJobRecoveryStart(job.id, gitBaseCommit, startedDirty)`.
  - If dirty and `job.allowDirtyStart` is false, refuse execution with explicit actionable message that includes:
    - "commit, stash, or discard your changes"
    - guidance to re-queue with `pilot add ... --force-dirty` only when intentionally accepting weaker recovery guarantees
  - If dirty and `job.allowDirtyStart` is true, emit a clear warning that recovery guarantees are weaker.
- After execution attempt (success and failure paths), capture current `gitHeadCommit` with `updateJobRecoveryHead` before terminal DB status updates.
- Keep behavior safe for repos with no commits (`gitBaseCommit`/`gitHeadCommit` can remain null).

Add `test/core/runner-recovery.test.ts` for key paths:
- default dirty refusal
- dirty allowed when `allowDirtyStart=true`
- base/head helper updates called at appropriate lifecycle points
- no-commit path does not crash
- refusal message assertions include commit/stash guidance and `--force-dirty` tradeoff language

Do not implement undo command behavior here; this plan only establishes execution metadata correctness.
