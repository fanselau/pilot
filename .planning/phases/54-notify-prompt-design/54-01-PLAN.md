  <name>Task 1: Rewrite buildDeliveryPrompt for explicit reply behavior</name>
  <files>src/core/callback.ts</files>
  <action>
Rewrite the `buildDeliveryPrompt()` function in `src/core/callback.ts` to produce a prompt that explicitly tells the target agent to respond with a useful update. The key behavioral changes:

1. **Opening instruction** — Replace the passive "Pilot job update:" header with an explicit action instruction. The prompt must open with something like:
   "A Pilot job just {completed/failed}. Reply in your target chat with a concise, natural-language update for the team."
   This primes the agent for action, not passive context absorption.

2. **Structured metadata block** — Keep all existing fields (job_id, project, description, status, duration, verdict, confidence, verdict_reason, error, next_step) as a clearly delimited data section. Use a label like "Job details:" followed by the key: value pairs. This gives the agent raw material to summarize.

3. **Reply guidance** — Replace the single trailing "Reply naturally..." line with explicit behavioral guidance:
   - For completed jobs: instruct the agent to acknowledge success, mention project+description, note verdict if available, and state the natural next action.
   - For failed jobs: instruct the agent to clearly flag the failure, include error/verdict_reason context, and suggest concrete follow-up (e.g. `pilot retry <id>` after fixing root cause).
   - Explicitly state: "Do NOT choose NO_REPLY — this is a real event the team needs to know about."

4. **Do NOT change** the function signature, exports, `parseJudgeVerdict`, `formatDuration`, `truncate`, or `nextStepGuidance` helpers. Do NOT change any transport/routing/delivery code.

5. The prompt should be concise — not a wall of text. Target 10-20 lines total. The instruction framing should be 2-3 lines, the data block is what it is, and the reply guidance is 2-3 lines.
  </action>
