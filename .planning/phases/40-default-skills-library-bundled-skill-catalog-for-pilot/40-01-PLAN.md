**Types:**
```typescript
export interface SkillRef {
  install: string;       // marketplace identifier: "author/skill-name"
  categories: string[];  // categories to auto-tag
}

export interface DetectedStack {
  items: string[];       // detected stack keys (e.g. ['react', 'typescript', 'tailwind'])
  signals: Record<string, string>; // what triggered each detection (e.g. { react: 'package.json dependency' })
}

export interface Recommendation {
  skills: Array<SkillRef & { tier: 1 | 2; stackKey?: string }>;
  detectedStack: DetectedStack;
}

export interface BootstrapResult {
  attempted: number;
  installed: number;
  skipped: number;
  failed: number;
  tagged: number;
  detectedStack: DetectedStack;
  errors: Array<{ skill: string; error: string }>;
}
```

**Constants — copy EXACTLY from requirements/default-skills-library.md:**
- `TIER1_SKILLS: SkillRef[]` — 5 universal skills (affaan-m/coding-standards, Shubhamsaboo/code-reviewer, obra/systematic-debugging, lobehub/typescript, affaan-m/security-review)
- `STACK_SKILLS: Record<string, SkillRef[]>` — keyed by: react, typescript, tailwind, cloudflare, hono, testing, drizzle, postgres, docs, api, ui-design

**Functions:**

1. `detectProjectStack(projectDir: string): DetectedStack`
   - Read `package.json` (if exists) — check dependencies + devDependencies for: react, next, @tanstack/*, tailwindcss, vitest, jest, hono, drizzle-orm, drizzle-kit
   - Check `wrangler.toml` or `wrangler.json` → cloudflare
   - Check `tsconfig.json` → typescript
   - Check `*.prisma` files or drizzle config files → database (map to drizzle or postgres)
   - Check `biome.json` or `.eslintrc*` → has linter (informational, not mapped to skills)
   - Map detected items to STACK_SKILLS keys
   - Bounded: only scan root-level files, no recursive traversal
   - Return `{ items: string[], signals: Record<string, string> }`

2. `recommendDefaultSkills(projectDir: string, options?: { tier?: 1 | 2 | 'all' }): Recommendation`
   - Call `detectProjectStack(projectDir)`
   - Start with TIER1_SKILLS (unless tier=2)
   - Add matching STACK_SKILLS entries for each detected item (unless tier=1)
   - Default tier is 'all'
   - Deduplicate by `install` field (Tier 1 wins)
   - Return `{ skills: [...], detectedStack }`

3. `bootstrapDefaultSkills(options: { projectDir: string; yes?: boolean; tier?: 1 | 2 | 'all' }): Promise<BootstrapResult>`
   - Call `recommendDefaultSkills(projectDir, { tier })`
   - For each recommended skill:
     a. Run `npx skills install <skill.install>` via execa (timeout: 60s)
     b. If install succeeds, call `syncManifest()` to pick up the new SKILL.md
     c. Then call `tagSkill(skillName, skill.categories)` to apply categories
     d. If install fails, record in errors array and **continue** (non-fatal)
   - After all installs, call `syncManifest()` one final time
   - Return structured `BootstrapResult`
   - Import `tagSkill`, `syncManifest` from `./skills.js` (NOT command-layer functions)
   - Use `execa` for `npx skills install` — do NOT reimplement marketplace client

**Important patterns:**
- Use `existsSync` + `readFileSync` with try/catch for detection (graceful on missing files)
- Do NOT use `addSkill` from skills.ts (that's for GitHub repos). Use `npx skills install` via execa for marketplace skills.
- After `npx skills install`, the skill lands in `~/.pilot/skills/` but manifest isn't updated yet — that's why we call `syncManifest()` to discover it, then `tagSkill()` to apply categories.
