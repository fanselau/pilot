**Step 1: Ensure shebang survives build reliably.**

TypeScript 5.x preserves shebangs, but we must verify and add a postbuild safety net.

1. Run `npm run build` and check `head -1 dist/index.js`. If it shows `#!/usr/bin/env node`, the compiler handles it.

2. **Regardless of step 1**, add a `postbuild` script to `package.json` that guarantees the shebang and sets executable permission:
```json
"scripts": {
  "build": "tsc",
  "postbuild": "chmod +x dist/index.js",
  ...
}
```
The `chmod +x` is essential for `npm link` — without it, the symlinked binary won't be executable on Linux. The shebang itself is preserved by tsc 5.x, but if for any reason it's missing, add a `postbuild` check:
```json
"postbuild": "node -e \"const f=require('fs');const c=f.readFileSync('dist/index.js','utf8');if(!c.startsWith('#!'))f.writeFileSync('dist/index.js','#!/usr/bin/env node\\n'+c);\" && chmod +x dist/index.js"
```

3. Verify `package.json` has `"bin": { "pilot": "./dist/index.js" }` — it already does. No change.

4. Run `npm run build && npm link` and verify `pilot --version` works from `/tmp`. If `npm link` fails with permission errors, document the fix (use `--prefix` or run in user context).

**Step 2: Add `--no-tui` flag to `pilot run`.**

In `src/index.ts`, add `--no-tui` option to the run command:


This flag is informational — the runner already runs headless by default. The flag signals intent for dumb terminals and CI environments. No behavior change in `src/commands/run.ts`.
