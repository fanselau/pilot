**Create `src/core/runner-log.ts`** — pure core module, no UI deps:

```typescript
interface RunnerLogger {
  log(message: string): void;     // writes timestamped line to log file
  getPath(): string;              // returns current log file path
  close(): void;                  // cleanup
}
```

- `createRunnerLogger()`: creates `~/.pilot/logs/runner-YYYY-MM-DD.log` (date-stamped). Uses `fs.mkdirSync` for `~/.pilot/logs/` on first call (sync is fine — happens once at startup). Returns RunnerLogger that appends lines with `fs.appendFileSync` (sync to avoid interleaving — runner log writes are infrequent and small).
- `getRunnerLogPath(date?: string)`: returns path to runner log for given date (default today). Used by `pilot log runner` and `pilot tail runner`.
- `getLatestRunnerLogPath()`: finds most recent runner log file in `~/.pilot/logs/` by scanning directory, sorting by date in filename.
- `rotateRunnerLogs(keepDays: number = 7)`: scans `~/.pilot/logs/runner-*.log`, deletes any older than `keepDays` days based on filename date (not mtime — deterministic).

**Create `src/core/notifications.ts`** — pure core module:

```typescript
interface NotificationConfig {
  enabled: boolean;
  on: Array<'complete' | 'fail' | 'stuck'>;
  webhook?: string;
}

interface NotificationPayload {
  event: 'complete' | 'fail' | 'stuck';
  project: string;
  title: string;
  duration_ms?: number;
  commits?: number;
  error?: string;
  stuckScore?: number;
}
```

- `loadNotificationConfig()`: reads `~/.pilot/config.json`, parses `notifications` section. Returns null if file doesn't exist or no notification config. Does NOT throw on missing file.
- `sendNotification(config: NotificationConfig, payload: NotificationPayload)`: if config.enabled and payload.event is in config.on, POST to config.webhook with JSON body. Use `fetch()` (built-in in Node.js 20+). Fire-and-forget: catch errors and log to stderr, never throw (notifications must not crash the runner). Timeout: 5 seconds via AbortController.
