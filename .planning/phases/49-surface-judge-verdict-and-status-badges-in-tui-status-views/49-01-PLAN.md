<task type="auto">
  <name>Task 1: Create shared judge verdict normalization and badge formatter</name>
  <files>src/core/judge-signal.ts</files>
  <action>
Create `src/core/judge-signal.ts` as a pure helper module used by CLI and TUI.

Implement a typed parser/normalizer for `Job.scope` + `Job.judgeVerdict` that:
- Returns `outcome: 'none'` for non-phase jobs (quick/milestone) so judge badges never appear there.
- Safely parses JSON verdict payloads and supports runner shape (`verdict`, `confidence`, `reason`) with backward compatibility fallback to legacy `summary` text.
- Maps verdict values to operator-facing outcomes: `succeeded -> pass`, `failed -> fail`, `doubting -> doubt`.
- Emits `inconclusive` when confidence is `0`, verdict payload is missing/unparseable/unknown, or confidence is unusable.
- Produces stable badge text exactly matching phase requirements: `judge:pass 92%`, `judge:fail 95%`, `judge:doubt 61%`, or `judge:inconclusive`.

Export helper APIs for downstream consumers (for example `buildJudgeSignal(...)` plus badge/reason helpers), and keep all verdict parsing in this module (do not leave ad-hoc `JSON.parse(job.judgeVerdict)` logic in new call sites).
