<task type="auto">
  <name>Task 2: Fix completed panel hover/overlay rendering artifacts</name>
  <files>src/tui/components/completed-panel.tsx</files>
  <action>
Fix the visual artifact/overlay that appears in completed panel selection/navigation. The root cause is the `bg()` function's interaction between flash state and selection state, plus the single-color `fg()` that makes all text the same color (status icon color) regardless of selection.

**Problems:**
1. Flash uses `theme.fg` as background (white/light bg) which creates a harsh inverse flash that looks like an overlay glitch.
2. When both `flashing()` and `selected()` are true, flash wins — selection highlight disappears.
3. The `fg()` function returns `color` (status color) for non-flashing, but ALL text uses this — so project name, description, duration all get status color (green/red) instead of normal fg.
4. The `line()` helper concatenates everything into one string with no visual separation.

**Fixes:**

1. **Separate text colors for status icon vs content:** Instead of one `<text>` with `fg={fg()}`, split the row into:
   - Status icon (`<text content={icon} fg={color} />`) — always uses status color
   - Content (`<text content={rest} fg={contentFg()} />`) — uses `theme.fg` normally, `theme.bg` when flashing

2. **Soften flash effect:** Replace `theme.fg` (white) background with a softer flash:
   - Flash bg: status color (green for completed, red for failed) at 30% opacity → use a muted version
   - Or simpler: use `statusColors.done` as flash bg (green tint) with `theme.fg` text
   - Best approach for terminal: flash bg = `'#1a3a1a'` (dark green tint), fg = `statusColors.done` (bright green)

3. **Fix priority: flash should not hide selection.** Update `bg()`:
   ```typescript
   const bg = () => {
     if (selected()) return theme.highlight;
     if (flashing()) return '#1a3a1a';  // subtle green tint
     return undefined;
   };
   ```
   Selection always wins over flash — user always knows where cursor is.

4. **Split the row rendering** from one `<text>` to structured fields:
   ```tsx
   <box flexDirection="row" backgroundColor={bg()}>
     <text content={`${icon} `} fg={color} />
     <text content={`#${job.id}  ${job.project}  ${job.scope}  `} fg={selected() ? theme.fg : theme.fg} />
     <text content={`"${truncate(job.description, 20)}"  `} fg={theme.muted} />
     <text content={`${duration()}  ${formatTokens(tokenCount())} tok  ${relative()}`} fg={theme.muted} />
   </box>
   ```

5. **Wire real token counts for completed jobs.** Currently `formatTokens(0)` is hardcoded to 0. The completed panel doesn't receive token data. Since completed jobs have `sessionTitles`, add token fetching:
   - Import `fetchSessionEnrichment` from `../data/opencode-db.js`
   - Create a `createEffect` that fetches tokens for all completed jobs' session titles on mount and when jobs change
   - Store in a local `Map<string, number>` signal (jobId → total tokens)
   - Use in the row rendering: `formatTokens(jobTokens().get(job.id) ?? 0)`
   - Fetch once on mount + when `props.jobs` changes (not on a timer — completed data is static)

**Important:** Do NOT change the flash detection logic (createEffect with prevIds comparison). Only change the visual rendering and bg/fg color logic. The flash timing (2s setTimeout) stays the same.
  </action>

  </verify>
