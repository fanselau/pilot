<task type="auto">
  <name>Task 2: Add budgeted verification retry orchestration with fingerprint escalation</name>
  <files>src/core/runner.ts</files>
  <action>
Implement retry orchestration directly in the plan-and-execute flow:

1. On retryable verification failure, compare current fingerprint to the last stored fingerprint and escalate immediately on exact match.
2. If budget remains, persist retry metadata (`retry_count`, `retry_hint`, fingerprint, attempt summary) and re-run via strategy intent:
   - `retry-resume` + valid verification -> `plan-phase <N> --gaps` then `execute-phase <N> --gaps-only`
   - `retry-resume` + invalid/missing/tiny (<=100 bytes) verification -> force `retry-full`
   - `retry-full` -> full plan-and-execute path for the same phase context
3. Wire retry hint context into retry execution by mapping persisted `retry_hint` into the delegation/execute retry context payload (`retry_context`) before launching the retry path.
4. If budget exhausted, throw terminal failure with attempt summary context so downstream notifications include all attempts.

Keep hung-session retry sharing the same retry budget contract; do not fork into a separate counter model.
  </action>
  <verify>
    - Retry path increments `retry_count` only when a retry is actually scheduled
    - Same fingerprint escalation fails immediately without incrementing retry budget
    - Gap retry execution path includes `--gaps-only`
    - Retry delegation context includes the current attempt's `retryHint`
  </verify>
  <done>
    Runner auto-retries verification failures deterministically and only blocks projects on terminal retry outcomes.
  </done>
</task>
