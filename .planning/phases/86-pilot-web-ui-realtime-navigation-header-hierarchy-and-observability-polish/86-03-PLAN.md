    1. **Add `synthesizeHeaderFields()` to `web/src/lib/step-semantics.ts`**:
       Create a function that takes a `StepTimelineGroup` and returns a structured object of fields to display in the sticky header:
       ```typescript
       export interface SynthesizedHeaderFields {
         label: string;           // "Execution", "Judge", "Gap Closure", etc.
         stage: string | null;    // "Planning", "Executing", "Verifying", "Gap Closure Round 2"
         verdict: string | null;  // "pass 95%", "gaps_found 60%", null
         model: string | null;    // "claude-sonnet-4-6", "gpt-5.4"
         statusCounters: { active: number; done: number; total: number } | null;
         continuationReason: string | null;  // "gaps found by judge", "hung session recovery"
         hasSummary: boolean;     // Whether this step has a summary/verdict to scroll to
         isActive: boolean;       // Currently running
       }
       
       export function synthesizeHeaderFields(group: StepTimelineGroup): SynthesizedHeaderFields
       ```
       
       Implementation:
       - `label`: Use existing `formatStepLabel(group)`
       - `stage`: Derive from `group.source` — 'delegation' → "Execution", 'judge:gaps' → "Gap Closure", etc.
       - `verdict`: Parse from `group.verdictReason` if judge step
       - `model`: Extract from session data if available (first model in group's items)
       - `statusCounters`: Count active/done items in `group.items`
       - `continuationReason`: From `group.source` — 'judge:gaps' → "gaps found", 'judge:hung' → "hung recovery"
       - `hasSummary`: True if judge step with verdictReason
       - `isActive`: `group.status === 'running'`

       Each step group in the content pane has a sticky header. Currently these are minimal labels. Redesign them to be VISUALLY DIFFERENTIATED by hierarchy level:

       **Level 2 — Step Group Header (per-step sticky)**:

       - Background: `bg-background/95 backdrop-blur` with a bottom border that's `border-b-2` (thicker than default) with color varying by step type:

         - Judge/Verification: `border-amber-500/30`
         - Gap Closure: `border-orange-500/30`
         - Quick Task: `border-muted-foreground/20`

       - These are the BranchLifecycleBlock headers

       - This creates a clear visual hierarchy where step headers dominate and branch headers are subordinate
