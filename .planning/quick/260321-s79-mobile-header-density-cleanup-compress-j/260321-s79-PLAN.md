  <action>
**Goal:** Reduce the 5-6 stacked header bars on mobile job-detail down to ~2 thin bars (breadcrumb+summary combined, then tabs), getting content to start ~120-140px from top instead of ~250-300px.

**1. `__root.tsx` — Hide AppHeader on mobile job-detail views:**
- Add `useIsMobile()` hook and `useMatches()` from TanStack Router to detect when user is on a `/jobs/$jobId` route on mobile.
- When on mobile AND on a job-detail route, hide the AppHeader entirely (it provides no useful context when inside job detail — the breadcrumb already has "← Dashboard").
- Keep the AppHeader visible on desktop always, and on mobile for non-job-detail routes (dashboard, project views).
- The height calc in `jobs.$jobId.tsx` uses `h-[calc(100vh-3rem)]` — when header is hidden, this needs to become `h-screen`. The simplest approach: use `useIsMobile()` + route matching in `jobs.$jobId.tsx` to conditionally set the height, OR just set `h-screen` on mobile in `jobs.$jobId.index.tsx` since the parent layout already has `flex flex-col overflow-hidden`.

**2. `jobs.$jobId.index.tsx` — Merge breadcrumb into split-pane:**
- On mobile, make the breadcrumb bar thinner: reduce `py-2` to `py-1`, use `gap-2` instead of `gap-3`.
- Pass the breadcrumb as part of the split-pane or render it inline with the summary bar from split-pane-detail.

**3. `split-pane-detail.tsx` — Compress mobile layout:**
- **Summary bar:** Combine the breadcrumb (← Dashboard) and the compact summary into a single ~32px row. The current summary already has StatusBadge + job ID + step info + Actions. Merge the back arrow into this row. This means the breadcrumb from `jobs.$jobId.index.tsx` should NOT render on mobile; instead, add a back button directly in the SplitPaneDetail mobile header. Pass `jobId` as a prop or derive from snapshot.
  - Actually, cleaner approach: keep the breadcrumb in `jobs.$jobId.index.tsx` but make it ultra-compact on mobile (h-7, py-1, smaller text), and then make the SplitPaneDetail summary bar also ultra-compact.
- **Running banner:** Instead of a full-width colored bar, reduce to a tiny inline indicator. The summary bar already shows `isActive` with a pulse dot. Eliminate the separate running banner block entirely on mobile — fold the elapsed time into the summary bar's right side (it's already nearly there with the step label). The running info (step label + elapsed) can be a small text span in the existing summary row.
- **Tabs:** Make tabs full-width, flatter, and more compact on mobile:
  - Override TabsList height: add className to reduce from default h-9 to h-7 on mobile.
  - Use `w-full` on TabsList and distribute tabs evenly.
  - Reduce tab text to `text-xs` on mobile.
  - Remove the `rounded-lg bg-muted` container style on mobile for a flatter look — use `variant="underline"` on mobile instead of default.
- **"All steps" bar:** This bar in `step-content-pane.tsx` says "All steps" + item count. On mobile, hide this bar entirely — the tab already says "Timeline" and the item count is low-signal for mobile users. The "Jump to error" button should move into the summary bar or be accessible some other way (e.g., as an action in the sheet). Handle this in step-content-pane with a prop or CSS approach.

**4. `step-content-pane.tsx` — Conditionally hide "All steps" header on mobile:**
- Accept an optional `hideHeader?: boolean` prop on `StepContentPaneProps`.
- When `hideHeader` is true, skip rendering the header div (the "All steps" bar).
- Keep the "Jump to error" button accessible: when hideHeader is true and there's a firstErrorGroup, render a small floating "Jump to error" button similar to the existing "Follow" button.
- In `split-pane-detail.tsx`, pass `hideHeader={true}` when rendering StepContentPane on mobile.

**Implementation constraints:**
- Do NOT change desktop layout at all — all changes gated behind `useIsMobile()` or responsive classes.
- Use Tailwind responsive prefixes (sm:, md:) where possible over JS-gated rendering.
- Keep existing imports and component interfaces stable.
- The total mobile header+chrome height should be roughly: breadcrumb (~28px) + summary (~32px) + tabs (~28px) = ~88px, down from ~250-300px.
