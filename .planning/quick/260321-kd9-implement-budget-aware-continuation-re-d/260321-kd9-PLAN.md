<objective>
Implement budget-aware continuation gating and improved human-only classification in Pilot's step management, so the runner does not blindly re-delegate when remaining step budget is insufficient, and human-only remaining work is correctly classified rather than triggering pointless machine continuation.

Purpose: Fix the final narrow control-flow issue where `handleGapsContinuation` and `handleFailedContinuation` never check remaining step budget before calling `reDelegateForContinuation()`, causing steps to be appended that push past `MAX_STEPS_PER_JOB` only to fail at the next loop iteration. Also improve `isHumanOnlyRemaining()` to catch more human-review signals.

Output: Modified runner.ts with budget-aware continuation, new constant in types.ts, comprehensive tests.
</objective>

    ```typescript
    /**
     * Build the budget-exhaustion message — explains proactively that budget is insufficient.
     * Differentiates from step-cap (reactive) and continuation-limit (cycle-based).
     * For gaps_found: suggests completed_pending_review since work is substantially done.
     * For failed: explains budget ran out during recovery.
     */
    function buildBudgetExhaustedMessage(
      remaining: number,
      required: number,
      totalSteps: number,
      source: 'judge:gaps' | 'judge:failed',
      lastReason?: string,
    ): string {
      const sourceLabel = source === 'judge:gaps' ? 'gap closure' : 'failure recovery';
      return (
        `Budget insufficient for ${sourceLabel}: ${remaining} steps remaining, ${required} needed. ` +
        `${totalSteps} steps already completed. ` +
        (lastReason ? `Last verdict: ${lastReason.slice(0, 200)}. ` : '') +
        (source === 'judge:gaps'
          ? 'The work is substantially complete — remaining items may need human review.'
          : 'Recovery could not proceed within remaining step budget.')
      );
    }
    ```
