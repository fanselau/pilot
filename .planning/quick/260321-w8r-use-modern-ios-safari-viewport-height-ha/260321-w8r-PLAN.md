<objective>
Replace all `100vh` / `h-screen` usage with modern dynamic viewport units (`dvh`) so iOS Safari's collapsing browser chrome doesn't create unwanted page-level scroll.

Purpose: On iOS Safari, `100vh` includes the area behind the browser chrome, causing content to overflow and create a scroll bounce. The `dvh` (dynamic viewport height) unit adapts to the actual visible area.

Output: All viewport-height references in the Pilot web UI use `dvh` with a `100vh` fallback for older browsers.
</objective>

**In `web/src/styles.css`** — add a viewport-height custom property at the top of the `@layer base` block so older browsers that don't support `dvh` still get `100vh`:

```css
@layer base {
  :root {
    --app-dvh: 100dvh;
  }
  @supports not (height: 100dvh) {
    :root {
      --app-dvh: 100vh;
    }
  }
}
```

This is a safety net. The actual fix uses Tailwind v4's built-in `dvh` utilities directly.

**In `web/src/routes/__root.tsx`** — change body class from `min-h-screen` to `min-h-dvh`:
- `min-h-screen` → `min-h-dvh` (Tailwind v4 ships this utility natively)

**In `web/src/routes/jobs.$jobId.tsx`** — replace the viewport height classes:
- Mobile: `h-screen` → `h-dvh` 
- Desktop: `h-[calc(100vh-3rem)]` → `h-[calc(100dvh-3rem)]`
- The full expression becomes: `${isMobile ? 'h-dvh' : 'h-[calc(100dvh-3rem)]'}`

**In `web/src/components/split-pane-detail.tsx`** — replace the inline style:
- `style={{ height: 'calc(100vh - 4rem)' }}` → `style={{ height: 'calc(100dvh - 4rem)' }}`
